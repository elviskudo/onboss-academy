Tanpa kata kunci class, Rust menggabungkan **struct untuk data** dan **impl untuk perilaku**.

## Mendefinisikan Struct

```rust
struct Siswa {
    nama: String,
    skor: i32,
}
```

Setiap field punya tipe. Semua field wajib diisi saat instance dibuat.

## Membuat Instance

```rust
let s = Siswa {
    nama: String::from("Sari"),
    skor: 90,
};

println!("{} - {}", s.nama, s.skor);
```

Akses field memakai titik `.`. Struktur literal menulis semua field sekaligus.

## 3 Bentuk Method

| Bentuk | Sintaks | Untuk apa |
| --- | --- | --- |
| Baca | `fn m(&self)` | Method hanya membaca field |
| Ubah | `fn m(&mut self)` | Method mengubah field — instance wajib `mut` |
| Ambil milik | `fn m(self)` | Method memakai habis instance (mis. ke `Vec`) |

```rust
impl Siswa {
    fn perkenalan(&self) {
        println!("Halo, saya {}", self.nama);
    }

    fn tambah_skor(&mut self, n: i32) {
        self.skor += n;
    }
}

fn main() {
    let mut s = Siswa { nama: String::from("Ani"), skor: 70 };
    s.tambah_skor(15);
    println!("skor = {}", s.skor);
}
```

## Konstruktor dan Method Statis

```rust
impl Siswa {
    fn baru(nama: &str, skor: i32) -> Self {
        Siswa { nama: nama.to_string(), skor }
    }
}

let s = Siswa::baru("Sari", 90);
```

Method tanpa `self` dipanggil lewat tipe: `Siswa::baru(...)` — inilah konstruktor gaya Rust (tidak ada kata kunci `constructor`).

## Enum, Trait, dan Kenapa Tanpa Class

```rust
enum Warna { Merah, Hijau, Biru }

trait Hitung {
    fn nilai(&self) -> i32;
}
```

`struct`+`enum` untuk data, `trait` untuk kontrak perilaku — inilah padanan OOP di Rust. **4 pilar OOP** dan statusnya:

| Pilar | Status di Rust | Mekanismenya |
| --- | --- | --- |
| Encapsulation | ✅ Ada | Field privat per-default; `pub` untuk membuka |
| Inheritance | ❌ Tidak ada | Digantikan trait + komposisi (menanam struct) |
| Polymorphism | ✅ Ada | Generik (`T: Hitung`) dan trait object (`dyn Hitung`) |
| Abstraction | ✅ Ada | Trait menyembunyikan implementasi |

Tidak ada `class Kucing extends Hewan` — kalau butuh perilaku bersama, tulis trait `Hewan` lalu `impl Hewan untuk Kucing` dan `impl Hewan untuk Anjing`.

## Di Dunia Nyata

- **Model database**: struct `Pengguna` dengan `fn simpan(&self)` ke SQLite
- **State machine**: enum `Status` (Draft/Review/Terbit) dengan method per transisi
- **Game**: struct `Pemain` dengan `gerak(&mut self, arah)` dan `darah(&self)`
- **Kalkulator harga**: `impl` terpisah per tipe — `DiskonPersen`, `DiskonRupiah`
- **Validator form**: trait `Validasi { fn lolos(&self) -> bool }` dipakai semua tipe input
