Keamanan database bukan satu fitur, melainkan rangkaian kebiasaan: hak akses, parameterisasi query, penyimpanan rahasia, enkripsi, audit, dan backup.

## Lapisan Pertahanan

| Lapisan | Tindakan |
| --- | --- |
| Aplikasi | prepared statement, validasi input |
| Akun | least privilege, pisah akun baca/tulis |
| Jaringan | firewall, TLS, batasi akses IP |
| Data | enkripsi at-rest, hash kata sandi |
| Operasional | audit log, backup, patch

## Hak Akses

```sql
CREATE ROLE app_read ONLY;
GRANT SELECT ON karyawan TO app_read;

CREATE ROLE app_write;
GRANT SELECT, INSERT, UPDATE ON karyawan TO app_write;
-- Tidak memberi DROP, DELETE, atau hak supervisor
```

Nama perintah berbeda di tiap database, tetapi prinsipnya sama: akun untuk aplikasi tidak boleh menjadi superuser.

## Kata Sandi

```text
kata sandi pengguna → hash + salt → disimpan di database
```

Gunakan algoritma yang dirancang untuk kata sandi, seperti bcrypt, scrypt, atau Argon2. SHA-256 biasa terlalu cepat sehingga mudah dicoba brute-force.

## Enkripsi

- **In transit**: TLS/SSL antara aplikasi dan database.
- **At rest**: enkripsi disk atau kolom (TDE, pgcrypto).
- **Backup**: enkripsi file cadangan dan kelola kuncinya terpisah.

Enkripsi tidak menggantikan hak akses; keduanya bekerja bersama.

## Audit dan Retensi

```sql
-- Konsep umum: tabel audit berisi aktor, aksi, waktu, dan data lama/baru
CREATE TABLE audit_karyawan (
  id INTEGER PRIMARY KEY,
  aktor TEXT,
  aksi TEXT,
  waktu TEXT,
  detail TEXT
);
```

Simpan log audit di tempat yang tidak bisa dihapus sembarangan oleh akun aplikasi.

## Backup dan Recovery

| Prinsip | Penjelasan |
| --- | --- |
| 3-2-1 | 3 salinan, 2 media berbeda, 1 di lokasi terpisah |
| Otomatis | jadwalkan, jangan mengandalkan ingatan |
| Diuji | lakukan restore simulasi berkala |
| RPO/RTO | tentukan berapa data hilang dan berapa lama downtime yang bisa diterima

<div class="note">💡 Kredensial yang tidak sengaja masuk Git tetap bocor walau sudah dihapus di commit berikutnya. Putar (rotate) kunci segera dan bersihkan riwayat repositori.</div>

## Di Dunia Nyata

- **Aplikasi web**: akun DB hanya SELECT/INSERT/UPDATE pada tabel bisnis.
- **Layanan kesehatan**: audit log dan enkripsi untuk memenuhi regulasi.
- **E-commerce**: nomor kartu tidak disimpan; gunakan token payment gateway.
- **Operasional**: restore backup di staging tiap bulan.
