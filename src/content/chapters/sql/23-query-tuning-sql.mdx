Optimisasi dimulai dari pengukuran, bukan dari intuisi. Query plan menjelaskan apa yang akan dilakukan database: memindai tabel, mencari lewat index, menyortir, atau membuat tabel sementara.

## Membaca Plan

```sql
EXPLAIN QUERY PLAN
SELECT nama FROM karyawan WHERE dept = 'Engineering';
```

Tanpa index, keluaran biasanya menyebut `SCAN karyawan`. Setelah `CREATE INDEX idx_karyawan_dept ON karyawan(dept)`, plan berubah menjadi `SEARCH karyawan USING INDEX idx_karyawan_dept`.

## Langkah Optimisasi

1. Ukur waktu query dengan data volume realistis.
2. Baca query plan.
3. Periksa filter `WHERE` dan kunci `JOIN`.
4. Tambah atau ubah index bila memang diperlukan.
5. Ukur lagi; simpan bukti perbaikan.

```sql
-- PostgreSQL
EXPLAIN ANALYZE SELECT ...
-- MySQL
EXPLAIN SELECT ...
```

## Filter Selektif

```sql
-- Baik: filter langsung pada kolom ter-index
SELECT * FROM pesanan WHERE user_id = 7 AND status = 'lunas';

-- Kurang baik: fungsi pada kolom membuat index tidak terpakai
SELECT * FROM pesanan WHERE LOWER(status) = 'lunas';
```

Simpan data dalam bentuk yang sudah konsisten (misalnya semua huruf kecil) agar query tidak perlu mengubahnya tiap kali.

## Join dan Sort

- Pastikan kolom yang di-`JOIN` bertipe sama dan ter-index.
- `ORDER BY` pada kolom tanpa index memaksa sort seluruh hasil.
- `DISTINCT`, `GROUP BY`, dan `UNION` juga bisa memicu tabel sementara.
- Batasi baris dengan `LIMIT` hanya setelah logika filter benar.

## Query yang Sering Tidak Disadari Mahal

```sql
-- Subquery di SELECT berjalan per baris secara logis
SELECT nama, (SELECT COUNT(*) FROM proyek WHERE lead_id = k.id) AS jumlah
FROM karyawan k;

-- Alternatif: agregat sekali lalu join
WITH j AS (SELECT lead_id, COUNT(*) AS jumlah FROM proyek GROUP BY lead_id)
SELECT k.nama, COALESCE(j.jumlah, 0) AS jumlah
FROM karyawan k LEFT JOIN j ON j.lead_id = k.id;
```

<div class="note">💡 Optimizer modern sangat pintar, tetapi ia hanya bisa memilih dari index yang kamu sediakan. Menambah index secara acak bukan strategi — gunakan plan sebagai pemandu.</div>

## Di Dunia Nyata

- **Endpoint lambat**: EXPLAIN mengungkap full scan pada tabel 5 juta baris.
- **Dashboard**: materialized view menggantikan agregasi real-time.
- **Pencarian**: FTS menggantikan `LIKE '%...%'` yang tidak ter-index.
- **Batch job**: index komposit sesuai pola filter mempercepat malam hari.
