SQL adalah standar, tetapi setiap database punya dialek dan ekstensi. Menulis query portable berarti memakai fitur inti standar bila memungkinkan dan mengisolasi fitur khas vendor.

## Ringkasan Perbedaan

| Fitur | PostgreSQL | MySQL | SQL Server | SQLite |
| --- | --- | --- | --- | --- |
| Limit | `LIMIT n` | `LIMIT n` | `TOP n` | `LIMIT n` |
| String | `x \|\| y` | `CONCAT(x,y)` | `+` | `\|\|` |
| Auto id | `SERIAL` / `IDENTITY` | `AUTO_INCREMENT` | `IDENTITY` | `INTEGER PRIMARY KEY` |
| Tanggal | `CURRENT_DATE` | `CURDATE()` | `GETDATE()` | `date('now')` |
| UPSERT | `ON CONFLICT` | `ON DUPLICATE KEY` | `MERGE` | `ON CONFLICT` |

Daftar ini ringkas dan tidak mencakup semua versi; selalu cek dokumentasi versi yang dipakai.

## Menulis Query Portable

```sql
-- Relatif portable
SELECT dept, COUNT(*) AS jumlah
FROM karyawan
WHERE gaji >= 8000000
GROUP BY dept
ORDER BY jumlah DESC;
```

Fitur seperti `LIMIT`, `||`, dan `EXTRACT` sudah luas didukung, tetapi tetap ada pengecualian. Uji query di database target sebelum deploy.

## Fitur Khas yang Berguna

```sql
-- PostgreSQL: RETURNING membuat DML mengembalikan baris
INSERT INTO karyawan (nama, gaji) VALUES ('Baru', 9000000) RETURNING id;

-- SQLite/PostgreSQL: UPSERT
INSERT INTO pengaturan (kunci, nilai) VALUES ('tema', 'gelap')
ON CONFLICT(kunci) DO UPDATE SET nilai = excluded.nilai;
```

## Tipe Data

Perbedaan yang sering menggigit: `TEXT` di SQLite bisa menampung angka, `BOOLEAN` di PostgreSQL nyata, MySQL menyimpannya sebagai `TINYINT(1)`. Tanggal dengan timezone sebaiknya memakai `TIMESTAMPTZ` di PostgreSQL.

## Strategi Multi-Database

1. Pusatkan SQL khusus vendor dalam satu lapisan repositori.
2. Pakai ORM atau query builder bila tim bekerja di banyak engine.
3. Tulis tes integrasi terhadap database produksi yang sebenarnya.
4. Hindari nama tabel/kolom yang sama dengan kata kunci SQL.

<div class="note">💡 "SQL standar" tidak menjamin kode berjalan identik di semua mesin. Anggap portability sebagai sifat yang harus diuji, bukan asumsi.</div>

## Di Dunia Nyata

- **Startup**: mulai SQLite, migrasi ke PostgreSQL tanpa mengubah seluruh query.
- **Enterprise**: SQL Server untuk sistem lama, PostgreSQL untuk layanan baru.
- **Mobile**: sqlite di perangkat, sinkron ke MySQL di server.
- **Analitik**: dialect engine tertentu (BigQuery, Snowflake) perlu dipelajari tersendiri.
