## Validasi Bawaan

```ruby
class Article < ApplicationRecord
  validates :title, presence: true, length: { minimum: 5 }
  validates :slug, uniqueness: { case_sensitive: false }
  validate :tanggal_tidak_masa_depan

  private
  def tanggal_tidak_masa_depan
    return if published_at.blank?
    errors.add(:published_at, "tidak boleh di masa depan") if published_at > Time.current
  end
end
```

```ruby
validates :email, presence: true, uniqueness: true
validates :usia, numericality: { greater_than_or_equal_to: 17 }
validates :title, length: { in: 5..100 }
```

Rails menyediakan validator untuk keberadaan, keunikan, format, panjang, dan tipe angka. Semua error terkumpul di `objek.errors`.

## Validator Kustom

```ruby
validate :tanggal_tidak_masa_depan

def tanggal_tidak_masa_depan
  return if published_at.blank?
  errors.add(:published_at, "tidak boleh di masa depan") if published_at > Time.current
end
```

Gunakan `validate` (tunggal) untuk method kustom, `validates` (jamak) untuk validator bawaan.

## Konteks dan Pesan

| Opsi | Fungsi | Contoh |
|---|---|---|
| `on:` | membatasi konteks | `on: :create` |
| `message:` | mengganti pesan default | `message: "wajib diisi"` |
| `allow_nil:` | lewat jika nil | `allow_nil: true` |
| `if:` | validasi bersyarat | `if: :published?` |

## Callback vs Validasi

`before_validation` bisa membersihkan data sebelum validasi berjalan:

```ruby
before_validation :normalisasi_slug

def normalisasi_slug
  self.slug = title.parameterize if title.present?
end
```

Callback dipakai untuk **mengubah** data, validasi untuk **menolak** data. Jangan mencampur keduanya dalam satu method.

<div class="note">💡 Uniqueness validator rentan race condition. Tambahkan index unik di database — validasi memberi pesan ramah, index memberi jaminan di tingkat database.</div>
