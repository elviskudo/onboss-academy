## Kenapa Gemfile Penting

```ruby
source "https://rubygems.org"
gem "rails", "~> 7.1"
gem "pg"
gem "sidekiq"

group :development, :test do
  gem "rspec-rails"
end
```

Gemfile adalah **daftar belanja** proyek. Kamu menulis nama gem dan rentang versi yang diinginkan, lalu Bundler mencari kombinasi yang saling cocok.

```ruby
source "https://rubygems.org"
gem "rails", "~> 7.1"
gem "pg"
```

`~> 7.1` berarti "versi 7.x, tapi jangan lompat ke 8.0". Ini menjaga kode tetap kompatibel saat patch dirilis.

## Anatomi Gemfile

| Bagian | Contoh | Fungsi |
|---|---|---|
| `source` | `https://rubygems.org` | tempat mengunduh gem |
| `gem` | `gem "redis"` | dependensi yang dipakai aplikasi |
| versi | `"~> 7.1"` | batas versi yang diizinkan |
| `group` | `group :test do` | mengelompokkan gem per lingkungan |
| `git` | `git: "..."` | sumber gem dari repositori |

## Perintah Sehari-hari

```bash
bundle install      # pasang semua gem
bundle update rails # perbarui satu gem
bundle exec rspec   # jalankan perintah dalam konteks bundle
bundle list         # lihat gem yang terpasang
```

`bundle exec` penting saat ada beberapa versi gem di mesin yang sama — perintah itu memastikan versi yang dipakai adalah versi di lockfile.

## Lockfile sebagai Kontrak

Gemfile.lock menyimpan **resolusi akhir**: versi pasti semua gem beserta dependensi turunannya. Simpan file ini di version control. Tanpa lockfile, dua developer bisa mendapat kombinasi gem berbeda dan mengalami bug yang hanya muncul di satu mesin.

<div class="note">💡 Setiap kali mengubah Gemfile, jalankan <code>bundle install</code> lalu commit Gemfile.lock bersamaan. Memisahkan keduanya adalah sumber klasik error "gem tidak ditemukan" di server.</div>
