## Checklist Sebelum Deploy

```ruby
# config/environments/production.rb
config.public_file_server.enabled = ENV["RAILS_SERVE_STATIC_FILES"].present?
config.force_ssl = true
config.log_level = :info

# perintah di server
RAILS_ENV=production bin/rails assets:precompile
RAILS_ENV=production bin/rails db:migrate
bundle exec puma -C config/puma.rb
```

| Langkah | Perintah / File | Alasan |
|---|---|---|
| Pasang gem produksi | `bundle install --without development test` | ukuran image lebih kecil |
| Precompile aset | `bin/rails assets:precompile` | CSS/JS siap disajikan |
| Migrasi database | `bin/rails db:migrate` | skema sesuai kode |
| Rahasia | Rails credentials / ENV | jangan commit password |
| Mode produksi | `RAILS_ENV=production` | caching dan error handling aktif |

## Puma

```ruby
# config/puma.rb
workers ENV.fetch("WEB_CONCURRENCY") { 2 }
threads_count = ENV.fetch("RAILS_MAX_THREADS") { 5 }
threads threads_count, threads_count
port ENV.fetch("PORT") { 3000 }
```

Worker adalah proses terpisah; thread berjalan di dalam worker. Di container, jumlah worker biasanya disesuaikan dengan CPU yang tersedia.

## Logging dan Monitoring

```ruby
config.logger = ActiveSupport::Logger.new(STDOUT)
config.log_tags = [:request_id]
```

Di platform container, log ke stdout dikumpulkan oleh orkestrator. `request_id` membantu melacak satu request lintas baris log.

## Health Check

```ruby
get "/up" => "rails/health#show", as: :rails_health_check
```

Endpoint ini mengembalikan 200 bila aplikasi dan database bisa diakses. Load balancer memakainya untuk memutuskan apakah instance boleh menerima traffic.

<div class="note">💡 Selalu jalankan migrasi sebagai langkah deploy terpisah, sebelum mengalihkan traffic ke versi baru. Migrasi yang mengubah data besar sebaiknya dilakukan saat jam sepi.</div>
