## Tiga Level Cache

```ruby
# low-level cache
def ringkasan(user)
  Rails.cache.fetch(["ringkasan", user.id], expires_in: 1.hour) do
    user.articles.sum(:views)
  end
end

# fragment cache di view
<% cache @article do %>
  <%= render "artikel/kartu", article: @article %>
<% end %>
```

| Level | Contoh | Cocok untuk |
|---|---|---|
| Query cache | aktif otomatis per request | query identik berulang dalam satu request |
| Low-level | `Rails.cache.fetch` | hasil komputasi atau aggregate |
| Fragment | `cache @article` | potongan HTML yang mahal dirender |

## Low-level Cache

```ruby
Rails.cache.fetch("statistik", expires_in: 10.minutes) do
  Article.group(:status).count
end
```

Blok hanya dijalankan saat data belum ada atau sudah kedaluwarsa. Kunci cache sebaiknya mencakup semua input yang memengaruhi hasil.

## Fragment dan Russian Doll

```erb
<% cache @article do %>
  <h2><%= @article.title %></h2>
  <% cache @article.author do %>
    <%= @article.author.nama %>
  <% end %>
<% end %>
```

Saat artikel berubah, cache artikel diperbarui tetapi cache penulis tetap dipakai. Teknik bertingkat ini disebut *Russian doll caching*.

## Cache Store

| Store | Kelebihan | Kekurangan |
|---|---|---|
| Memory | cepat | hilang saat restart, per proses |
| File | sederhana | lambat di banyak file |
| Redis | cepat, bersama | butuh servis tambahan |
| Memcached | cepat, ringan | tidak persisten |

## Mengukur Dulu

```bash
bundle exec ruby -r bullet -e 'puts "Profil dulu sebelum mengoptimalkan"'
```

Pasang gem `bullet` di development untuk mendeteksi N+1 dan unused eager loading. Optimasi tanpa pengukuran sering membuang waktu pada bagian yang bukan bottleneck.

<div class="note">💡 Invalidate cache dengan kunci yang mencakup `updated_at`, misalnya `cache [@article, "kartu"]`. Rails otomatis menambahkan `updated_at` ke cache key objek Active Record.</div>
