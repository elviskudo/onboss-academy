## Arsitektur Singkat

```ruby
class ChatChannel < ApplicationCable::Channel
  def subscribed
    stream_from "chat_#{params[:room]}"
  end

  def speak(data)
    Message.create!(room: params[:room], body: data["message"])
  end
end

# dari tempat lain
ActionCable.server.broadcast("chat_umum", message: "Halo semua!")
```

| Komponen | Peran |
|---|---|
| Connection | koneksi WebSocket per browser |
| Channel | topik logik tempat client berlangganan |
| Subscriber | client yang bergabung ke channel |
| Broadcast | pengiriman pesan ke semua subscriber |

## Channel Pertama

```ruby
class ChatChannel < ApplicationCable::Channel
  def subscribed
    stream_from "chat_#{params[:room]}"
  end
end
```

`stream_from` memberi tahu server bahwa client ingin menerima semua pesan untuk nama stream tersebut.

## Client JavaScript

```javascript
const subscription = consumer.subscriptions.create(
  { channel: "ChatChannel", room: "umum" },
  { received(data) { console.log(data.message); } }
);
```

`received` dipanggil setiap kali server melakukan broadcast ke stream itu.

## Broadcast dari Model

```ruby
after_create_commit do
  ActionCable.server.broadcast("chat_#{room}", message: body)
end
```

Di produksi, Action Cable bisa memakai adapter `redis` agar broadcast menjangkau beberapa proses server.

<div class="note">💡 Autentikasi koneksi dilakukan di `ApplicationCable::Connection` lewat `identified_by :current_user`. Jangan mempercayai `params` dari client untuk menentukan identitas pengguna.</div>
