## Migrasi sebagai Riwayat Skema

```ruby
class AddIndexAndRoleToUsers < ActiveRecord::Migration[7.1]
  def up
    add_column :users, :role, :string, default: "member"
    add_index :users, :email, unique: true
    add_reference :articles, :author, foreign_key: true
  end

  def down
    remove_reference :articles, :author, foreign_key: true
    remove_index :users, :email
    remove_column :users, :role
  end
end
```

Migrasi adalah file Ruby yang mengubah struktur database. Setiap file punya timestamp, sehingga urutan eksekusinya jelas.

```bash
bin/rails generate migration AddRoleToUsers role:string
bin/rails db:migrate
```

## Pasangan Up dan Down

```ruby
def up
  add_column :users, :role, :string
end

def down
  remove_column :users, :role
end
```

`down` membuat migrasi bisa dibatalkan dengan `bin/rails db:rollback`. Untuk perubahan sederhana, metode `change` sudah cukup karena Rails tahu cara membalikkan `add_column`.

## Index dan Foreign Key

| Perubahan | Alasan |
|---|---|
| `add_index :users, :email, unique: true` | mempercepat lookup sekaligus mencegah email ganda |
| `add_reference :articles, :author, foreign_key: true` | menambah `author_id` + constraint database |
| `change_column_null` | menegaskan kolom wajib diisi |

Foreign key di database adalah perlindungan terakhir meskipun validasi model sudah ada.

## Migration Data

```ruby
def up
  User.where(role: nil).update_all(role: "member")
end
```

Gunakan `update_all` untuk update massal — jauh lebih cepat daripada loop `save`. Namun `update_all` melewati callback dan validasi, jadi pahami risikonya.

## Schema.rb

Setiap `db:migrate` memperbarui `db/schema.rb`. File ini adalah gambaran akhir skema yang dipakai saat menyiapkan database baru lewat `bin/rails db:setup`.

<div class="note">💡 Hindari mengedit migrasi yang sudah dijalankan di produksi. Buat migrasi baru untuk perubahan lanjutan agar riwayat tetap jujur dan rollback tetap bisa dilakukan.</div>
