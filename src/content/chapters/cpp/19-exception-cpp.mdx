Exception C++ mirip Java, tapi tanpa checked exception. Kekuatan sebenarnya muncul saat dipasangkan dengan RAII.

## Dasar

```cpp
try {
    if (gagal) throw std::runtime_error("pesan");
} catch (const std::runtime_error &e) {
    std::cerr << e.what() << '
';
} catch (...) {
    std::cerr << "tidak diketahui
";
}
```

Tangkap dengan **const reference** agar tidak ada slicing dan tidak menyalin.

## Hierarki

```
std::exception
├── std::logic_error      → invalid_argument, out_of_range, domain_error
└── std::runtime_error    → overflow_error, range_error
```

Buat exception sendiri dengan mewarisi `std::runtime_error`.

## Stack Unwinding

Saat exception dilempar, semua object lokal di scope antara `throw` dan `catch` dihancurkan otomatis. Inilah gunanya smart pointer/container — resource ikut ter-cleanup tanpa kode `finally` (C++ tidak punya `finally`).

## Exception Safety

| Level | Arti |
|---|---|
| Nothrow | tidak pernah melempar |
| Strong | jika gagal, state tidak berubah |
| Basic | tidak ada leak, state依然 valid |
| None | bisa leak/corrupt |

Copy-and-swap adalah teknik klasik untuk mencapai strong guarantee.

## no-throw Destructor

Destructor sebaiknya tidak melempar exception. Jika destructor melempar saat stack unwinding, program akan `std::terminate()`.

<div class="note">💡 Pakai exception untuk kondisi **luar biasa** (file tidak ada, alokasi gagal). Untuk input user yang salah secara normal, kembalikan `std::optional` atau `expected` (C++23) — alur lebih jelas dan tanpa overhead exception.</div>
