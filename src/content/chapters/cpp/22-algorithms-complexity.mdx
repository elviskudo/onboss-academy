Kompleksitas membantu memprediksi bagaimana program bersikala saat data membesar. Fokus pada pertumbuhan, bukan waktu absolut.

## Notasi Big-O

| Notasi | Nama | Contoh |
|---|---|---|
| O(1) | konstan | `v[i]` |
| O(log n) | logaritmik | binary search, `set` |
| O(n) | linear | loop satu level |
| O(n log n) | linearitmik | `sort`, `merge sort` |
| O(n²) | kuadratik | nested loop |
| O(2ⁿ) | eksponensial | fibonacci naif |

## Analisis Loop

```cpp
for (int i = 0; i < n; i++)        // O(n)
    for (int j = 0; j < n; j++)    // × O(n)
        kerja();                   // → O(n²)

for (int i = n; i > 1; i /= 2)     // → O(log n)
    kerja();
```

## Kompleksitas Container STL

| Container | Akses | Cari | Insert |
|---|---|---|---|
| `vector` | O(1) | O(n) | O(n) di tengah |
| `list` | O(n) | O(n) | O(1) dengan iterator |
| `set` | — | O(log n) | O(log n) |
| `unordered_set` | — | O(1) rata-rata | O(1) rata-rata |

## Waktu vs Memori

Sering ada trade-off: `unordered_set` lebih cepat tapi lebih banyak memori dan tidak terurut. Pilih sesuai kebutuhan.

## Pengukuran

Teori tetap perlu dibuktikan dengan profiling:

```cpp
auto t0 = std::chrono::steady_clock::now();
jalankan();
auto t1 = std::chrono::steady_clock::now();
```

<div class="note">💡 Optimasi tanpa pengukuran sering membuang waktu. Profile dulu, temukan bottleneck, baru ubah struktur data atau algoritma.</div>
