Memilih kontainer yang tepat sering lebih berdampak daripada micro-optimasi. Berikut ringkasan praktisnya.

## Sequence Container

| Kontainer | Akses | Insert tengah | Catatan |
|---|---|---|---|
| `array` | O(1) | — | ukuran tetap |
| `vector` | O(1) | O(n) | default terbaik |
| `deque` | O(1) | O(n) | push depan & belakang |
| `list` | O(n) | O(1)* | *dengan iterator |
| `forward_list` | O(n) | O(1)* | singly, hemat memori |

## Associative Container

| Kontainer | Urutan | Lookup |
|---|---|---|
| `set` / `map` | terurut | O(log n) |
| `unordered_set/map` | tidak | O(1) rata-rata |
| `multiset/multimap` | terurut, duplikat | O(log n) |

## Tips Vector

```cpp
std::vector<int> v;
v.reserve(1000);   // alokasi sekali di awal
```

Tanpa `reserve`, vector tumbuh dengan faktor ~2 dan menyalin ulang elemen berkali-kali.

## Invalidasi Iterator

- `vector::push_back` bisa meminvalidasi semua iterator saat reallocasi.
- `map`/`set` iterator tetap valid selama elemen tidak dihapus.
- `unordered_map` iterator bisa invalid saat rehash.

<div class="note">💡 Default ke `std::vector`. Baru pindah ke `list`, `deque`, atau container asosiatif kalau ada kebutuhan konkret yang tidak bisa dipenuhi vector.</div>
