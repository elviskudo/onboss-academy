## 7 Tipe Error Bawaan

| Tipe error | Penyebab umum | Contoh situasi |
|------------|---------------|----------------|
| `Error` | Error umum buatanmu | `throw new Error("Gagal simpan")` |
| `TypeError` | Tipe salah | Memanggil fungsi pada `undefined` |
| `ReferenceError` | Variabel tak dikenal | `console.log(nama)` tanpa deklarasi |
| `SyntaxError` | Salah sintaks | Kurung `{` tidak ditutup |
| `RangeError` | Nilai di luar rentang | `Array(-1)` |
| `URIError` | `decodeURIComponent` salah | String `%ZZ` tidak valid |
| `EvalError` | Pemakaian `eval` tak benar | Jarang muncul modern |

Semua bisa di-catch lewat `catch (e)`; `e.name` memberi tipe-nya, `e.message` memberi isi pesan, dan `e.stack` memberi lokasi baris.

## try / catch / finally

```js
function bagi(a, b) {
  if (b === 0) throw new Error("Pembagian dengan nol!");
  return a / b;
}

try {
  console.log(bagi(10, 2)); // 5
  console.log(bagi(10, 0)); // lempar error
} catch (e) {
  console.error("Gagal:", e.message);
} finally {
  console.log("Selesai menghitung");
}
```

## Error Custom

```js
class ValidationError extends Error {
  constructor(field) {
    super(`Field ${field} wajib diisi`);
    this.name = "ValidationError";
  }
}

if (!email) throw new ValidationError("email");
```

## Melempar vs Menangkap vs Mengembalikan

```js
// 1. Lempar — saat pemanggil HARUS tahu dan boleh gagal
if (b === 0) throw new Error("Pembagian dengan nol");

// 2. Tangkap — saat kamu bisa memulihkan situasi
try {
  JSON.parse(userInput);
} catch (e) {
  data = {};           // pulihkan dengan nilai aman
}

// 3. Return error — pola ringkas tanpa exception (ALTO/Go style)
function bagi(a, b) {
  if (b === 0) return { ok: false, error: "nol" };
  return { ok: true, value: a / b };
}
```

Aturan praktis: error **tak terduga** → `throw`; error **yang memang bagian dari alur** (login gagal, data tidak ada) → nilai kembalian. Jangan sampai `catch {}` kosong — error hilang tanpa jejak.

## Tips Debugging

1. `console.log`, `console.table`, `console.dir` di mana perlu
2. **Breakpoint** di DevTools → Sources → klik nomor baris
3. `debugger;` di kode → eksekusi berhenti otomatis saat DevTools terbuka
4. Baca pesan error dari bawah ke atas — baris pertama di stack-mu biasalah biang keladinya

```js
console.table([
  { produk: "Kopi", stok: 5 },
  { produk: "Teh", stok: 0 },
]);
```

`console.table` menampilkan array object sebagai tabel — jauh lebih cepat dipindai daripada baris log panjang.

## Di Dunia Nyata

- **Checkout toko online**: `try { prosesBayar() } catch` menampilkan "Pembayaran gagal, coba lagi" alih-alih layar putih.
- **Parsing data API** yang formatnya tidak dijamin: `JSON.parse` dibungkus try/catch.
- **Validasi input user** dibuang ke `ValidationError` custom supaya bisa ditampilkan per-field.
- **Cleanup loading spinner** ditaruh di `finally` — muncul sukses maupun gagal.
- **Kalkulator / form kalkulasi** menampilkan `Error` di UI saat hasil `NaN` atau `Infinity`.

## Proyek Akhir: Kalkulator Mini

Rangkum fungsi, event, DOM, dan error handling jadi kalkulator bekerja sungguhan. Langkah membangun: (1) susun tampilan dengan `createElement`, (2) simpan state ekspresi dalam `let expr`, (3) evaluasi dengan pembungkus `Function` + `try/catch`, (4) tampilkan `Error` rapi saat hasil tidak valid. Kembangkan: riwayat perhitungan, keyboard support, pembagian dengan nol.
