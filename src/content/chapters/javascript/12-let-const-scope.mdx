Pemilihan kata kunci deklarasi menentukan **di mana variabel bisa diakses** dan **apakah boleh diubah**. Kode modern hampir selalu memakai `const`, lalu `let` hanya saat memang perlu reassignment.

## Perbandingan var, let, const

| Fitur | `var` | `let` | `const` |
|-------|-------|-------|---------|
| Scope | Fungsi | Blok | Blok |
| Bisa diubah | Ya | Ya | Tidak (binding) |
| Hoisting | Ya (undefined) | TDZ | TDZ |
| Deklarasi ulang | Boleh | Error | Error |
| Dianjurkan | ❌ | ✅ | ✅✅ |

## Scope Blok

```js
if (true) {
  let pesan = "dalam blok";
  var bocor = "keluar blok";
}
console.log(bocor);  // "keluar blok"
console.log(pesan);  // ReferenceError
```

Blok adalah apa pun di antara `{` dan `}` — termasuk badan `if`, `for`, `while`, dan fungsi.

## TDZ (Temporal Dead Zone)

```js
console.log(x); // undefined (var)
var x = 5;

console.log(y); // ReferenceError
let y = 5;
```

Meski `let` secara teknis "diangkat" ke atas, ia tidak boleh diakses sampai baris deklarasinya dijalankan.

## Const tidak Membekukan Objek

```js
const pengguna = { nama: "Sari" };
pengguna.nama = "Budi";   // ✅ boleh
pengguna = { nama: "Andi" }; // ❌ TypeError

const daftar = [1, 2];
daftar.push(3); // ✅ boleh
```

Kalau ingin benar-benar membekukan, pakai `Object.freeze(pengguna)` (dangkal) atau deep freeze.

## Scope Global dan Window

```js
var legacy = "aku masuk window";
let modern = "aku tidak";

console.log(window.legacy); // "aku masuk window"
console.log(window.modern); // undefined
```

Di browser, `var` di level teratas menjadi properti `window` — sumber banyak konflik. `let`/`const` tidak.

<div class="note">💡 Mulailah dengan `const` untuk semua variabel. Kalau linter mengeluh karena nilai diubah, baru ganti ke `let`. Pola ini mencegah bug reassignment tidak sengaja.</div>

## Di Dunia Nyata

- Konfigurasi, URL API, dan konstanta matematika memakai `const`.
- Counter perulangan memakai `let` karena nilainya berubah tiap iterasi.
- Library modern memakai ES module, sehingga variabel tidak pernah mencemari `window`.
