Array (berurutan, diakses dengan index) dan object (berpasangan `kunci: nilai`) adalah dua struktur data utama JavaScript. Array menyediakan **30+ method bawaan**, yang wajib dikuasai dikelompokkan jadi 5 kategori:

| Kategori | Jumlah inti | Anggota | Fungsi |
|----------|-------------|---------|--------|
| Mutasi (mengubah asli) | 8 | `push pop shift unshift splice reverse sort fill` | Tambah/hapus/ubah isi array di tempat |
| Pencarian | 6 | `indexOf includes find findIndex at lastIndexOf` | Cari posisi/nilai |
| Iterasi | 7 | `forEach map filter reduce some every findLast` | Telusuri & transformasi |
| Transformasi (array baru) | 4 | `slice concat join flat` | Salin, gabung, ratakan |
| Lain-lain | 3 | `length flatMap toSorted` | Panjang, map + rata, salinan terurut |

**Mutable vs immutable**: metode mutasi (`push`, `splice`, `sort`) mengubah array asli; metode transformasi (`map`, `filter`, `slice`) menghasilkan array baru dan membiarkan asli utuh. Untuk data yang tidak boleh berubah (state React, konfigurasi), pakai yang immutable.

**Kapan array vs object**: array untuk daftar berurutan yang diiterasi dan diurutkan (`daftarUser`); object untuk entri bernama (`user`, `{ nama, email }`); object vs Map — Map unggul kalau kuncinya dinamis/banyak operasi `set/get` cepat.

## Method Array Wajib

```js
const angka = [5, 3, 8, 1];

angka.push(9);          // tambah di akhir → [5,3,8,1,9]
angka.pop();            // hapus akhir
angka.includes(3);      // true
angka.indexOf(8);       // 2
angka.join(", ");       // "5, 3, 8, 1"
[...angka].sort();      // salinan terurut
```

## map / filter / reduce

```js
const produk = [
  { nama: "Kopi", harga: 20000 },
  { nama: "Teh", harga: 15000 },
  { nama: "Jus", harga: 25000 },
];

const nama = produk.map((p) => p.nama);          // ["Kopi","Teh","Jus"]
const murah = produk.filter((p) => p.harga < 22000);
const total = produk.reduce((sum, p) => sum + p.harga, 0);
```

## chained (Berantai)

```js
const hasil = produk
  .filter((p) => p.harga > 15000)
  .map((p) => p.nama)
  .join(", ");
```

## Spread & Rest

```js
const a = [1, 2];
const b = [...a, 3, 4];        // [1,2,3,4]
const user = { ...data, aktif: true };

function jumlah(...angka) {    // rest: kumpulkan sisa argumen
  return angka.reduce((x, y) => x + y, 0);
}
```

## Destructuring

```js
const orang = { nama: "Sari", umur: 20, kota: "Bandung" };
const { nama, umur } = orang;

const [x, y] = [10, 20];

function sapa({ nama, umur }) {
  return `${nama} (${umur})`;
}
```

## OOP di JavaScript: Prototype + Class ES6

JavaScript **bukan bahasa berbasis class** secara historis — ia berbasis **prototype**: setiap object punya `[[Prototype]]` (induk) yang diwarisi lewat rantai. Method yang tidak ada di object dicari naik ke induknya sampai `Object.prototype`.

```js
// Gaya asli JS — deklarasi object literal + prototype
const hewan = {
  suara() { return "..."; },
};
const kucing = Object.create(hewan); // kucing prototipe-nya hewan
kucing.nama = "Miu";
console.log(kucing.suara());   // "..." — diwarisi dari hewan
console.log(kucing.hasOwnProperty("suara")); // false — bukan miliknya sendiri
```

Sejak ES6 (2015) JavaScript punya sintaks `class` — **sugar sintaks di atas prototype**, bukan sistem tipe baru:

```js
class Hewan {
  constructor(nama) { this.nama = nama; }
  suara() { return "..."; }
}
class Kucing extends Hewan {
  suara() { return "Meong"; }   // polymorphism
}
const k = new Kucing("Miu");
console.log(k.nama, k.suara()); // "Miu Meong"
console.log(Kucing.prototype.hasOwnProperty("suara")); // true
```

Status **4 pilar OOP** di JavaScript:

| Pilar | Status di JS | Cara |
|-------|--------------|------|
| Encapsulation | Lemah (sebelum ES2022) | `#privat` atau closure; `private` TS hanya saat kompilasi |
| Inheritance | Ada | `class B extends A` → prototype chain |
| Polymorphism | Ada | Method sama, perilaku beda di subclass |
| Abstraction | Sebagian | Tidak ada `abstract`; tiru dengan class dasar yang mengecualikan diri |

Kapan OOP vs prosedural/functional? Pakai class saat ada **state bersama yang diubah lewat method** (Keranjang, Akun Bank); pakai fungsi murni saat logikanya murni input → output (hitung total, format tanggal). Keduanya sah di JS — React modern bahkan cenderung ke functional.

## Di Dunia Nyata

- **Keranjang belanja**: `push` item baru, `filter` buang yang dibatalkan, `reduce` jadi total bayar.
- **Daftar pengguna API** di-*map* jadi kartu profil: `users.map(u => u.name)`.
- **State aplikasi React** wajib immutable — spread `{ ...state, ...payload }`, bukan `state.x = …`.
- **Model database** seperti `class User extends Model` memakai pewarisan class ES6.
- **Merge konfigurasi** `({ ...defaultConfig, ...userConfig })` dengan spread object.

<div class="note">💡 `class` di JS bukan bukti JS "berbasis class" — hapus sintaksnya dan yang tersisa tetap prototype chain. Pahami `Object.create` dan `Kucing.prototype`, sekali paham tidak ada lagi "magic" di balik `extends`.</div>
