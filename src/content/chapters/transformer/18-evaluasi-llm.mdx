Membandingkan LLM tidak bisa hanya dengan “terasa lebih pintar”. Dibutuhkan **evaluasi terstruktur**.

## Metrik Intrinsik

```text
Perplexity = exp( -1/N · Σ log P(token_i | token_<i) )
```

```python
import math

avg_nll = 1.2
print("perplexity ≈", round(math.exp(avg_nll), 2))
```

Perplexity lebih rendah biasanya lebih baik, tetapi tidak menjamin jawaban benar atau aman.

| Metrik | Fokus | Catatan |
|---|---|---|
| Perplexity | pemodelan probabilitas | intrinsik, cepat |
| BLEU / ROUGE | kesamaan dengan referensi | rapuh terhadap parafrasa |
| Exact Match | jawaban persis | cocok untuk factoid |
| F1 / accuracy | klasifikasi | butuh label |
| Human eval | kualitas nyata | mahal tapi paling dipercaya |

## Benchmark

- **MMLU** — pengetahuan lintas 57 bidang.
- **GSM8K** — penalaran aritmetika langkah demi langkah.
- **HumanEval** — kemampuan menulis kode Python.
- **TruthfulQA** — ketahanan terhadap misconception umum.

## Praktik yang Baik

1. Buat test set tetap yang tidak pernah dipakai saat tuning prompt.
2. Sertakan contoh dalam bahasa dan domain yang benar-benar dipakai pengguna.
3. Pisahkan penilaian fakta, kelengkapan, nada, dan keamanan.
4. Uji juga kasus trivial dan adversarial, bukan hanya soal sulit.
5. Simpan versi prompt dan model agar hasil bisa direproduksi.

<div class="note">💡 Jika skor benchmark naik tetapi pengguna tetap mengeluh, kemungkinan benchmark tidak mewakili kebutuhan nyata. Evaluasi terbaik adalah yang menyerupai pemakaian produksi.</div>

## Evaluasi Generatif

Untuk tugas terbuka, pakai rubrik berbobot: kebenaran 40%, kelengkapan 25%, kejelasan 20%, kesesuaian format 15%. Minta beberapa evaluator独立 lalu rata-ratakan untuk mengurangi varians.
