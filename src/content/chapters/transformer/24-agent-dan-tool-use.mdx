**Agent** adalah LLM yang tidak hanya menjawab, tetapi juga bisa memanggil alat: mencari data, menghitung, atau menjalankan aksi lewat aplikasi.

## Alur Tool Calling

```text
Pertanyaan -> model memilih tool + argumen -> aplikasi menjalankan -> hasil dikembalikan -> model merangkum
```

```python
tools = [
    {"name": "cari_dokumen", "parameters": {"query": "string"}},
    {"name": "hitung", "parameters": {"ekspresi": "string"}},
]

def jalankan_tool(nama, args):
    if nama == "hitung":
        return eval(args["ekspresi"], {"__builtins__": {}}, {})
    return "tool tidak dikenal"
```

Penting: **model hanya mengusulkan**, aplikasi yang memutuskan apakah perintah boleh dijalankan.

## Pola ReAct

```text
Thought: saya perlu mencari aturan cuti.
Action: cari_dokumen(query="kebijakan cuti 2024")
Observation: durations 12 hari kerja.
Thought: saya sudah punya datanya.
Final: Kebijakan cuti 2024 adalah 12 hari kerja.
```

## Desain Tool yang Baik

| Prinsip | Penjelasan |
|---|---|
| Nama deskriptif | `kirim_email` lebih jelas dari `do_it` |
| Schema ketat | tipe argumen dan nilai yang diizinkan |
| Efek samping jelas | bedakan tool baca dan tool tulis |
| Error informatif | model bisa mencoba strategi lain |
| Jumlah terbatas | terlalu banyak tool membingungkan |

<div class="note">💡 Agent yang paling berguna sering kali bukan yang paling otonom, melainkan yang langkahnya bisa diawasi dan dibatasi dengan jelas.</div>

## Kapan Tidak Perlu Agent

Kalau alurnya sudah diketahui dan deterministik, tulis saja fungsi biasa. Agent bermanfaat saat jalur penyelesaian belum pasti: riset, diagnosis, atau tugas dengan banyak kemungkinan alat.

## Observability

Simpan untuk tiap langkah: prompt, tool yang dipilih, argumen, hasil, jumlah token, dan waktu. Trace ini menyelamatkan saat agent mengambil jalan yang salah di produksi.
