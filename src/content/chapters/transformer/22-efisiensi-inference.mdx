Melatih model itu mahal, tetapi **melayani** model juga punya tantangan tersendiri: latensi, throughput, dan memori GPU.

## KV Cache

Saat menghasilkan token ke-100, model tidak perlu menghitung ulang K/V untuk 99 token pertama. Cache menyimpannya.

```text
tanpa cache: O(n²) komputasi ulang
dengan cache: O(n) per token baru
```

Biayanya: memori cache tumbuh dengan panjang konteks dan jumlah permintaan bersamaan.

## Quantization

```python
parameter = 7_000_000_000
fp16 = parameter * 2   # 14 GB
int8 = parameter * 1   # 7 GB
int4 = parameter * 0.5 # 3.5 GB
print(fp16, int8, int4)
```

| Presisi | Memori relatif | Dampak kualitas |
|---|---|---|
| FP16 | 1x | baseline |
| BF16 | 1x | mirip FP16, stabil |
| INT8 | 0.5x | sangat kecil |
| INT4 | 0.25x | perlu pengujian |

## Teknik Lain

- **Continuous batching** — slot GPU diisi ulang begitu satu permintaan selesai.
- **PagedAttention** — mengelola KV cache seperti halaman memori, mengurangi fragmentasi.
- **Speculative decoding** — model draft menebak, model besar memverifikasi.
- **Prefix caching** — system prompt identik tidak dihitung ulang antarpengguna.

<div class="note">💡 Turunkan `max_tokens` dan minta jawaban ringkas sebelum membeli GPU lebih besar. Sering kali biaya terbuang karena model dibiarkan menulis terlalu panjang.</div>

## Memilih Konfigurasi

Mulai dari model terkecil yang lolos evaluated quality. Ukur **time to first token** untuk pengalaman interaktif dan **tokens per second** untuk throughput. Keduanya tidak selalu membaik dengan trik yang sama.
