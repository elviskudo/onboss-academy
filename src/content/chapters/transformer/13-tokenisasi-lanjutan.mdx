Tokenizer level kata cepat menghasilkan vocabulary besar dan banyak token tidak dikenal. **Subword tokenization** memecah kata langka menjadi potongan yang lebih umum.

## Byte Pair Encoding (BPE)

```text
korpus: low lower newest widest
iterasi 1: gabungkan "l" + "o" -> "lo"
iterasi 2: gabungkan "lo" + "w" -> "low"
iterasi 3: gabungkan "e" + "r" -> "er"
```

```python
def bpe_merge(kata, pasangan):
    hasil, i = [], 0
    while i < len(kata):
        if kata[i:i+len(pasangan)] == pasangan:
            hasil.append(pasangan)
            i += len(pasangan)
        else:
            hasil.append(kata[i])
            i += 1
    return hasil

print(bpe_merge("lower", "lo"))  # ['lo', 'w', 'e', 'r']
```

## Unigram dan SentencePiece

Model unigram menila semua kandidat subword dengan probabilitas, lalu membuang yang kontribusinya kecil. SentencePiece populer karena bekerja langsung pada teks mentah dan tidak bergantung pada aturan spasi bahasa tertentu.

| Aspek | BPE | Unigram |
|---|---|---|
| Arah | bottom-up (gabung) | top-down (buang) |
| Kriteria | frekuensi | likelihood |
| Tokenizer populer | GPT, RoBERTa | Llama, T5 |
| Perlakuan spasi | eksplisit | bisa disandikan |

## Byte-level BPE

Dengan memakai 256 byte sebagai dasar, tokenizer bisa merekonstruksi **semua** input termasuk emoji, simbol aneh, dan teks dalam bahasa apa pun.

<div class="note">💡 Jumlah token tidak selalu sama dengan jumlah kata. Satu kata bahasa Indonesia bisa menjadi 2–5 token, dan biaya API LLM biasanya dihitung per token.</div>

## Dampak ke Model

- Vocabulary kecil → embedding lebih hemat, tapi urutan token lebih panjang.
- Vocabulary besar → token lebih sedikit, tapi matriks embedding membengkak.
- Tokenizer harus sama persis antara training dan inference, kalau tidak representasinya berubah.
