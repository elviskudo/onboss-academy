Setelah attention mengumpulkan informasi dari token lain, **feed-forward network (FFN)** mengolah informasi itu di dalam tiap token. Disebut juga MLP blok.

## Struktur Dasar

```text
FFN(x) = W2 * activation(W1 * x + b1) + b2
```

```python
d_model = 512
d_ff = 4 * d_model  # 2048

def ffn(x, W1, b1, W2, b2):
    h = gelu(x @ W1 + b1)
    return h @ W2 + b2
```

| Parameter | Arti | Nilai umum |
|---|---|---|
| `d_model` | dimensi representasi token | 512–8192 |
| `d_ff` | dimensi hidden FFN | 2–8 kali `d_model` |
| aktivasi | fungsi nonlinier | ReLU, GELU, SwiGLU |

## Kenapa Per Token?

Attention sudah melakukan komunikasi antarposisi. FFN bekerja **position-wise**: token ke-3 diproses dengan bobot yang sama seperti token ke-10, tetapi tidak melihat token lain. Ini membuatnya mudah diparalelkan.

## Varian Modern

- **GELU** — versi halus dari ReLU, dipakai BERT dan GPT.
- **SwiGLU** — gating dengan dua proyeksi, dipakai Llama dan PaLM.
- **MoE (Mixture of Experts)** — beberapa FFN, hanya sebagian yang aktif per token.

```text
SwiGLU(x) = Swish(W1 x) ⊗ (W2 x)
output = W3(SwiGLU(x))
```

<div class="note">💡 FFN menyumbang porsi besar parameter model. Saat menghitung ukuran model, sekitar dua pertiga parameter sering berada di FFN, bukan attention.</div>

## Dampak Praktis

- FFN lebih besar membuat model lebih ekspresif, tapi biaya komputasi dan memori naik.
- MoE memisahkan kapasitas dari biaya: total parameter besar, token hanya melewati beberapa expert.
- Saat quantisasi, bobot FFN biasanya menjadi target utama penghematan memori.
