Ruby memakai exception untuk kondisi tak terduga, tapi bisa juga memakainya sebagai alur kontrol dengan hati-hati.

## Bentuk Dasar

```ruby
begin
  hasil = eval(input)
rescue SyntaxError => e
  warn "Sintaks salah: #{e.message}"
rescue => e
  warn "Error umum: #{e.class}"
ensure
  puts "Pembersihan di sini"
end
```

`rescue` dievaluasi dari atas ke bawah — taruh yang paling spesifik dulu.

## rescue di Method

```ruby
def baca(path)
  File.read(path)
rescue Errno::ENOENT
  ""
end
```

*Bentuk modifier* juga umum:

```ruby
nilai = Integer(input) rescue 0
```

## raise

```ruby
raise "pesan sederhana"          # RuntimeError
raise ArgumentError, "bukan angka"
raise ArgumentError, "pesan", caller
```

## retry

```ruby
percobaan = 0
begin
  percobaan += 1
  koneksi = buka_koneksi
rescue Timeout::Error
  retry if percobaan < 3
  raise
end
```

Batas percobaan wajib agar tidak melingkar selamanya.

## Exception Kustom

```ruby
class SaldoKurang < StandardError; end

def tarik(jumlah)
  raise SaldoKurang, "saldo tidak cukup" if jumlah > @saldo
end
```

## Praktik Baik

- Jangan pakai exception untuk alur bisnis normal
- Tangkaplah jenis yang spesifik, bukan `Exception` secara luas
- `ensure` untuk menutup file/koneksi

<div class="note">💡 <code>Exception</code> adalah induk semua error, termasuk <code>SystemExit</code> dan <code>Interrupt</code>. Menangkapnya bisa mencegah program keluar dengan benar — gunakan <code>StandardError</code> sebagai ganti.</div>
