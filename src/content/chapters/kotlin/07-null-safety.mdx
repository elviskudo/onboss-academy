Billion dollar mistake menurut penciptanya adalah izin null tanpa kontrol. Kotlin menjadikan null sebagai hal yang harus dinyatakan.

## Tipe Nullable

```kotlin
fun main() {
    var aman: String = "Halo"
    // aman = null   // gagal kompilasi

    var rawan: String? = "Halo"
    rawan = null     // diperbolehkan
    println(rawan)
}
```

Tanpa tanda tanya, null tidak akan pernah masuk ke variabel. Kotlin punya **4 mekanisme** untuk menangani nilai yang bisa null:

| Mekanisme | Contoh | Perilaku | Kapan dipakai |
| --- | --- | --- | --- |
| Safe call `?.` | `nama?.length` | akses batal, hasil `null` | rantai akses yang panjang |
| Elvis `?:` | `nama ?: "Tanpa"` | nilai pengganti bila null | memberi default |
| Force `!!` | `nama!!.length` | paksa; bila null → exception | hanya bila pasti tidak null |
| Smart cast | `if (nama != null) nama.length` | tipe otomatis menyempit | pengecekan sederhana |

## Safe Call dan Elvis

```kotlin
fun main() {
    val nama: String? = null

    println(nama?.length)        // null, tanpa error
    println(nama?.length ?: 0)   // 0
}
```

`?.` menghentikan akses bila null, `?:` memberi nilai pengganti.

## Menyediakan Nilai Default

```kotlin
fun panjang(teks: String?): Int = teks?.length ?: 0

fun main() {
    println(panjang("Kotlin"))
    println(panjang(null))
}
```

Gabungan keduanya membuat penanganan null singkat dan aman.

## Smart Cast

```kotlin
fun tampilkan(teks: String?) {
    if (teks != null) {
        println(teks.length)   // teks sudah String biasa
    } else {
        println("kosong")
    }
}

fun main() {
    tampilkan("Halo")
    tampilkan(null)
}
```

Setelah pengecekan, Kotlin tahu nilai tidak mungkin null dan meng-cast otomatis. Catatan: smart cast tidak berlaku untuk `var` yang bisa ditulis ulang dari tempat lain — karena nilainya bisa berubah di antara pengecekan dan pemakaian.

## Rantai Aman dan let

Safe call bisa dirantai, dan `let` membantu mengeksekusi blok hanya saat nilai ada:

```kotlin
fun main() {
    data class Alamat(val kota: String?)
    val alamat: Alamat? = Alamat(kota = "Bandung")

    println(alamat?.kota?.uppercase())   // BANDUNG

    alamat?.let {
        println("Kota ditemukan: ${it.kota}")
    }
}
```

`alamat?.kota?.uppercase()` — bila salah satu rantai null, seluruh ekspresi langsung menjadi null tanpa exception.

Koleksi pun bisa nullable per elemennya: `listOf(1, null, 3)` bertipe `List<Int?>`, dan `listOf(null)` bertipe `List<Int?>` yang isinya bukan null — perhatikan letak tanda tanyanya.

## Ketika Terpaksa Menggunakan !!

```kotlin
fun main() {
    val teks: String? = "siap"
    val wajib: String = teks!!
    println(wajib.length)
}
```

Pakai `!!` hanya bila kamu benar-benar yakin — kalau salah, program berhenti dengan error jelas. Di produksi, `!!` yang melempar NullPointerException justru membuktikan bahwa mekanisme null safety bekerja: kesalahanmu tertangkap, bukan diam-diam merusak data.

## Di Dunia Nyata

- **Membaca field JSON opsional** — `data?.alamat?.kota ?: "-"` menampilkan "-" ketika API tidak mengirim alamat.
- **Intent/parameter aplikasi** — nilai yang dikirim komponen lain bisa hilang; `getStringExtra("id")` bertipe `String?` dan wajib ditangani.
- **Konfigurasi dengan default** — `portServer ?: 8080` memberi nilai bawaan bila konfigurasi tidak diisi.
- **Mengambil elemen list** — `daftar.firstOrNull()` menghasilkan nullable; memakai `[0]` langsung berisiko IndexOutOfBounds.
- **Menghentikan rantai aman** — `user?.profil?.avatar?.let { tampilkan(it) }` menggantikan tiga kali pengecekan if bertingkat.

<div class="note">💡 Utamakan ?. lalu ?: dengan nilai default. Simpan !! untuk data yang memang tidak pernah null — lebih sedikit ! berarti lebih sedikit potensi crash di produksi.</div>
