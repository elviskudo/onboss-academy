Terkadang sebuah proyek perlu menyertakan kode dari repositori lain — misalnya library internal atau komponen UI bersama. **Submodule** menyimpan referensi ke commit tertentu, bukan menyalin seluruh isinya.

## Menambah Submodule

```bash
git submodule add https://github.com/org/ui-kit.git packages/ui-kit
git add .gitmodules packages/ui-kit
git commit -m "Tambah submodule ui-kit"
```

Yang tersimpan di repo induk hanyalah pointer commit dan entri di `.gitmodules`.

```text
[submodule "packages/ui-kit"]
    path = packages/ui-kit
    url = https://github.com/org/ui-kit.git
```

## Mengambil Submodule

```bash
git clone https://github.com/org/app.git
cd app
git submodule update --init --recursive
```

Tanpa langkah ini, direktori submodule kosong.

## Memperbarui

```bash
cd packages/ui-kit
git switch main
git pull origin main
cd ../..
git add packages/ui-kit
git commit -m "Perbarui ui-kit ke versi terbaru"
```

Repo induk akan mencatat commit baru dari submodule.

<div class="note">💡 Submodule sering berada dalam keadaan **detached HEAD**. Buat branch lokal sebelum mengubah kode di dalamnya agar commit tidak mengambang.</div>

## Alternatif

| Pendekatan | Kelebihan | Kekurangan |
|---|---|---|
| Submodule | versi terkunci jelas | perlu init, lebih ribet |
| Package manager | familiar, dependency otomatis | butuh publish ke registry |
| Vendor copy | paling sederhana | duplikasi dan sulit update |
| Monorepo | satu riwayat | repositori besar |

Pilih submodule bila Anda benar-benar butuh mengontrol commit tepat dari repo eksternal.
