Bayangkan sedang mengerjakan fitur besar, lalu ada bug produksi mendesak. **Worktree** memungkinkan Anda membuka branch lain di folder berbeda tanpa menyimpan atau membuang pekerjaan saat ini.

## Menambah Worktree

```bash
git worktree add ../proyek-hotfix hotfix/urgent
```

Bila branch belum ada:

```bash
git worktree add -b hotfix/urgent ../proyek-hotfix main
```

## Mengelola

```bash
git worktree list
git worktree move ../proyek-hotfix ../hotfix
git worktree remove ../hotfix
git worktree prune
```

`prune` membersihkan metadata worktree yang direkamanual dihapus.

## Kenapa Tidak Sekadar Clone?

| Aspek | Clone baru | Worktree |
|---|---|---|
| Objek Git | duplikat | dibagi |
| Riwayat | perlu fetch ulang | langsung tersedia |
| Ruang disk | lebih besar | lebih efisien |
| Branch yang sama | bisa, tapi membingungkan | tidak bisa dibuka dua kali |

Git melarang branch yang sama aktif di dua worktree untuk mencegah perubahan saling menimpa.

<div class="note">💡 Worktree sangat cocok untuk review PR sambil tetap lanjut mengerjakan branch sendiri — buka worktree sementara, jalankan tes, lalu hapus.</div>

## Batasan

- Submodule tidak otomatis ikut ke worktree baru; jalankan `git submodule update --init`.
- Beberapa alat IDE menganggap tiap worktree sebagai proyek terpisah.
- Jangan menghapus folder worktree langsung dengan `rm -rf` bila ingin metadata tetap rapi.
