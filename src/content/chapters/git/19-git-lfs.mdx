Git menyimpan **setiap versi** sebuah file. Untuk file desain, video, atau dataset berukuran ratusan megabyte, ini membuat riwayat cepat membengkak. Git LFS (Large File Storage) menggantinya dengan pointer kecil.

## Cara Kerja

```text
di repo:    desain.psd -> "version https://git-lfs.github.com/spec/v1 ..."
di storage: file asli disimpan terpisah
saat checkout: pointer ditukar dengan file asli
```

## Menyiapkan

```bash
git lfs install
git lfs track "*.psd"
git lfs track "*.mp4"
git lfs track "assets/dataset/**"
git add .gitattributes
git add desain.psd
git commit -m "Tambah aset desain"
```

```text
*.psd filter=lfs diff=lfs merge=lfs -text
```

## Perintah Sehari-hari

```bash
git lfs ls-files
git lfs status
git lfs pull
git lfs migrate import --include="*.psd"
```

`migrate` berguna untuk memindahkan file besar yang sudah terlanjur masuk riwayat biasa.

<div class="note">💡 LFS bukan pengganti sistem aset digital. Untuk tim desain besar, tetap pertimbangkan DAM atau storage khusus dengan kontrol akses yang lebih kaya.</div>

## Kapan Dipakai

| Jenis file | LFS? |
|---|---|
| Kode sumber | tidak |
| Ikon kecil | tidak |
| Foto produk resolusi tinggi | ya |
| Video tutorial | ya |
| Model machine learning | ya |
| Dataset CSV raksasa | ya |

## Pertimbangan Biaya

Penyedia hosting biasanya memberi kuota LFS terpisah dari kuota repo. Pantau pemakaian bandwidth saat clone dan CI — tiap checkout aset besar bisa menghabiskan kuota bulanan.
