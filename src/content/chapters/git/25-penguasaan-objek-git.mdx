Git sering terasa seperti sihir sampai Anda melihat **objek**-nya. Semuanya adalah empat jenis dasar yang disimpan berdasarkan hash konten.

## Jenis Objek

| Objek | Berisi |
|---|---|
| blob | isi file mentah |
| tree | daftar nama file dan pointer blob/tree |
| commit | tree, parent, penulis, waktu, pesan |
| tag | penanda ke objek lain (+ metadata) |

```bash
echo "halo" | git hash-object --stdin
# 3b18e512dba79e4c8300dd08aeb37f8e728b8dad
```

Hash dihitung dari isi + header, sehingga isi sama selalu menghasilkan hash sama.

## Membongkar Satu Commit

```bash
git log --oneline -1
git cat-file -p HEAD
git cat-file -p HEAD^{tree}
git cat-file -p <hash-blob>
```

```text
tree 9a3f...
parent 2b7c...
author Sinta <sinta@x.id> 1700000000 +0700

Tambah README
```

## Area Staging

```text
working tree --git add--> index --git commit--> objek commit
```

Index adalah snapshot sementara. Itu sebabnya file yang diubah setelah `git add` tidak otomatis masuk commit — Anda harus `git add` lagi.

## Referensi

```bash
cat .git/HEAD
ls .git/refs/heads
git show-ref
```

Branch hanyalah **pointer ke commit**. Saat commit baru dibuat, pointer branch bergerak maju.

<div class="note">💡 Karena objek bersifat content-addressed, Git sangat efisien: dua file identik hanya disimpan sekali, walau muncul di banyak commit.</div>

## Kapan Pengetahuan Ini Berguna

- Memahami mengapa `reset --soft`, `--mixed`, dan `--hard` berbeda.
- Memulihkan objek yang “hilang” lewat hash dari `git fsck`.
- Men-debug alat yang menulis objek secara langsung.
