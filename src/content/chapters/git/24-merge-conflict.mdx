Konflik bukan tanda Git rusak — itu tanda dua orang mengubah **tempat yang sama**. Git berhenti dan meminta keputusan manusia.

## Membaca Penanda

```text
<<<<<<< HEAD
kode versi cabang saat ini
=======
kode versi cabang yang digabung
>>>>>>> nama-branch
```

Pilih salah satu, gabungkan keduanya, atau tulis versi baru. Hapus semua penanda `<<<<<<<`, `=======`, dan `>>>>>>>`.

## Langkah Penyelesaian

```bash
git merge fitur/harga-baru
# konflik muncul
code src/harga.js
git add src/harga.js
git commit
```

Saat konflik terjadi dalam rebase:

```bash
git add src/harga.js
git rebase --continue
```

## Mencegah Konflik

- Tarik perubahan terbaru sebelum mulai mengerjakan file yang sama.
- Pisahkan file per fitur bila memungkinkan.
- Gunakan format kode dan aturan baris yang konsisten.
- Komunikasikan saat akan menyentuh file bersama.

```bash
git config merge.conflictstyle diff3
```

`diff3` menambahkan versi **base** di tengah sehingga lebih mudah melihat apa yang berubah di masing-masing cabang.

<div class="note">💡 Jangan menyelesaikan konflik hanya dengan menghapus salah satu blok. Pahami mengapa tiap perubahan dibuat — bisa jadi keduanya membawa perbaikan penting.</div>

## Konflik Bukan Teks

Untuk file biner seperti gambar, Git tidak bisa menampilkan penanda. Pilih salah satu versi:

```bash
git checkout --ours  aset/logo.png
git checkout --theirs aset/logo.png
git add aset/logo.png
```

Setelah itu uji hasilnya sebelum commit.
