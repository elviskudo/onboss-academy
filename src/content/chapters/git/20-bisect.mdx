Ketika bug muncul padahal rilis sebelumnya baik, **bisect** mencari commit pertama yang menyebabkan masalah tanpa memeriksa ratusan commit satu per satu.

## Alur Manual

```bash
git bisect start
git bisect bad                 # HEAD sekarang rusak
git bisect good v2.1.0         # rilis lama masih baik
```

Git otomatis checkout commit di tengah. Uji aplikasi, lalu beri tahu hasilnya:

```bash
git bisect good    # commit ini masih aman
git bisect bad     # commit ini sudah rusak
```

Ulangi sampai Git menampilkan commit penjahatnya.

## Alur Otomatis

```bash
git bisect start
git bisect bad HEAD
git bisect good v2.1.0
git bisect run npm test -- --testNamePattern=checkout
git bisect reset
```

Skrip tes harus:

- keluar dengan kode `0` untuk kondisi baik;
- keluar bukan nol untuk kondisi buruk;
- keluar `125` bila hasil tidak bisa ditentukan (misalnya dependency gagal install).

## Contoh Keluaran

```text
a1b2c3d is the first bad commit
commit a1b2c3d
Author: ...
Date:   ...

    refactor: ubah perhitungan diskon
```

<div class="note">💡 Bisect bekerja paling baik bila commit bersifat atomik. Riwayat yang penuh commit “campuran” membuat hasilnya benar secara teknis tapi sulit diartikan.</div>

## Setelah Ketemu

```bash
git show a1b2c3d
git revert a1b2c3d
git bisect reset
```

Jangan lupa `reset` — tanpa itu Anda tetap berada dalam mode bisect.
