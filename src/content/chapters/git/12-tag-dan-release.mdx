**Tag** memberi nama permanen pada sebuah commit. Berbeda dengan branch yang terus bergerak, tag biasanya dipakai untuk rilis.

## Dua Jenis Tag

```bash
git tag v1.0.0                              # lightweight
git tag -a v1.1.0 -m "Tambah ekspor CSV"    # annotated
```

| Jenis | Isi | Direkomendasikan |
|---|---|---|
| Lightweight | pointer ke commit | untuk penanda sementara |
| Annotated | penulis, tanggal, pesan, tanda tangan | untuk rilis resmi |

## Melihat dan Mengelola

```bash
git tag
git tag -l "v1.*"
git show v1.1.0
git tag -d v1.0.0
git push origin --delete v1.0.0
```

```bash
git checkout v1.1.0        # masuk ke tagged commit (detached HEAD)
git switch -c rilis-1-1    # buat branch dari tag bila perlu edit
```

## SemVer Secara Singkat

```text
1.4.2
| | |
| | +-- patch: perbaikan bug, kompatibel
| +---- minor: fitur baru, kompatibel
+------ major: perubahan yang memutus kompatibilitas
```

<div class="note">💡 Tag yang sudah di-push sebaiknya tidak dipindah. Bila rilis perlu diperbaiki, buat tag patch baru seperti v1.1.1.</div>

## Integrasi CI

Banyak pipeline memicu deploy ketika tag dengan pola `v*` didorong. Itulah sebabnya annotated tag dengan pesan rilis sangat membantu: changelog bisa dibuat otomatis dari commit sejak tag sebelumnya.
