Git adalah **sistem version control** yang dipakai hampir semua developer di dunia: setiap perubahan kode tercatat, bisa dilihat ulang, dan bisa dikembalikan. Berbeda dari folder backup manual, Git bekerja di dalam project lewat folder tersembunyi `.git`.

## Kenapa Version Control Penting

Tanpa Git, kejadian seperti ini familiar:

- file bernama `skrip_v2_FINAL_fix2.sh`
- perubahan penting tidak sengaja terhapus tanpa jejak
- dua orang saling menimpa kerjaan di file yang sama

Git menyelesaikan semuanya: setiap versi punya commit ID, setiap orang punya salinan penuh repo (distribusi), dan perubahan bisa digabung secara terkendali.

## Inisialisasi Repository

```bash
mkdir proyek-pertama
cd proyek-pertama
git init
```

Output kira-kira: `Initialized empty Git repository in .../proyek-pertama/.git/`. Sejak saat itu, folder ini adalah repo Git.

## Mengatur Identitas

Setiap commit menyimpan penulis. Atur sekali di awal:

```bash
git config --global user.name "Nama Kamu"
git config --global user.email "kamu@email.com"
git config --global init.defaultBranch main
```

`--global` berlaku untuk semua repo di komputer kamu. Tanpa `--global`, setting hanya untuk repo sekarang.

## Membaca Status

```bash
echo "# Proyek Pertama" > README.md
git status
```

Keluaran penting:

```
Untracked files:
  README.md
```

**Untracked** = file baru yang belum pernah dicatat Git. Belum ada yang hilang — Git hanya memberi tahu.

## Alur Dasar Git

```
working directory  --git add-->  staging area  --git commit-->  repository (.git)
```

- **working directory** — file yang kamu edit di editor
- **staging area (index)** — daftar perubahan yang siap di-commit
- **repository** — riwayat permanen berupa rantai commit

## Tiga Area Inti Git

Git memindahkan perubahan melalui **3 area**. Memahami batasnya mencegah anggapan bahwa file yang sudah disimpan editor otomatis masuk riwayat.

| Area | Fungsi | Contoh pemeriksaan | Kapan dipakai |
|---|---|---|---|
| Working tree | Menampung file yang sedang diedit | `git diff` | Saat menulis dan menguji perubahan |
| Index (staging area) | Menyusun isi snapshot berikutnya | `git diff --staged` | Saat memilih perubahan untuk satu commit |
| Repository `.git` | Menyimpan commit, branch, tag, dan konfigurasi | `git log --oneline` | Saat menelusuri atau memulihkan versi |

`git add` menyalin keadaan perubahan ke index, bukan memindahkan file fisik. `git commit` lalu membuat snapshot dari index ke repository. Karena itu satu file dapat sekaligus memiliki versi committed, staged, dan perubahan baru di working tree.

## Fungsi Perintah Awal

Ada **6 perintah inti** untuk orientasi repo baru.

| Perintah | Fungsi | Contoh | Kapan dipakai |
|---|---|---|---|
| `git init` | Membuat metadata repo lokal | `git init` | Memulai project yang belum memakai Git |
| `git status` | Menjelaskan keadaan tiga area | `git status --short` | Sebelum add, commit, atau operasi berisiko |
| `git config` | Mengatur identitas dan perilaku | `git config --list --show-origin` | Saat setup mesin atau audit konfigurasi |
| `git add` | Memasukkan perubahan ke index | `git add README.md` | Menyiapkan snapshot |
| `git commit` | Menyimpan snapshot | `git commit -m "Tambah README"` | Setelah satu unit kerja selesai |
| `git log` | Membaca riwayat | `git log --oneline` | Memeriksa hasil commit |

Jangan menjalankan `git init` di home directory tanpa sengaja: Git akan menganggap seluruh turunannya sebagai working tree. Periksa `pwd`, lalu hapus hanya `.git` yang baru dibuat jika memang salah lokasi; menghapus `.git` pada repo nyata menghilangkan riwayat lokal.

## Di Dunia Nyata

- Memulai aplikasi internal dan memastikan konfigurasi editor tidak ikut tercatat lewat `.gitignore`.
- Memeriksa `git status` sebelum commit agar `.env`, private key, dan dump database tidak bocor.
- Menelusuri konfigurasi identitas ketika commit CI memakai email yang salah.
- Menggunakan repo lokal tanpa internet saat mengembangkan prototipe di perjalanan.

<div class="note">💡 `git init` tidak butuh server atau internet. Semua operasi Git berjalan lokal; remote seperti GitHub baru ditambahkan di bab remote.</div>
