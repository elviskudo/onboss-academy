Setelah sebuah fitur selesai dikerjakan di branch, pekerjaan itu harus kembali ke `main`. Di sinilah **merge** bekerja.

## Merge Sederhana

```bash
git switch main
git merge fitur-login
```

Kalau `main` tidak bergerak sejak cabang dibuat, terjadi **fast-forward**: pointer `main` cukup digeser ke commit terakhir `fitur-login` — bersih, tanpa commit tambahan.

## Memaksa Commit Merge (--no-ff)

```bash
git merge --no-ff fitur-login -m "Gabung fitur login"
```

Riwayat menjadi:

```
*   9a2b1c3 Gabung fitur login
|\
| * f3a91c2 Tambah form login
| * 44c8e01 Siapkan route auth
* | 8d1e0a4 Perbaiki README
|/
```

Struktur cabang tetap terlihat — berguna untuk audit dan blame.

## Menghadapi Konflik

```bash
git merge fitur-login
# Auto-merging app.py
# CONFLICT (content): Merge conflict in app.py
```

Buka file dan temukan penanda:

```
<<<<<<< HEAD
port = 8000
=======
port = 8080
>>>>>>> fitur-login
```

Perbaiki menjadi hasil yang kamu mau (hapus semua penanda), lalu:

```bash
git add app.py
git commit -m "Selesaikan konflik merge fitur-login"
```

Ingin membatalkan sepenuhnya:

```bash
git merge --abort
```

## Tips Mengurangi Konflik

- merge/rebase `main` ke cabang fitur secara berkala
- satu branch satu topik — jangan campur refactor besar dengan fitur kecil
- komunikasikan siapa menyentuh file apa

## Tiga Hasil Merge

| Hasil | Fungsi/arti | Contoh pemicu | Kapan dipakai |
|---|---|---|---|
| Fast-forward | Memajukan pointer tanpa commit merge | `git merge fitur-a` | Target belum punya commit baru |
| Three-way merge | Menggabungkan dua ujung dan leluhur bersama | `git merge fitur-b` | Kedua branch sudah berkembang |
| Konflik | Menunda hasil untuk keputusan manusia | Perubahan pada baris yang sama | Git tidak dapat memilih isi benar |

Selalu berada di branch **tujuan** sebelum merge. Untuk memasukkan fitur ke `main`, jalankan `git switch main`, perbarui `main`, lalu `git merge fitur`. Sesudah konflik diedit, cari semua penanda dengan `git diff --check`, jalankan test, stage file, dan selesaikan commit. Jangan sekadar memilih “ours” atau “theirs” tanpa memahami perilaku gabungannya; kedua sisi bisa sama-sama diperlukan.

`git merge --abort` aman untuk membatalkan merge yang belum selesai, tetapi perubahan lokal yang sudah ada sebelum merge dapat menyulitkan pemulihan. Mulailah dari working tree bersih. Menghapus file konflik atau memakai `reset --hard` tanpa inspeksi dapat membuang pekerjaan lokal.

## Di Dunia Nyata

- Menggabungkan branch login setelah CI dan review lulus.
- Menyelesaikan konflik lockfile dengan meregenerasi lockfile, bukan mengedit marker sembarang.
- Memakai `--no-ff` ketika kebijakan audit perlu menunjukkan batas satu fitur.
- Membatalkan merge untuk berdiskusi dengan pemilik perubahan sebelum menentukan hasil bisnis.

<div class="note">💡 Konflik merge bukan error fatal — itu Git meminta keputusan manusia karena dua perubahan saling bertabrakan. Baca kedua sisi, pilih yang benar, lalu commit hasilnya.</div>

## Memeriksa Hasil

```bash
git log --oneline --graph --all
git status
```

Pastikan tidak ada sisa konflik dan `git status` bersih sebelum lanjut.
