**Git hook** adalah skrip yang berjalan otomatis pada titik tertentu dalam alur Git. Ia membantu menegakkan kualitas tanpa mengingatkan manual setiap kali.

## Anatomi Hook

```bash
ls .git/hooks
# sample
```

File dengan akhiran `.sample` hanya contoh. Buat file tanpa akhiran itu dan beri izin eksekusi.

```bash
chmod +x .git/hooks/pre-commit
```

## Hook yang Umum

| Hook | Waktu jalan | Contoh penggunaan |
|---|---|---|
| pre-commit | sebelum commit | lint, format, unit test |
| prepare-commit-msg | sebelum editor pesan | template otomatis |
| commit-msg | setelah pesan ditulis | validasi format pesan |
| post-commit | setelah commit | notifikasi |
| pre-push | sebelum push | test integrasi |
| post-merge | setelah merge | install dependency baru |

## Contoh commit-msg

```sh
#!/bin/sh
pesan=$(cat "$1")
case "$pesan" in
  feat:*|fix:*|docs:*|chore:*) exit 0 ;;
esac
echo "Pesan harus diawali feat:, fix:, docs:, atau chore:"
echo "Contoh: fix: perbaiki format tanggal"
exit 1
```

## Membagikan ke Tim

Karena `.git/hooks` tidak ikut ter-commit, simpan skrip di folder seperti `scripts/hooks/` lalu pakai pengelola hook:

```bash
npx husky init
npx husky add .husky/pre-commit "npm test"
```

<div class="note">💡 Jangan taruh test berjam-jam di pre-commit. Hook yang terlalu lama membuat orang tergoda memakai `--no-verify`, yang mengalahkan tujuan awalnya.</div>

## Catatan Penting

Hook bisa dilewati dengan `--no-verify`, jadi tetap pasang pemeriksaan juga di CI. Perlakukan hook sebagai pagar pelindung, bukan satu-satunya garda keamanan.
