Autentikasi bukan sekadar form login. Yang lebih penting adalah menjaga status session tetap konsisten di seluruh aplikasi.

## Auth Context

```jsx
const AuthContext = React.createContext(null);

function AuthProvider({ children }) {
  const [user, setUser] = React.useState(null);
  const [memuat, setMuat] = React.useState(true);

  React.useEffect(() => {
    fetch("/api/saya", { credentials: "include" })
      .then((r) => (r.ok ? r.json() : null))
      .then(setUser)
      .finally(() => setMuat(false));
  }, []);

  async function login(email, password) {
    const res = await fetch("/api/login", {
      method: "POST",
      credentials: "include",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ email, password }),
    });
    if (!res.ok) throw new Error("Login gagal");
    setUser(await res.json());
  }

  async function logout() {
    await fetch("/api/logout", { method: "POST", credentials: "include" });
    setUser(null);
  }

  return (
    <AuthContext.Provider value={{ user, login, logout, memuat }}>
      {children}
    </AuthContext.Provider>
  );
}
```

## Rute Terlindungi

```jsx
function Protected({ children }) {
  const { user, memuat } = React.useContext(AuthContext);
  if (memuat) return <p>Memeriksa sesi…</p>;
  if (!user) return <Navigate to="/login" replace />;
  return children;
}
```

Pasang di level rute:

```jsx
<Route path="/dashboard" element={
  <Protected><Dashboard /></Protected>
} />
```

## Tips Keamanan

- Simpan sesi di cookie `httpOnly`, `secure`, `sameSite`.
- Jangan taruh token di URL atau localStorage bila bisa dihindari.
- Tetap validasi izin di server — UI hanya pembatas pengalaman, bukan pengaman.

<div class="note">💡 Tiga lapisan yang saling melengkapi: server memutuskan akses, API memeriksa session, dan React menyembunyikan UI yang tidak relevan. Jangan hanya mengandalkan salah satu.</div>
