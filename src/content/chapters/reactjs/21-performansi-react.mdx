React sudah cepat untuk sebagian besar aplikasi. Masalah muncul saat daftar besar atau state tersebar terlalu luas.

## Langkah Pertama: Ukur

Gunakan React DevTools → tab **Profiler**, rekam interaksi, lalu lihat komponen mana yang lama. Jangan menebak.

## Penyebab Umum

| Penyebab | Solusi |
|----------|--------|
| Induk render → semua anak render | `React.memo` pada anak |
| Fungsi baru tiap render | `useCallback` |
| Hitung berat tiap render | `useMemo` |
| 10.000 baris sekaligus | virtualisasi |

## React.memo

```jsx
const Baris = React.memo(function Baris({ produk, onPilih }) {
  console.log("render baris", produk.id);
  return (
    <li>
      {produk.nama}
      <button onClick={() => onPilih(produk.id)}>Pilih</button>
    </li>
  );
});
```

`memo` hanya efektif bila props benar-benar stabil. Itulah sebabnya `useCallback` sering dipasangkan.

## Virtualisasi

```jsx
// konsep: render hanya window yang terlihat
const UkuranBaris = 40;
const mulai = Math.floor(scrollTop / UkuranBaris);
const akhir = mulai + 20;
const terlihat = items.slice(mulai, akhir);
```

Di produksi gunakan librari seperti `react-window` atau `@tanstack/react-virtual`.

## State yang Terlalu Tinggi

```jsx
// ❌ ketikan di satu input merender seluruh halaman
function App() {
  const [kata, setKata] = useState("");
  return <><Header /><FormCari kata={kata} ubah={setKata} /><DaftarBesar /></>;
}
```

Pindahkan `kata` ke `FormCari` atau gunakan context terpisah.

<div class="note">💡 Urutan yang disarankan: ukur → perbaiki struktur state → baru memo/virtualisasi. Optimasi tanpa pengukuran sering membuat kode lebih rumit tanpa hasil.</div>
