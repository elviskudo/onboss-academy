Tanpa penanganan, satu error di komponen bisa membuat seluruh aplikasi putih. *Error boundary* membatasi kerusakan itu.

## Membuat Boundary

```jsx
class BatasError extends React.Component {
  constructor(props) {
    super(props);
    this.state = { error: null };
  }

  static getDerivedStateFromError(error) {
    return { error };
  }

  componentDidCatch(error, info) {
    console.error("Error UI:", error, info.componentStack);
    // kirim ke layanan logging di sini
  }

  render() {
    if (this.state.error) {
      return (
        <div className="error-box">
          <h2>Yaah, bagian ini gagal dimuat.</h2>
          <button onClick={() => this.setState({ error: null })}>
            Coba lagi
          </button>
        </div>
      );
    }
    return this.props.children;
  }
}
```

## Memakainya

```jsx
<BatasError>
  <GrafikPenjualan />
</BatasError>

<BatasError>
  <PanelRekomendasi />
</BatasError>
```

Kalau grafik gagal, rekomendasi tetap tampil. Ini alasan boundary sebaiknya ditempatkan di beberapa titik strategis.

## Yang Tidak Ditangkap

- Error di event handler → pakai `try/catch`.
- Error di `setTimeout`, `Promise`, atau `async` → tangani dengan `.catch`.
- Error di boundary itu sendiri → butuh boundary di atasnya.

```jsx
async function simpan() {
  try {
    await api.simpan(data);
  } catch (e) {
    setPesan("Gagal menyimpan: " + e.message);
  }
}
```

## Fallback yang Baik

Fallback sebaiknya informatif dan punya jalan keluar: tombol ulangi, tautan ke halaman utama, atau pesan yang menjelaskan apa yang gagal.

<div class="note">💡 Error boundary bukan pengganti pengujian. Ia adalah jaring pengaman terakhir agar user tidak melihat layar kosong saat terjadi kegagalan tak terduga.</div>
