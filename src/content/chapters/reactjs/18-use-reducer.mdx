Saat state punya beberapa transisi yang saling terkait, `useReducer` lebih rapi daripada beberapa `useState`.

## Konsep Dasar

```jsx
const awal = { qty: 0, harga: 25000 };

function reducer(state, action) {
  switch (action.type) {
    case "tambah":
      return { ...state, qty: state.qty + 1 };
    case "kurangi":
      return { ...state, qty: Math.max(0, state.qty - 1) };
    case "kosongkan":
      return { ...state, qty: 0 };
    default:
      return state; // aksi tak dikenal → state tetap
  }
}

function Keranjang() {
  const [state, dispatch] = React.useReducer(reducer, awal);
  const total = state.qty * state.harga;

  return (
    <div>
      <p>{state.qty} item — Rp{total.toLocaleString("id-ID")}</p>
      <button onClick={() => dispatch({ type: "tambah" })}>+</button>
      <button onClick={() => dispatch({ type: "kurangi" })}>−</button>
      <button onClick={() => dispatch({ type: "kosongkan" })}>Kosongkan</button>
    </div>
  );
}
```

## Aksi yang Membawa Data

```jsx
dispatch({ type: "set", qty: 5 });
// di reducer:
case "set":
  return { ...state, qty: action.qty };
```

## Kenapa Reducer Murni itu Penting

```jsx
// ❌ salah: mengubah state lama
state.qty += 1;
return state;

// ✅ benar: objek baru
return { ...state, qty: state.qty + 1 };
```

React membandingkan referensi. Kalau objeknya sama, ia mengira tidak ada perubahan.

## Perbandingan

| | useState | useReducer |
|---|----------|------------|
| State sederhana | ✅ | berlebihan |
| Banyak aksi terkait | bisa berantakan | ✅ rapi |
| Logika bisa diuji terpisah | agak sulit | ✅ mudah |
| Boilerplate | sedikit | lebih banyak |

<div class="note">💡 Reducer juga jadi fondasi Redux. Menguasai pola ini membuatmu lebih siap saat proyek membutuhkan state global yang kompleks.</div>
