`useEffect` menyambungkan komponen ke dunia luar: API, timer, subscription, dan DOM.

## Anatomi Efek

```jsx
React.useEffect(() => {
  // 1. aksi utama
  const timer = setInterval(() => setDetik((d) => d + 1), 1000);

  // 2. cleanup (opsional)
  return () => clearInterval(timer);
}, []); // 3. dependency
```

| Dependency | Perilaku |
|------------|----------|
| tidak ada | tiap render |
| `[]` | sekali saat mount |
| `[id]` | saat `id` berubah |

## Fetch dengan Aman

```jsx
function DetailProduk({ id }) {
  const [produk, setProduk] = React.useState(null);
  const [error, setError] = React.useState("");

  React.useEffect(() => {
    const controller = new AbortController();

    fetch(`/api/produk/${id}`, { signal: controller.signal })
      .then((res) => {
        if (!res.ok) throw new Error("Gagal memuat");
        return res.json();
      })
      .then(setProduk)
      .catch((e) => {
        if (e.name !== "AbortError") setError(e.message);
      });

    return () => controller.abort();
  }, [id]);

  if (error) return <p>{error}</p>;
  if (!produk) return <p>Memuat…</p>;
  return <h2>{produk.nama}</h2>;
}
```

Tanpa `abort`, response lama bisa menimpa data baru saat user cepat berpindah `id` — ini disebut *race condition*.

## Efek dan DOM

```jsx
const ref = React.useRef(null);

React.useEffect(() => {
  ref.current?.focus();
}, []);

<input ref={ref} />
```

Efek berjalan setelah DOM tersedia, jadi `ref.current` sudah terisi.

## Kapan Tidak Perlu Efek

- Mengubah data yang sudah ada di props → cukup hitung saat render.
- Transformasi array → `map`/`filter` langsung.
- Menangani event → gunakan event handler.

<div class="note">💡 Anggap useEffect sebagai "jembatan keluar", bukan tempat meletakkan semua logika. Makin sedikit efek, makin mudah aplikasi diprediksi.</div>
