Test membuat perubahan di masa depan lebih aman. Fokusnya: **apa yang dilihat dan dilakukan user**.

## Menyiapkan

```bash
npm i -D vitest @testing-library/react @testing-library/user-event jsdom
```

```js
// vitest.config.js
export default { test: { environment: "jsdom", globals: true } };
```

## Test Pertama

```jsx
// Counter.jsx
export default function Counter() {
  const [n, setN] = React.useState(0);
  return (
    <div>
      <output>{n}</output>
      <button onClick={() => setN(n + 1)}>Tambah</button>
    </div>
  );
}
```

```jsx
import { render, screen } from "@testing-library/react";
import userEvent from "@testing-library/user-event";
import Counter from "./Counter";

test("menampilkan 0 lalu bertambah", async () => {
  render(<Counter />);
  expect(screen.getByRole("status")).toHaveTextContent("0");

  await userEvent.click(screen.getByRole("button", { name: "Tambah" }));
  expect(screen.getByRole("status")).toHaveTextContent("1");
});
```

Catatan: elemen `<output>` punya peran `status`, sehingga lebih stabil daripada mencari tag.

## Query yang Disarankan

| Prioritas | Contoh |
|-----------|--------|
| 1 | `getByRole` |
| 2 | `getByLabelText` |
| 3 | `getByText` |
| 4 | `getByTestId` (terakhir) |

## Test Form

```jsx
await userEvent.type(screen.getByLabelText(/nama/i), "Sari");
await userEvent.click(screen.getByRole("button", { name: /simpan/i }));
expect(screen.getByText(/halo, sari/i)).toBeInTheDocument();
```

<div class="note">💡 Hindari test yang mengecek state internal atau snapshot besar. Test yang terlalu rapuh justru memperlambat tim saat UI diperbarui.</div>
