Seiring pertumbuhan proyek, waktu `tsc` bisa meningkat. Beberapa kebiasaan menjaga pengalaman pengembangan tetap menyenangkan.

## Konfigurasi untuk Proyek Besar

```json
{
  "compilerOptions": {
    "incremental": true,
    "tsBuildInfoFile": ".cache/tsbuildinfo",
    "skipLibCheck": true,
    "strict": true,
    "verbatimModuleSyntax": true,
    "moduleResolution": "bundler"
  }
}
```

`incremental` menyimpan hasil kompilasi sebelumnya sehingga run berikutnya hanya memproses file yang berubah.

## Pisahkan Typecheck dari Build

```json
{
  "scripts": {
    "typecheck": "tsc --noEmit",
    "build": "vite build",
    "test": "vitest"
  }
}
```

Biarkan bundler (Vite/esbuild/SWC) yang menghasilkan JS — mereka jauh lebih cepat. TypeScript cukup bertugas memeriksa tipe.

## Kurangi any

```ts
// ❌
function proses(data: any): any { ... }

// ✅
function proses(data: unknown): Hasil<Output> { ... }
```

Semakin sedikit `any`, semakin banyak bug yang tertangkap sebelum produksi.

## Impor Efisien

```ts
import type { User } from "./types";
import { ambilUser } from "./api";
```

Dengan `verbatimModuleSyntax`, kamu harus eksplisit memakai `import type` untuk tipe. Ini membuat output JS lebih bersih dan prediktabel.

## Hindari Tipe Terlalu Kompleks

```ts
// ⚠️ sulit dibaca dan bisa melambatkan compiler
type Aku = T extends infer U ? U extends V ? ... : ... : never;

// ✅ pecah jadi beberapa langkah
type Dasar = T extends V ? ... : ...;
type Aku = Dasar extends W ? ... : ...;
```

Conditional type yang bersarang dalam bisa memicu error "Type instantiation is excessively deep".

## Struktur Folder

```
src/
  types/        → deklarasi global & skema
  components/   → UI
  lib/          → helper murni
  hooks/        → logic reusable
```

Memisahkan tipe dari implementasi memudahkan navigasi dan mengurangi ketergantungan siklik.

## Alat Bantu

- `tsc --extendedDiagnostics` — melihat bagian mana yang paling lama.
- `tsc --generateTrace` — jejak detail untuk analitik performa compiler.
- ESLint + typescript-eslint — aturan tambahan di luar compiler.
- `tsc --noEmit --pretty false` — output mudah dibaca di CI.

<div class="note">💡 Jangan menurunkan `strict` demi menghilangkan error. Perbaiki penyebabnya — error tersebut biasanya memang menunjukkan bug nyata.</div>

## Di Dunia Nyata

- Monorepo memakai project references agar paket bisa dikompilasi paralel.
- CI menjalankan `typecheck` sebelum test untuk fail fast.
- `import type` mengurangi ukuran bundle pada proyek dengan banyak tipe shared.
