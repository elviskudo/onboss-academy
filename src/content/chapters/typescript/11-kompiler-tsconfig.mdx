TypeScript bukan dijalankan langsung oleh browser. Kode kamu harus dikompilasi menjadi JavaScript oleh `tsc` atau oleh bundler yang memakai compiler tersebut.

## Alur Kerja Kompilasi

```bash
npm install -D typescript
npx tsc --init        # membuat tsconfig.json
npx tsc               # kompilasi sekali
npx tsc --noEmit      # hanya cek tipe
npx tsc --watch       # pantau perubahan
```

File `.ts` berubah menjadi `.js`. Kalau memakai `sourceMap: true`, dihasilkan juga `.js.map` untuk memetakan error kembali ke kode aslinya.

## Struktur tsconfig.json

```json
{
  "compilerOptions": {
    "target": "ES2020",
    "lib": ["ES2020", "DOM"],
    "module": "ESNext",
    "moduleResolution": "bundler",
    "strict": true,
    "noEmit": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "forceConsistentCasingInFileNames": true,
    "baseUrl": ".",
    "paths": { "@/*": ["src/*"] }
  },
  "include": ["src"],
  "exclude": ["node_modules", "dist"]
}
```

## Opsi yang Paling Berdampak

| Opsi | Efek |
|------|------|
| `strict` | Paket pemeriksaan ketat sekaligus |
| `noImplicitAny` | Error kalau tipe tidak bisa disimpulkan |
| `strictNullChecks` | `null`/`undefined` tidak otomatis bisa ditugaskan |
| `noUnusedLocals` | Error pada variabel yang tidak dipakai |
| `exactOptionalPropertyTypes` | Opsional tidak sama dengan `undefined` eksplisit |
| `noUncheckedIndexedAccess` | Akses array/record bisa `undefined` |

## Target vs Module

- `target` mengatur **sintaks** JavaScript output (apakah arrow function diturunkan ke `function`).
- `module` mengatur **sistem module** (`ESNext`, `CommonJS`, `NodeNext`).

Memilih keduanya harus selaras dengan tempat kode dijalankan. Proyek Next.js/Vite memakai `ESNext`; proyek Node lama bisa memakai `CommonJS`.

## File Deklarasi (.d.ts)

```ts
declare module "pustaka-tanpa-tipe" {
  export function proses(input: string): number;
}
```

File `.d.ts` hanya berisi tipe, tanpa implementasi. `@types/nama-paket` dari npm adalah cara paling umum mendapatkan deklarasi untuk library JavaScript.

## Type Checking di Editor vs Build

Editor (VS Code) memakai TypeScript Language Service untuk memberi squiggly merah saat kamu mengetik. Itu berbeda dengan hasil `tsc`. Selalu jalankan `tsc --noEmit` di CI agar pemeriksaan tidak hanya bergantung pada editor.

<div class="note">💡 `skipLibCheck: true` mempercepat kompilasi dengan tidak mengecek file `.d.ts` di node_modules. Aman untuk kebanyakan proyek aplikasi.</div>

## Di Dunia Nyata

- Monorepo memakai `extends` untuk membagi konfigurasi dasar antar paket.
- `paths` memungkinkan import `@/components/Button` tanpa `../../../`.
- `tsc --noEmit` dipasang sebagai script `npm run typecheck` sebelum deploy.
