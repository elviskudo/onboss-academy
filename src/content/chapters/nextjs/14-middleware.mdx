Middleware adalah lapisan penjaga di depan rute. Ia berjalan sebelum halaman atau route handler diproses.

## Contoh Auth Redirect

```ts
// middleware.ts
import { NextResponse } from "next/server";
import type { NextRequest } from "next/server";

export function middleware(request: NextRequest) {
  const session = request.cookies.get("session")?.value;

  if (!session && request.nextUrl.pathname.startsWith("/dashboard")) {
    const url = new URL("/login", request.url);
    url.searchParams.set("next", request.nextUrl.pathname);
    return NextResponse.redirect(url);
  }

  return NextResponse.next();
}

export const config = {
  matcher: ["/dashboard/:path*"],
};
```

## Rewrite

```ts
if (request.nextUrl.pathname.startsWith("/blog")) {
  const url = request.nextUrl.clone();
  url.pathname = `/artikel${url.pathname}`;
  return NextResponse.rewrite(url);
}
```

Browser tetap menampilkan `/blog/...` tapi konten berasal dari `/artikel/...`.

## Matcher

```ts
export const config = {
  matcher: ["/((?!_next/static|_next/image|favicon.ico).*)"],
};
```

Ini mengabaikan aset internal agar middleware tidak dipanggil sia-sia.

## Header Respons

```ts
const response = NextResponse.next();
response.headers.set("x-request-id", crypto.randomUUID());
return response;
```

<div class="note">💡 Middleware cepat dan dekat dengan pengguna, tapi jangan menyimpan logika sensitif di sini. Otorisasi akhir tetap dilakukan di server/API.</div>
