Next.js adalah jawaban React untuk kebutuhan produksi: routing lengkap, rendering di server, dan pengiriman aset yang optimal — semuanya dengan konfigurasi minimal.

## Apa yang Ditambahkan Next.js ke React?

React sendiri hanya menangani tampilan. Next.js menambahkan:

- **Routing berbasis folder**: struktur `app/` = struktur URL
- **Rendering fleksibel**: server (SSR), statis (SSG), atau hybrid per halaman
- **Data fetching bawaan**: `fetch` di server component dengan cache terkontrol
- **Optimasi**: gambar, font, dan skrip dioptimasi otomatis
- **API bawaan**: route handler untuk endpoint tanpa server terpisah

## Server, Static, atau Client?

```typescript
// Halaman dirender di server setiap request (SSR)
export const dynamic = "force-dynamic";

// Atau dibangun sekali saat build (SSG), lalu direfresh berkala
export const revalidate = 60;
```

Keputusan rendering bisa dibuat per halaman — bukan untuk seluruh aplikasi sekaligus.

## Struktur Berbasis Folder

```
app/
  layout.tsx     layout global
  page.tsx       halaman beranda → /
  produk/
    page.tsx     /produk
```

Tidak ada file daftar rute manual. Folder dan file bernama khusus (`page`, `layout`, `route`) langsung dipetakan ke URL.

## Hydration Singkat

Di sisi client, React menghidupkan bagian client component melalui hydration sehingga event listener terpasang pada HTML yang sudah terlihat.

## Lima Kemampuan Inti

Next.js App Router menyatukan **5 kemampuan inti**.

| Kemampuan | Fungsi | Contoh | Kapan dipakai |
|---|---|---|---|
| File-system routing | Memetakan folder ke URL | `app/produk/page.tsx` | Semua halaman |
| Server Components | Render dan akses data di server | komponen `async` | Konten tanpa interaksi browser |
| Client Components | Menyediakan state dan event | `useState` | Tombol, input, browser API |
| Route Handlers | Membuat endpoint HTTP | `app/api/route.ts` | Webhook atau API publik |
| Metadata API | Menghasilkan informasi SEO | `metadata` | Judul, deskripsi, social preview |

React menyediakan model komponen; Next.js menentukan cara komponen dirutekan, dirender, mengambil data, dan dikirim. State browser tetap memakai React, misalnya `useState`, tetapi data rahasia dan query database tinggal di server.

```typescript
"use client";

import { useState } from "react";

export default function Counter() {
  const [jumlah, setJumlah] = useState(0);
  return <button onClick={() => setJumlah(jumlah + 1)}>Klik {jumlah}</button>;
}
```

## Alur Satu Request

Ada **4 tahap utama**: router mencocokkan URL, server component mengambil data, server mengirim hasil render, lalu client component di-hydrate jika perlu. Tautan internal berikutnya memakai navigasi client-side dan mempertahankan layout yang sama.

## Di Dunia Nyata

- Situs berita merender artikel di server agar crawler menerima isi lengkap.
- Dashboard memakai client component kecil untuk filter interaktif.
- Toko menghasilkan halaman produk statis dan menyegarkannya berkala.
- SaaS menaruh webhook pembayaran di route handler tanpa server terpisah.

<div class="note">💡 Prinsip Next.js: default-kan pekerjaan di server, kirim JavaScript ke browser seperlunya. Membatasi penggunaan "use client" adalah kunci performa App Router — kamu akan mempraktikkannya di bab komponen server & client.</div>
