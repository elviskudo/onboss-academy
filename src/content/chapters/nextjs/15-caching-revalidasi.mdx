Cache adalah alasan Next.js terasa cepat. Tapi cache yang tidak dipahami bisa membuat data tampak "basi".

## Opsi fetch

```ts
// di-cache, diperbarui tiap 60 detik
const data = await fetch(url, { next: { revalidate: 60 } });

// selalu ambil data baru
const segar = await fetch(url, { cache: "no-store" });

// beri tag agar bisa dihapus manual
const berTag = await fetch(url, { next: { tags: ["produk"] } });
```

## Revalidate dari Aksi

```ts
"use server";

import { revalidateTag, revalidatePath } from "next/cache";

export async function simpanProduk(formData: FormData) {
  await updateProduk(formData);
  revalidateTag("produk");
  revalidatePath("/produk");
}
```

Setelah aksi selesai, halaman terkait diperbarui tanpa menunggu masa kedaluwarsa.

## Route Segment Config

```tsx
// app/produk/page.tsx
export const revalidate = 300; // 5 menit
export const dynamic = "force-dynamic"; // selalu dinamis
```

## Memilih Strategi

| Data | Strategi |
|------|----------|
| Harga saham | `no-store` |
| Katalog produk | revalidate 60–3600 |
| Artikel blog | revalidate / static |
| Dashboard user | dinamis per request |

<div class="note">💡 Mulai dari cache default, lalu ubah hanya bila data memang berubah cepat. Terlalu banyak `no-store` menghilangkan keuntungan server rendering.</div>
