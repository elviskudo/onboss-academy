Salah satu alasan orang pindah ke Next.js: mengambil data tanpa membuat endpoint terpisah. Di App Router, halaman biasa adalah komponen async.

## await Langsung di Halaman

```typescript
// app/produk/page.tsx
type Produk = { id: number; nama: string; harga: number };

async function ambilProduk(): Promise<Produk[]> {
  const res = await fetch(`${process.env.API_URL}/produk`);
  if (!res.ok) throw new Error("Gagal memuat produk");
  return res.json();
}

export default async function ProdukPage() {
  const produk = await ambilProduk();

  return (
    <ul>
      {produk.map((p) => (
        <li key={p.id}>
          {p.nama} — Rp{p.harga}
        </li>
      ))}
    </ul>
  );
}
```

Tidak ada useEffect, tidak ada state loading manual — server yang menunggu, user menerima HTML utuh.

## Mengontrol Cache

```typescript
// selalu segar (tanpa cache)
const akun = await fetch(`${API_URL}/akun`, { cache: "no-store" });

// di-cache statis, diisi saat build
const kategori = await fetch(`${API_URL}/kategori`, { cache: "force-cache" });

// di-cache + refresh berkala
const artikel = await fetch(`${API_URL}/artikel`, { next: { revalidate: 60 } });
```

Pilih kebijakan cache per data, sesuai sifatnya: profil user = no-store, katalog = force-cache, berita = revalidate.

## ISR: Halaman Statis yang Hidup

```typescript
// app/artikel/page.tsx
export const revalidate = 300; // detik

export default async function ArtikelPage() {
  const artikel = await fetch(`${API_URL}/artikel`, { next: { revalidate: 300 } });
  return <DaftarArtikel artikel={await artikel.json()} />;
}
```

Halaman dirender statis lalu diperbarui di latar belakang — kombinasi cepatnya SSG dengan datanya yang tetap segar.

## Streaming dengan Suspense

```typescript
import { Suspense } from "react";

export default function Halaman() {
  return (
    <main>
      <h1>Katalog</h1>
      <Suspense fallback={<p>Memuat ulasan…</p>}>
        <UlasanTerbaru />   {/* async component di file sendiri */}
      </Suspense>
    </main>
  );
}
```

Bagian cepat tampil segera; bagian lambat menyusul saat siap — user tidak menatap layar kosong.

## Fetch di Banyak Tempat dengan Aman

```typescript
// lib/produk.ts — dipakai berbagai komponen
export async function getProduk(id: string) {
  const res = await fetch(`${API_URL}/produk/${id}`, { next: { revalidate: 60 } });
  if (!res.ok) return null;
  return res.json() as Promise<Produk | null>;
}
```

Untuk akses data non-`fetch`, React `cache()` dapat memoize pemanggilan yang sama dalam satu proses render agar layout dan halaman tidak mengulang query.

## Tiga Strategi Kesegaran

Pilih **3 strategi utama** berdasarkan sifat data.

| Strategi | Konfigurasi | Fungsi | Kapan dipakai |
|---|---|---|---|
| Dinamis | `cache: "no-store"` | membaca sumber terbaru | akun dan stok kritis |
| Statis | `cache: "force-cache"` | memakai data tersimpan | kategori jarang berubah |
| Revalidasi | `next: { revalidate: 60 }` | menyegarkan berkala | artikel dan katalog |

Cache request, cache data, dan cache halaman adalah lapisan berbeda. Nyatakan kebijakan secara eksplisit dan ukur kebutuhan aktual; jangan meng-cache data personal lintas pengguna. Jalankan request independen secara paralel agar tidak membentuk waterfall.

```typescript
const [produk, kategori] = await Promise.all([
  getProduk(),
  getKategori(),
]);
```

Error dari `fetch` HTTP tidak otomatis melempar untuk status 404/500, sehingga `res.ok` wajib diperiksa. Gunakan `notFound()` untuk resource yang memang tidak ada dan biarkan error tak terduga ditangkap `error.tsx`.

## Di Dunia Nyata

- Profil login memakai `no-store` agar data antar pengguna tidak tertukar.
- Kategori toko memakai cache statis karena hampir tidak berubah.
- Berita memakai revalidasi 60 detik agar cepat tetapi tetap segar.
- Dasbor menjalankan query statistik independen secara paralel dan men-stream widget lambat.

<div class="note">💡 Pertanyaan pertama setiap kali mengambil data: "seberapa sering data ini berubah?" Jawabannya menentukan cache: no-store untuk data personal, revalidate untuk konten editorial, force-cache untuk referensi yang hampir tidak pernah berubah.</div>
