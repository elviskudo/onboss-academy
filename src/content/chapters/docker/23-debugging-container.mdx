Debugging container mirip debugging proses biasa, dengan tambahan lapisan isolasi. Kuncinya: mulai dari log, lalu metadata, baru masuk ke dalam container.

## Alur Investigasi

```bash
docker ps -a --filter name=api
docker logs --tail 200 api
docker inspect api
docker events --since 5m --filter container=api
```

## Membaca Log

```bash
docker logs -f api                  # ikuti log langsung
docker logs --since 10m api         # hanya 10 menit terakhir
docker logs --timestamps api        # tambah waktu tiap baris
```

Aplikasi sebaiknya menulis log ke **stdout/stderr**, bukan ke file di dalam container. Docker lalu bisa mengumpulkannya dengan driver logging.

## Masuk ke Container

```bash
docker exec -it api sh          # alpine/busybox
docker exec -it api bash        # debian/ubuntu
docker exec api env | sort
docker exec api ls -la /app
```

`exec` hanya bekerja pada container yang sedang berjalan. Untuk container yang sudah mati, salin filenya dengan `docker cp api:/path ./local`.

## Kode Exit yang Umum

| Kode | Arti |
|---|---|
| 0 | Selesai sukses |
| 1 | Error aplikasi umum |
| 125 | Docker sendiri gagal menjalankan container |
| 126 | Perintah tidak bisa dieksekusi |
| 127 | Perintah tidak ditemukan |
| 137 | SIGKILL, sering kehabisan memori |
| 143 | SIGTERM diakhiri dengan rapi |

## Memeriksa OOM

```bash
docker inspect --format '{{.State.OOMKilled}}' api
docker stats --no-stream api
```

<div class="note">💡 `docker logs` hanya melihat proses PID 1. Jika aplikasinya memfork child yang mencetak ke file, log itu tidak muncul—ubah aplikasi agar menulis ke stdout.</div>
