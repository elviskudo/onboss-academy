Container bukan mesin virtual: ia berbagi kernel dengan host. Karena itu, konfigurasi keamanan yang baik tetap wajib walaupun image berasal dari sumber tepercaya.

## Prinsip Dasar

1. **Image minimal** — lebih sedikit paket berarti lebih sedikit kerentanan.
2. **Non-root** — jalankan proses dengan UID tetap.
3. **Filesystem read-only** — tulis hanya di lokasi yang disengaja.
4. **Capability dibatasi** — berikan hanya yang benar-benar diperlukan.
5. **Tidak ada secret di layer** — gunakan mount atau layanan khusus.

## User Non-root

```dockerfile
FROM node:20-alpine
RUN adduser -D -u 10001 appuser
WORKDIR /app
COPY --chown=appuser:appuser package*.json ./
RUN npm ci --omit=dev
COPY --chown=appuser:appuser . .
USER 10001
CMD ["node", "server.js"]
```

Memberi UID numerik (bukan hanya nama) memudahkan pencocokan hak akses dengan volume di host.

## Membatasi Hak

```bash
docker run --rm -d \
  --read-only \
  --tmpfs /tmp:size=16m \
  --cap-drop ALL \
  --cap-add NET_BIND_SERVICE \
  --security-opt no-new-privileges \
  --pids-limit 100 \
  app:1.0
```

`no-new-privileges` mencegah proses mendapat hak lebih tinggi lewat `setuid`. `--pids-limit` melindungi dari serangan fork bomb.

## Memindai Image

```bash
docker build -t app:1.0 .
trivy image app:1.0
trivy image --severity HIGH,CRITICAL app:1.0
```

Hasil pemindaian bukan vonis mutlak—beberapa CVE tidak relevan untuk penggunaanmu. Tetap perbarui base image secara berkala dan pin digest yang sudah terverifikasi.

<div class="note">💡 Socket `/var/run/docker.sock` jangan pernah di-mount ke container yang bisa diakses pengguna biasa. Siapa pun yang bisa memanggil API Docker pada dasarnya mendapat hak root host.</div>
