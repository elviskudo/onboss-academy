Deploy yang sehat memisahkan **build** dari **run**. Pipeline CI membangun image sekali, menyimpannya di registry, lalu setiap lingkungan menarik artefak yang sama.

## Alur yang Disarankan

```bash
# CI
docker build -t app:${GIT_SHA} .
docker tag app:${GIT_SHA} registry/tim/app:1.4.2
docker push registry/tim/app:1.4.2

# Server
docker pull registry/tim/app:1.4.2
docker stop app-lama
docker rm app-lama
docker run -d --name app-baru -p 80:80 registry/tim/app:1.4.2
```

## Deploy Bertahap (Blue-Green)

1. Jalankan versi baru di port sementara (`8081`).
2. Jalankan healthcheck dan uji smoke.
3. Arahkan load balancer ke versi baru.
4. Biarkan versi lama hidup sebentar untuk rollback.
5. Hentikan versi lama setelah yakin.

## Deployment dengan Compose

```bash
docker compose pull api
docker compose up -d --no-deps --build api
docker compose ps
```

Compose akan membuat container baru hanya untuk layanan yang berubah. Tambahkan `--remove-orphans` bila ada layanan lama yang sudah tidak ada di file.

## Runtime Configuration

Konfigurasi yang berbeda per lingkungan sebaiknya disuntikkan saat run, bukan ditanam di image:

```bash
docker run -d \
  -e APP_ENV=production \
  --env-file /etc/app/prod.env \
  -v /etc/app/certs:/certs:ro \
  registry/tim/app:1.4.2
```

## Checklist Sebelum Rilis

- [ ] Image sudah dipindai kerentanannya.
- [ ] Tag atau digest dicatat di release notes.
- [ ] Healthcheck aktif dan endpoint `/health` ringan.
- [ ] Backup database terakhir diverifikasi.
- [ ] Prosedur rollback sudah dilatih.

<div class="note">💡 Jangan pernah menimpa tag `latest` sebagai satu-satunya penanda rilis. Jika ada masalah, kamu tidak punya nama lama untuk kembali.</div>
