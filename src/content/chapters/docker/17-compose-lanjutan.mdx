File `docker-compose.yml` dasar sudah cukup untuk proyek kecil. Saat aplikasi bertumbuh, beberapa opsi tambahan membuatnya lebih andal.

## Menunggu Kesediaan, Bukan Sekadar Urutan

```yaml
services:
  db:
    image: postgres:16-alpine
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U app"]
      interval: 5s
      timeout: 3s
      retries: 5

  api:
    build: .
    depends_on:
      db:
        condition: service_healthy
```

Tanpa `condition`, Compose hanya menunggu container db **dibuat**, bukan siap menerima koneksi—sumber error `connection refused` saat startup.

## Kebijakan Restart

| Nilai | Perilaku |
|---|---|
| `no` | Tidak restart otomatis (default) |
| `always` | Selalu restart, termasuk setelah daemon restart |
| `on-failure` | Restart hanya saat exit code bukan 0 |
| `unless-stopped` | Seperti always, kecuali container sengaja distop |

## Override per Lingkungan

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d
```

File kedua menggabung/menimpa nilai file pertama. Ini cara rapi menyimpan pengaturan produksi tanpa menggandakan seluruh konfigurasi.

## Perintah Sehari-hari

```bash
docker compose config          # lihat hasil gabungan & substitusi variabel
docker compose up -d --build   # rebuild image lalu jalankan
docker compose logs -f api     # log satu layanan
docker compose exec db psql -U app
docker compose ps
docker compose down            # stop + hapus container & network
docker compose down -v         # + hapus volume (hati-hati!)
```

<div class="note">💡 Gunakan `${VARIABLE:-default}` di file compose untuk memberi nilai cadangan. Simpan nilai nyata di `.env`, dan jangan commit file itu ke repository.</div>
