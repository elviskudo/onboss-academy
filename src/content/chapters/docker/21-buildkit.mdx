BuildKit adalah mesin build generasi baru Docker. Ia membangun graf dependensi instruksi, menjalankan stage yang saling bebas secara paralel, dan menyediakan mount khusus untuk cache serta secret.

## Mengaktifkan

```bash
DOCKER_BUILDKIT=1 docker build -t app:1.0 .
docker build --progress=plain -t app:1.0 .
```

Baris directives di awal Dockerfile menentukan versi parser yang dipakai:

```dockerfile
# syntax=docker/dockerfile:1
```

## Cache Mount

```dockerfile
RUN --mount=type=cache,target=/root/.npm npm ci
RUN --mount=type=cache,target=/var/cache/apt \
    apt-get update && apt-get install -y curl
```

Berbeda dengan cache layer, cache mount **tidak ikut** ke dalam image final. Isinya bertahan antar build sehingga mengunduh ulang paket bisa dihindari.

## Secret Mount

```dockerfile
RUN --mount=type=secret,id=npmrc,target=/root/.npmrc \
    npm ci --include=dev
```

```bash
docker build --secret id=npmrc,src=$HOME/.npmrc -t app:1.0 .
```

File rahasia hanya tersedia selama perintah `RUN` berjalan. Ia tidak masuk layer, tidak bisa dilihat dengan `docker history`, dan tidak ikut ter-push.

## Cache Eksternal untuk CI

```bash
docker buildx build \
  --cache-from type=registry,ref=ghcr.io/tim/app:cache \
  --cache-to type=registry,ref=ghcr.io/tim/app:cache,mode=max \
  -t ghcr.io/tim/app:1.4.2 .
```

Mode `max` menyimpan lebih banyak metadata antar stage sehingga build di runner berbeda tetap bisa memakai cache.

<div class="note">💡 Invalidate cache terjadi saat isi yang disalin berubah. Salin file lock (`package-lock.json`, `go.sum`) lebih dulu, baru kode aplikasi—kunci yang umum ini berlaku juga di BuildKit.</div>
