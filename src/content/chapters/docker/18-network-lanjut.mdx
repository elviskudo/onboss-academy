Jaringan Docker bukan sekadar `-p`. Memilih driver yang tepat menentukan bagaimana container berbicara satu sama lain dan dengan dunia luar.

## Driver yang Sering Dipakai

| Driver | Kapan dipakai | Karakter |
|---|---|---|
| `bridge` | Default, satu host | Isolasi + NAT keluar |
| `host` | Butuh performa maksimal, Linux | Tanpa isolasi port |
| `none` | Proses offline | Hanya loopback |
| `overlay` | Swarm/Kubernetes multi-host | Jaringan lintas node |
| `macvlan` | Container butuh IP LAN sendiri | Terlihat seperti perangkat fisik |

## DNS Internal

```bash
docker network create appnet
docker run -d --name db --network appnet postgres:16-alpine
docker run --rm --network appnet alpine sh -c 'ping -c 2 db'
```

Pada bridge default, container hanya bisa memanggil lewat IP. Pada **user-defined bridge**, nama container menjadi hostname—ini alasan utama membuat jaringan sendiri.

## Inspeksi dan Koneksi Manual

```bash
docker network ls
docker network inspect appnet
docker network connect appnet web     # tambahkan container ke jaringan lain
docker network disconnect appnet web
```

Satu container boleh terhubung ke beberapa jaringan sekaligus—pola umum untuk memisahkan jaringan publik dan database.

## Port Publishing

```bash
docker run -p 8080:80 nginx              # semua antarmuka host
docker run -p 127.0.0.1:8080:80 nginx    # hanya localhost
docker run -P nginx                      # publish semua EXPOSE ke port acak
docker port <container>                  # lihat pemetaan aktif
```

## Mode Host: Kelebihan dan Risiko

Mode host menghilangkan lapisan NAT sehingga latency lebih rendah, tetapi container berbagi stack jaringan host. Dua proses tidak boleh memakai port yang sama. Mode ini hanya didukung penuh di Linux; di Docker Desktop perlu pengaturan khusus.

<div class="note">💡 Jangan mengandalkan nomor IP container—IP berubah saat container dibuat ulang. Selalu gunakan nama layanan pada jaringan user-defined.</div>
