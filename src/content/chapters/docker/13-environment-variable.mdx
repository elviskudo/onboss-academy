Variabel environment adalah cara standar memberi konfigurasi ke aplikasi dalam container tanpa mengubah kode. Bedanya dengan argumen command: env biasanya dipakai untuk pengaturan, bukan perilaku sekali jalan.

## ENV di Dockerfile

```dockerfile
FROM node:20-alpine
ENV NODE_ENV=production
ENV PORT=3000
EXPOSE 3000
CMD ["node", "server.js"]
```

`ENV KEY=value` mendukung bentuk `ENV KEY value` (lama), tetapi bentuk `=` lebih jelas. Nilai dengan spasi perlu dikutip.

## Menimpa Saat Runtime

```bash
docker run -d \
  -e NODE_ENV=staging \
  -e DATABASE_URL=postgres://db:5432/app \
  --env-file .env.production \
  -p 3000:3000 app:1.0
```

Prioritas: nilai `-e` menimpa nilai dari `--env-file`, yang pada gilirannya menimpa `ENV` di image.

## ARG untuk Build

```dockerfile
ARG VERSION=dev
RUN echo "Building $VERSION" > /app/version.txt
```

```bash
docker build --build-arg VERSION=1.4.2 -t app:1.4.2 .
```

Nilai ARG tidak otomatis bertahan di image final. Jika ingin keduanya, deklarasikan ARG lalu salin ke ENV:

```dockerfile
ARG VERSION=dev
ENV APP_VERSION=${VERSION}
```

## Melihat dan Menghindari Kebocoran

```bash
docker inspect app --format '{{range .Config.Env}}{{println .}}{{end}}'
docker exec app env | sort
```

Kedua perintah menampil nilai env, jangan sampai token produksi ikut tercetak di log CI. Untuk data sensitif, gunakan Docker secrets (Swarm), Kubernetes Secret, atau layanan seperti Vault.

<div class="note">💡 `ENV` dapat tertinggal pada metadata image. Jangan pakai untuk API key meski image-nya privat.</div>
