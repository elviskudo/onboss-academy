Registry adalah tempat menyimpan dan mendistribusikan image. Docker Hub adalah yang paling dikenal, tetapi tim sering memakai registry privat untuk kode internal.

## Alur Push

```bash
docker login registry.example.com
docker build -t app:1.0 .
docker tag app:1.0 registry.example.com/tim/app:1.0
docker push registry.example.com/tim/app:1.0
```

`docker push` mengunggah layer yang belum ada di registry. Layer yang sudah ter-common (misalnya base image) tidak dikirim ulang.

## Struktur Nama

```text
registry.example.com/tim/api:1.4.2
│                    │   │  │
│                    │   │  └── tag
│                    │   └───── repository
│                    └───────── namespace/organisasi
└────────────────────────────── host registry
```

Aturan sederhana: bagian sebelum `/` pertama mengandung `.` atau `:` ⇒ itu adalah host registry.

## Registry Lokal untuk Eksperimen

```bash
docker run -d -p 5000:5000 --name registry registry:2
docker tag alpine:3.20 localhost:5000/alpine:lokal
docker push localhost:5000/alpine:lokal
curl localhost:5000/v2/_catalog
```

Registry lokal biasanya HTTP biasa. Docker menolak HTTP untuk alamat selain localhost; untuk host lain perlu konfigurasi `insecure-registries`—dan itu berisiko di produksi.

## Autentikasi di CI

```bash
echo "$REGISTRY_TOKEN" | docker login ghcr.io -u "$USER" --password-stdin
```

Gunakan `--password-stdin` agar kata sandi tidak muncul di history shell atau log proses. Token sebaiknya berupa credential dengan masa berlaku terbatas, bukan kata sandi akun.

<div class="note">💡 Setelah push, verifikasi dengan menarik image di mesin lain. Tag yang sama bisa menunjuk ke digest berbeda bila pipeline menimpanya—simpan digest untuk rilis produksi.</div>
