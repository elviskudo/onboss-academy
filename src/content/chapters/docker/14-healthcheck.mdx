`docker ps` hanya memberi tahu apakah proses utama masih hidup. Proses bisa hidup tetapi tidak lagi melayani request—di sinilah **healthcheck** dibutuhkan.

## Sintaks Dasar

```dockerfile
HEALTHCHECK --interval=30s --timeout=3s --start-period=10s --retries=3 \
  CMD curl -fsS http://localhost:8080/health || exit 1
```

| Opsi | Fungsi | Default |
|---|---|---|
| `--interval` | Jeda antar pemeriksaan | 30s |
| `--timeout` | Batas waktu satu pemeriksaan | 30s |
| `--start-period` | Masa tunggu aplikasi starting | 0s |
| `--retries` | Gagal berturut sebelum unhealthy | 3 |

## Endpoint Khusus

Buat endpoint `/health` yang ringan: tidak boleh mengakses database berat atau memicu pekerjaan mahal. Cukup jawab `200 OK` bila proses siap menerima traffic.

```bash
docker ps --format 'table {{.Names}}\t{{.Status}}'
# up 2 minutes (healthy)
docker inspect --format '{{json .State.Health}}' app
```

## Tanpa curl di Image

Image `scratch` atau `alpine` minimal sering tidak punya `curl`. Gunakan alat yang sudah ada:

```dockerfile
# Node.js
HEALTHCHECK CMD node -e "fetch('http://localhost:3000/health').then(r=>process.exit(r.ok?0:1)).catch(()=>process.exit(1))"

# Python
HEALTHCHECK CMD python -c "import urllib.request; urllib.request.urlopen('http://localhost:8000/health')"
```

## Healthcheck saat docker run

```bash
docker run -d --name api \
  --health-cmd "curl -fsS http://localhost:8080/health || exit 1" \
  --health-interval 15s \
  --health-timeout 2s \
  --health-retries 2 \
  app:1.0
```

Perintah CLI menimpa healthcheck bawaan image. Orkestrator seperti Swarm dan Kubernetes bisa memakai hasil ini untuk mengganti container yang tidak sehat.

<div class="note">💡 `start-period` mencegah container baru dinyatakan unhealthy saat aplikasi masih melakukan inisialisasi—misalnya migrasi database yang memakan waktu.</div>
