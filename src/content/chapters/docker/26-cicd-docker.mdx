Pipeline yang baik mengubah commit menjadi image yang bisa dilacak, diuji, dan dipulihkan. Docker memberi unit pengiriman yang konsisten dari laptop sampai produksi.

## Tahapan Pipeline

```text
commit → build (test stage) → test → build final → scan → push → deploy → smoke test
```

## Contoh GitHub Actions

```yaml
name: ci
on: [push]
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: docker/setup-buildx-action@v3
      - name: Test
        run: |
          docker build --target test -t app:test .
          docker run --rm app:test npm test
      - name: Build & push
        run: |
          echo "${{ secrets.GITHUB_TOKEN }}" |
            docker login ghcr.io -u "${{ github.actor }}" --password-stdin
          docker build \
            --cache-from type=registry,ref=ghcr.io/tim/app:cache \
            --cache-to type=registry,ref=ghcr.io/tim/app:cache,mode=max \
            -t ghcr.io/tim/app:${{ github.sha }} .
          docker push ghcr.io/tim/app:${{ github.sha }}
```

## Tag yang Dihasilkan

| Tag | Tujuan |
|---|---|
| `sha-<commit>` | Traceability, dipakai produksi |
| `1.4.2` | Rilis resmi |
| `staging` | Menunjuk build terakhir yang lolos staging |
| `latest` | Kenyamanan lokal, bukan jaminan produksi |

## Deploy dan Verifikasi

```bash
docker pull ghcr.io/tim/app:${GIT_SHA}
docker run -d --name app-baru \
  --health-cmd "curl -fsS localhost:8080/health || exit 1" \
  -p 8081:80 ghcr.io/tim/app:${GIT_SHA}

# smoke test
curl -fsS http://localhost:8081/health
```

Jika gagal, hentikan `app-baru` dan biarkan versi lama tetap melayani traffic.

<div class="note">💡 Jangan simpan kredensial registry di file compose atau Dockerfile. Gunakan secrets CI dan beri hak tulis hanya pada repository yang diperlukan.</div>
