Docker menyediakan **container**; Kubernetes mengatur kapan dan di mana container itu berjalan, berapa banyak salinan, serta bagaimana traffic dibagikan.", 

## Peta Konsep

| Objek | Peran | Analogi Docker |
|---|---|---|
| Pod | Tempat container berjalan | Container + jaringan bersama |
| Deployment | Menjaga replika & update | `docker compose up --scale` + rollback |
| Service | Alamat stabil | DNS internal + load balancer |
| ConfigMap | Konfigurasi teks | `--env-file` |
| Secret | Konfigurasi sensitif | `--env-file` terenkripsi |
| Ingress | Routing HTTP dari luar | Reverse proxy |

## Manifest Minimal

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web
spec:
  replicas: 2
  selector:
    matchLabels:
      app: web
  template:
    metadata:
      labels:
        app: web
    spec:
      containers:
      - name: web
        image: nginx:alpine
        ports:
        - containerPort: 80
```

```bash
kubectl apply -f deployment.yaml
kubectl get pods
kubectl rollout status deployment/web
kubectl rollout undo deployment/web
```

## Probe = Healthcheck

```yaml
livenessProbe:
  httpGet:
    path: /health
    port: 8080
  initialDelaySeconds: 10
readinessProbe:
  httpGet:
    path: /ready
    port: 8080
```

- **Liveness** — jika gagal, Pod direstart.
- **Readiness** — jika gagal, Pod tidak menerima traffic.

Keduanya memakai endpoint yang sama dengan `HEALTHCHECK` di Dockerfile, jadi logikanya bisa dipakai ulang.

## Kapan Compose, Kapan Kubernetes

Compose cocok untuk satu host dan pengembangan lokal. Kubernetes dipakai ketika dibutuhkan multi-node, auto-scaling, self-healing, dan rollout terkendali. Kompleksitasnya jauh lebih tinggi, jadi jangan pindah hanya karena "trend".

<div class="note">💡 Kubernetes tidak membangun image. CI tetap bertugas membangun dan mendorong image ke registry; cluster hanya menarik dan menjalankannya.</div>
