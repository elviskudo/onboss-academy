Build produksi bukan sekadar "ng build". Ada beberapa pengaturan yang membuat aplikasi lebih cepat dan aman.

## Konfigurasi Budget

```json
"budgets": [
  { "type": "initial", "maximumWarning": "500kB", "maximumError": "1MB" },
  { "type": "anyComponentStyle", "maximumWarning": "4kB" }
]
```

CLI akan memberi peringatan atau gagal bila batas terlampaui.

## Opsi Build

```json
"production": {
  "optimization": true,
  "outputHashing": "all",
  "sourceMap": false,
  "namedChunks": false,
  "extractLicenses": true,
  "budgets": [...]
}
```

`outputHashing` membuat nama file berubah konten — browser bisa cache agresif.

## Analisis Bundle

```bash
ng build --stats-json
npx source-map-explorer dist/app/browser/main*.js
```

Perhatikan pustaka besar yang hanya dipakai sekali.mungkin bisa diganti dengan import langsung atau lazy load.

## Pemeriksaan Sebelum Deploy

- [ ] `ng build` sukses tanpa error.
- [ ] Tidak ada secret di dalam bundle.
- [ ] Lazy route sudah dipakai untuk fitur berat.
- [ ] Error boundary / fallback tersedia.

<div class="note">💡 Optimasi terbaik biasanya bukan micro-tuning, tapi mengurangi apa yang dikirim. Hapus dependensi yang tidak terpakai sebelum memikirkan minifikasi.</div>
