State management bukan soal memilih library paling populer, tapi memilih kompleksitas yang sepadan dengan masalah.

## Tingkatan Kebutuhan

| Kebutuhan | Pilihan |
|-----------|---------|
| Satu komponen | `signal()` lokal |
| Beberapa komponen satu fitur | service + signal |
| Seluruh aplikasi, alur kompleks | NgRx / store serupa |

## Store Sederhana

```typescript
import { Injectable, signal, computed } from "@angular/core";

@Injectable({ providedIn: "root" })
export class KeranjangStore {
  private _items = signal<Produk[]>([]);
  readonly items = this._items.asReadonly();
  readonly jumlah = computed(() => this._items().length);
  readonly total = computed(() =>
    this._items().reduce((s, p) => s + p.harga, 0)
  );

  tambah(p: Produk) {
    this._items.update((lama) => [...lama, p]);
  }

  hapus(id: number) {
    this._items.update((lama) => lama.filter((p) => p.id !== id));
  }

  kosongkan() { this._items.set([]); }
}
```

`asReadonly()` mencegah komponen mengubah state dari luar.

## Pemakaian

```typescript
export class RingkasanComponent {
  private store = inject(KeranjangStore);
  total = this.store.total;
  jumlah = this.store.jumlah;
}
```

```html
<p>{{ jumlah() }} item — Rp{{ total() }}</p>
```

## Kapan NgRx

Pertimbangkan NgRx bila ada banyak aksi yang saling memengaruhi, perlu time-travel debugging, atau beberapa tim mengerjakan modul berbeda dengan kontrak state yang jelas.

<div class="note">💡 Mulai dari yang paling sederhana. Service + signal sudah cukup untuk sebagian besar aplikasi; kamu selalu bisa bermigrasi ke store yang lebih berat nanti.</div>
