Menulis class itu satu hal; mengelola proyek yang bisa di-build, di-test, dan di-deploy adalah hal lain. Java punya ekosistem build tooling yang matang.

## Struktur Standar

```
proyek/
├── pom.xml                       (Maven)
├── src/
│   ├── main/
│   │   ├── java/com/contoh/app/  ← kode produksi
│   │   └── resources/            ← konfigurasi, properties
│   └── test/
│       ├── java/                 ← JUnit test
│       └── resources/
└── target/                       ← hasil build (jangan di-commit)
```

## Maven vs Gradle

| Aspek | Maven | Gradle |
|---|---|---|
| File | `pom.xml` (XML) | `build.gradle` (Groovy/Kotlin) |
| Konvensi | kuat | fleksibel |
| Performa | lebih lambat | inkremental & cache |
| Cocok untuk | proyek standar enterprise | proyek besar/Android |

## Perintah Umum

```bash
mvn compile          # kompilasi
mvn test             # jalankan test
mvn package          # hasilkan .jar
mvn spring-boot:run  # jalankan aplikasi Spring

gradle build
gradle test
gradle run
```

## Module (JPMS)

```java
// module-info.java
module com.contoh.app {
    requires java.sql;
    exports com.contoh.app.api;
}
```

Modul membantu menyembunyikan paket internal dan mempercepat startup.

## Praktik Sehat

1. Satu class = satu tanggung jawab.
2. Pakai dependency injection, bukan `new` di mana-mana.
3. Simpan konfigurasi di `application.properties`, bukan hardcode.
4. Pisahkan layer: controller → service → repository.
5. Tambahkan CI yang menjalankan `mvn test` setiap push.

<div class="note">💡 Untuk proyek baru, **Gradle with Kotlin DSL** atau **Maven** keduanya pilihan aman. Ikuti konvensi tim — konsistensi lebih penting daripada preferensi pribadi.</div>
