Java sejak awal mendukung multithreading. Kotlin/Go mungkin punya model lebih baru, tapi API ini tetap fondasi banyak aplikasi enterprise.

## Membuat Thread

```java
Thread t = new Thread(() -> System.out.println("Jalan di thread lain"));
t.start();   // jangan panggil run() langsung!
```

Atau:

```java
class Kerja implements Runnable {
    public void run() { ... }
}
new Thread(new Kerja()).start();
```

## Sinkronisasi

```java
class Counter {
    private int nilai = 0;

    public synchronized void tambah() { nilai++; }
    public synchronized int get() { return nilai; }
}
```

Alternatif lebih modern:

```java
private final AtomicInteger nilai = new AtomicInteger();
nilai.incrementAndGet();
```

## ExecutorService

```java
ExecutorService pool = Executors.newFixedThreadPool(4);
Future<Integer> f = pool.submit(() -> hitungBerat());
Integer hasil = f.get();     // blok sampai selesai
pool.shutdown();             // WAJIB, kalau tidak program tidak keluar
```

| Factory | Cocok untuk |
|---|---|
| `newFixedThreadPool(n)` | beban stabil |
| `newCachedThreadPool()` | tugas pendek berfluktuasi |
| `newSingleThreadExecutor()` | urutan harus terjaga |
| `newScheduledThreadPool(n)` | tugas berulang / delay |

## volatile

```java
private volatile boolean jalan = true;
```

`volatile` menjamin visibilitas perubahan antar thread, tapi **tidak** menjamin atomisitas untuk operasi majemuk seperti `i++`.

<div class="note">💡 Gunakan <code>ExecutorService</code>, bukan <code>new Thread()</code> di dalam loop. Pool mengontrol jumlah thread sehingga aplikasi tidak kehabisan resource saat traffic naik.</div>
