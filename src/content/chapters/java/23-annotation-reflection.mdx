Annotation adalah metadata yang melekat pada class, method, atau field. Reflection adalah kemampuan program memeriksa strukturnya sendiri saat runtime.

## Annotation Bawaan

```java
@Override          // cek override
@Deprecated        // tandai usang
@SuppressWarnings   // redam warning
@FunctionalInterface // pastikan 1 method abstrak
```

## Membuat Annotation

```java
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface Rute {
    String path();
    String method() default "GET";
}
```

- `RetentionPolicy.SOURCE` → dibuang setelah compile
- `RetentionPolicy.CLASS` → ada di .class, tidak terbaca runtime
- `RetentionPolicy.RUNTIME` → bisa dibaca lewat reflection

## Reflection Dasar

```java
Class<?> c = Siswa.class;
Field[] fields = c.getDeclaredFields();
Method[] methods = c.getDeclaredMethods();
Constructor<?> ctor = c.getDeclaredConstructor(String.class);
Object obj = ctor.newInstance("Sari");
```

Untuk mengakses private, gunakan `setAccessible(true)` — tapi pikirkan dua kali, karena ini merusak encapsulation.

## Membaca Annotation

```java
for (Method m : Controller.class.getMethods()) {
    Rute r = m.getAnnotation(Rute.class);
    if (r != null) {
        daftarRute.put(r.path(), m);
    }
}
```

Ini adalah dasar cara kerja framework seperti Spring MVC dan JUnit.

## Risiko

| Masalah | Penjelasan |
|---|---|
| Performa | Reflection lebih lambat dari panggilan langsung |
| Type safety | Error baru muncul saat runtime |
| Refactor | IDE sulit mendeteksi ketergantungan string |

<div class="note">💡 Reflection sangat berguna untuk membangun framework, tapi hindari dalam logika bisnis aplikasi. Kalau bisa dipanggil langsung, panggil langsung.</div>
