Java membedakan dua dunia exception: checked dan unchecked. Memahami perbedaannya menentukan API yang nyaman dipakai.

## Hierarki

```
Throwable
├── Error              → JVM bermasalah (OutOfMemoryError)
└── Exception
    ├── RuntimeException  → unchecked (NPE, IAE, IndexOutOfBounds)
    └── IOException, SQLException, ClassNotFoundException → checked
```

## Checked vs Unchecked

```java
// checked → wajib
public void baca() throws IOException {
    Files.readString(Path.of("data.txt"));
}

// unchecked → opsional
public void bagi(int a, int b) {
    if (b == 0) throw new IllegalArgumentException("b nol");
}
```

Gunakan checked untuk kondisi yang **bisa dipulihkan** oleh caller (file tidak ada, koneksi putus). Unchecked untuk bug programmer atau precondition yang dilanggar.

## try-with-resources

```java
try (BufferedReader br = Files.newBufferedReader(Path.of("data.txt"))) {
    return br.readLine();
} catch (IOException e) {
    throw new UncheckedIOException(e);
}
```

Lebih aman dan pendek daripada `finally { br.close(); }`.

## Custom Exception & Chaining

```java
class GagalBayar extends Exception {
    GagalBayar(String pesan, Throwable sebab) {
        super(pesan, sebab);   // cause menjaga stack trace asli
    }
}
```

## Exception di Lambda/Stream

Checked exception tidak bisa dilempar langsung dari lambda `Function`. Bungkus dengan `RuntimeException` atau buat wrapper functional interface yang menyatakan `throws`.

<div class="note">💡 Jangan menangkap `Exception` lalu hanya mencetaknya tanpa melakukan apa pun. Either tangani (retry, fallback, notifikasi) atau lempar ulang dengan konteks yang lebih jelas.</div>
