Null dan exception adalah dua sumber bug paling umum. C# modern menyediakan alat untuk keduanya: *nullable reference types* dan blok `try` yang rapi.

## Nullable Reference Types

Sejak C# 8, aktifkan dengan `<Nullable>enable</Nullable>` di file proyek. Tipe biasa seperti `string` dianggap **tidak boleh null**; tulis `string?` jika boleh.

```csharp
string Pasti = "Halo";    // harus diisi
string? BolehKosong = null; // boleh null

Console.WriteLine(BolehKosong?.Length ?? 0);
```

- `?.` — null-conditional: akses anggota hanya jika tidak null
- `??` — null-coalescing: pakai nilai kanan jika kiri null
- `??=` — tetapkan nilai jika masih null
- `!` — null-forgiving: beri tahu kompiler "saya yakin ini tidak null"

```csharp
string? input = null;
input ??= "default"; // sekarang "default"
```

## Exception

```csharp
try
{
    int angka = int.Parse("abc"); // melempar FormatException
}
catch (FormatException e)
{
    Console.WriteLine("Format salah: " + e.Message);
}
catch (Exception e)
{
    Console.WriteLine("Error umum: " + e.Message);
}
finally
{
    Console.WriteLine("Selalu dijalankan");
}
```

Tangkap yang paling spesifik dahulu. Blok `finally` tetap berjalan walau `return` dipanggil di dalam `try`.

## Membuat Exception Sendiri

```csharp
public class SaldoKurangException : Exception
{
    public SaldoKurangException(string pesan) : base(pesan) { }
}

void Tarik(decimal jumlah)
{
    if (jumlah > Saldo)
        throw new SaldoKurangException("Saldo tidak cukup");
}
```

## using Declaration

Untuk resource yang harus ditutup, `using` menggantikan `finally`:

```csharp
using var reader = new StreamReader("data.txt");
string isi = reader.ReadToEnd();
// file otomatis ditutup di akhir scope
```

<div class="note">💡 Jangan pakai exception untuk alur bisnis normal. ITU mahal dan kode jadi sulit diikuti. Untukinput yang mungkin salah, <code>TryParse</code> lebih tepat daripada <code>Parse</code> + catch.</div>
