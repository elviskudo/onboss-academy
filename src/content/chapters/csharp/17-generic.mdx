Generic memungkinkan kamu menulis satu definisi yang bekerja untuk banyak tipe, tanpa mengorbankan keamanan tipe. `List<int>` dan `Dictionary<string, int>` adalah contoh yang sudah kamu pakai sebelumnya.

## Class Generic

```csharp
class Kotak<T>
{
    private T isi;
    public Kotak(T isi) => this.isi = isi;
    public T Ambil() => isi;
}

var angka = new Kotak<int>(42);
var teks = new Kotak<string>("Halo");
```

Kompiler membuat kode spesifik untuk tiap tipe yang dipakai, jadi tidak ada boxing dan tidak perlu cast.

## Method Generic

```csharp
static T ElemenPertama<T>(T[] data) => data[0];

int a = ElemenPertama(new[] { 1, 2, 3 });
string b = ElemenPertama(new[] { "x", "y" });
```

Tipe disimpulkan dari argumen, jadi kamu jarang perlu menulis `<int>` secara eksplisit.

## Constraint

Batasi tipe yang boleh dipakai dengan `where`:

| Constraint | Arti |
|---|---|
| `where T : class` | Harus reference type |
| `where T : struct` | Harus value type |
| `where T : new()` | Harus punya konstruktor tanpa argumen |
| `where T : IDisposable` | Harus mengimplementasikan antarmuka |
| `where T : BaseClass` | Harus turunan dari kelas tertentu |

```csharp
static T Buat<T>() where T : new() => new T();
```

## Interface Generic & Covariance

```csharp
interface IRepositori<T>
{
    void Simpan(T item);
    T Ambil(int id);
}

IEnumerable<string> teks = new List<string>();
IEnumerable<object> objek = teks; // covariance: aman untuk hanya-baca
```

`IEnumerable<out T>` bersifat kovarian; `IComparer<in T>` bersifat kontravarian. Keduanya menjaga arah aliran data tetap aman.

<div class="note">💡 Kalau method hanya membaca dari parameter, gunakan <code>IEnumerable&lt;T&gt;</code>, bukan <code>List&lt;T&gt;</code>. Method jadi bisa menerima array, List, atau hasil LINQ tanpa diubah.</div>
