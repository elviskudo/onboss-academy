MySQL bisa menjalankan pekerjaan terjadwal tanpa cron eksternal lewat Event Scheduler. Selain itu, ada perintah perawatan untuk menjaga statistik dan struktur tabel tetap sehat.

## Event Scheduler

```sql
SET GLOBAL event_scheduler = ON;

CREATE EVENT bersih_log
ON SCHEDULE EVERY 1 DAY
STARTS CURRENT_DATE + INTERVAL 1 DAY
DO
  DELETE FROM log WHERE dibuat < DATE_SUB(NOW(), INTERVAL 30 DAY);

SHOW EVENTS;
DROP EVENT IF EXISTS bersih_log;
```

## Interval yang Umum

```sql
ON SCHEDULE EVERY 1 HOUR
ON SCHEDULE EVERY 6 HOUR STARTS '2026-12-01 00:00:00'
ON SCHEDULE EVERY 1 WEEK
```

Event berjalan di dalam server, jadi perlu akun dengan hak yang tepat dan pengawasan. Jika gagal, periksa error log.

## Perintah Perawatan

| Perintah | Fungsi |
| --- | --- |
| `ANALYZE TABLE` | perbarui statistik optimizer |
| `OPTIMIZE TABLE` | susun ulang tabel/index |
| `CHECK TABLE` | cek kerusakan |
| `REPAIR TABLE` | perbaiki MyISAM (tidak untuk InnoDB) |

```sql
ANALYZE TABLE karyawan;
OPTIMIZE TABLE log;
CHECK TABLE karyawan;
```

## Statistik Optimizer

Optimizer memilih index berdasarkan statistik. Setelah import data besar atau perubahan masif, statistik bisa basi:

```sql
ANALYZE TABLE penjualan;
EXPLAIN SELECT * FROM penjualan WHERE tanggal >= '2026-01-01';
```

## Pembersihan Data

```sql
DELETE FROM log WHERE dibuat < DATE_SUB(NOW(), INTERVAL 90 DAY);
```

Untuk tabel sangat besar, partisi per bulan dan `DROP PARTITION` biasanya jauh lebih cepat daripada DELETE massal.

<div class="note">💡 Event Scheduler berjalan di server database. Jika kamu sudah punya cron di aplikasi, pertimbangkan mana yang lebih mudah dipantau dan di-audit di timmu.</div>

## Di Dunia Nyata

- **Retention**: hapus log lebih lama dari 30 hari tiap malam.
- **Ringkasan**: isi tabel agregat setiap jam.
- **Statistik**: ANALYZE setelah batch import harian.
- **Kesehatan**: monitoring CHECK TABLE pada sistem dengan I/O tidak stabil.
