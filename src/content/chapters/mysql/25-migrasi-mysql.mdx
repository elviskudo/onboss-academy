Perubahan skema di database produksi perlu prosedur. ALTER TABLE pada tabel besar bisa memblokir write atau menyalin jutaan baris.

## Pola Expand–Migrate–Contract

```text
1. Expand   : tambah kolom/tabel baru, biarkan yang lama ada
2. Migrate  : aplikasi baru menulis ke dua tempat, data lama disalin
3. Contract: setelah semua terbaru, hapus kolom lama
```

Pola ini memungkinkan deploy bertahap tanpa downtime.

## ALTER yang Lebih Aman

```sql
ALTER TABLE produk
  ADD COLUMN harga_baru DECIMAL(12,2) NULL,
  ALGORITHM=INPLACE, LOCK=NONE;
```

Jika kombinasi tidak didukung, MySQL akan mengeluarkan error — lebih baik gagal saat deploy daripada mem-blokir produksi.

## Versioning

```text
migrations/
  001_create_produk.sql
  002_add_harga_baru.sql
  003_backfill_harga.sql
```

Setiap file berisi `up` dan ideally `down`. Simpan di repositori, jalankan dengan tool migrasi (Flyway, Liquibase, atau script internal).

## Backfill Bertahap

```sql
UPDATE produk SET harga_baru = harga
WHERE harga_baru IS NULL LIMIT 1000;
```

Ulangi sampai tidak ada baris tersisa. Batch kecil menghindari transaksi panjang dan replikasi lag.

## Uji Migrasi

1. Jalankan pada salinan produksi dengan volume data serupa.
2. Ukur durasi dan dampak lock.
3. Uji aplikasi lama dan baru secara bersamaan.
4. Uji rollback.

<div class="note">💡 Hindari mengganti nama kolom dan mengubah tipe secara sekaligus. Pecah menjadi langkah kecil agar setiap tahap bisa dibatalkan.</div>

## Di Dunia Nyata

- **Rename kolom**: tambah kolom baru, salin, lalu hapus yang lama.
- **Pemisahan tabel**: salin data ke tabel baru sebelum mengarahkan aplikasi.
- **Penambahan index**: gunakan ALGORITHM=INPLACE bila tersedia.
- **Rollback**: simpan skrip kebalikan di file yang sama.
