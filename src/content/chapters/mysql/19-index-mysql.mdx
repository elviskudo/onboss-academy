Index mempercepat pencarian dengan menyimpan struktur tambahan yang memetakan nilai ke baris. Di MySQL/InnoDB, index utama adalah B-Tree.

## Membuat Index

```sql
CREATE INDEX idx_produk_kategori ON produk(kategori);
CREATE UNIQUE INDEX idx_produk_sku ON produk(sku);
ALTER TABLE produk ADD INDEX idx_harga (harga);
SHOW INDEX FROM produk;
DROP INDEX idx_harga ON produk;
```

## Index Komposit

```sql
CREATE INDEX idx_pesanan_user_tanggal ON pesanan(user_id, tanggal);
```

Index ini membantu:

- `WHERE user_id = 5`
- `WHERE user_id = 5 AND tanggal >= '2026-01-01'`
- `ORDER BY tanggal` dalam partisi user_id tertentu

Tidak membantu: `WHERE tanggal = '...'` saja.

## FULLTEXT

```sql
CREATE FULLTEXT INDEX ft_artikel ON artikel(judul, isi);
SELECT * FROM artikel
WHERE MATCH(judul, isi) AGAINST('database mysql' IN NATURAL LANGUAGE MODE);
```

FULLTEXT mengerti kata dan relevansi, jauh lebih baik daripada `LIKE '%kata%'` pada teks panjang.

## Membaca EXPLAIN

| Kolom | Arti penting |
| --- | --- |
| `type` | ALL = full scan; ref/range/const = index dipakai |
| `key` | index yang dipilih |
| `rows` | perkiraan baris dibaca |
| `Extra` | Using index, Using temporary, Using filesort |

```sql
EXPLAIN SELECT nama FROM karyawan WHERE dept = 'Engineering';
```

## Kapan Index Tidak Dipakai

- Fungsi pada kolom: `WHERE YEAR(tanggal)=2026`
- Wildcard di awal: `LIKE '%kopi'`
- Perbandingan tipe berbeda: kolom INT dibanding string
- Tabel sangat kecil — optimizer memilih scan saja

<div class="note">💡 Primary key di InnoDB adalah clustered index: baris data disimpan bersama kunci. Index sekunder menyimpan nilai primary key sebagai penunjuk, jadi primary key yang pendek menghemat ruang.</div>

## Di Dunia Nyata

- **Login**: index UNIQUE pada email.
- **Feed**: `(user_id, created_at)` untuk mengambil posting terbaru.
- **Katalog**: index kategori + harga untuk filter.
- **Pencarian artikel**: FULLTEXT pada judul dan isi.
