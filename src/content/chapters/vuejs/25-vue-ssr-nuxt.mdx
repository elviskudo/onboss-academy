Aplikasi Vue pada umumnya dirender di browser (CSR). SSR merender HTML di server terlebih dahulu, lalu Vue "menghidupkannya" di browser.

## Kapan SSR

| Kebutuhan | Pilihan |
|-----------|---------|
| Dashboard internal | CSR biasa sudah cukup |
| Situs publik/SEO | SSR / SSG |
| Blog dan dokumentasi | SSG |

## Nuxt

```bash
npx nuxi@latest init proyek
```

Struktur:

```
pages/
  index.vue
  produk/[id].vue
components/
composables/
server/api/
```

Rute dibuat otomatis dari nama file — mirip App Router di Next.js.

## Data Fetching

```vue
<script setup>
const { data: produk, pending, error } = await useFetch('/api/produk')
</script>

<template>
  <p v-if="pending">Memuat…</p>
  <ul v-else>
    <li v-for="p in produk" :key="p.id">{{ p.nama }}</li>
  </ul>
</template>
```

## Hydration

Setelah HTML sampai, Vue memasang event listener dan state. Pastikan markup server dan client sama — beda kecil bisa memicu peringatan *hydration mismatch*.

<div class="note">💡 CSR tidak salah. Pilih SSR bila SEO dan waktu muat awal benar-benar penting; kalau tidak, aplikasi SPA lebih sederhana.</div>
