Composition API adalah gaya standar Vue 3: logika ditulis dalam `script setup`, dikelompokkan berdasarkan **kegunaan**, bukan berdasarkan jenis opsi.

## 5 Bagian Composition API

| Bagian | API | Fungsi | Kapan dipakai |
|--------|-----|--------|---------------|
| State tunggal | `ref` | Nilai reaktif yang bisa diganti | string, angka, boolean, array |
| State object | `reactive` | Proxy object/array | Form atau object stabil |
| Nilai turunan | `computed` | Getter reaktif ber-cache | Total, filter, status |
| Lifecycle | `onMounted`, `onUnmounted` | Setup/cleanup efek | Fetch, listener, timer |
| Reuse logika | composable `useX()` | Gabungkan state + function | Fitur dipakai lintas komponen |

Tidak ada class component yang perlu diwarisi. Function composable dan closure menggantikan mixin/class untuk memakai ulang perilaku.

## ref dan reactive

```html
<script setup>
import { ref, reactive } from "vue";

const jumlah = ref(0);              // primitif — .value
const user = reactive({             // object — langsung
  nama: "Sari",
  umur: 20,
});

function tambah() { jumlah.value++; }
function ulangTahun() { user.umur++; }
</script>

<template>
  <button @click="tambah">{{ jumlah }}</button>
  <p>{{ user.nama }} {{ user.umur }}</p>
</template>
```

Di dalam `<script setup>`, `jumlah` sudah berbentuk ref — di template cukup tulis `{{ jumlah }}`.

## Lifecycle Hooks

```html
<script setup>
import { onMounted, onUnmounted } from "vue";

onMounted(() => {
  console.log("Komponen siap — tempat fetch data awal");
});

onUnmounted(() => {
  console.log("Bersihkan listener/timer di sini");
});
</script>
```

Urutan penting: `setup` → `onBeforeMount` → `onMounted` → (`onUpdated`) → `onUnmounted`.

## Composable (Kode Pakai Ulang)

```javascript
// useCounter.js
import { ref } from "vue";

export function useCounter(start = 0) {
  const jumlah = ref(start);
  const tambah = () => jumlah.value++;
  const kurang = () => jumlah.value--;
  return { jumlah, tambah, kurang };
}
```

```html
<script setup>
import { useCounter } from "./useCounter";
const { jumlah, tambah } = useCounter(10);
</script>
```

Composable adalah fungsi JS biasa yang mengembalikan ref/function — tidak perlu class atau mixin.

## Pola JavaScript-nya (Closure)

```javascript
function useCounter(start = 0) {
  let jumlah = start; // "state privat" lewat closure
  return {
    jumlah: () => jumlah,
    tambah: () => ++jumlah,
  };
}

const c = useCounter(5);
c.tambah();
console.log(c.jumlah()); // 6
```

Inilah inti closure yang membuat composable bisa menyimpan state tanpa global variable. Array/object dalam composable tetap diproses dengan function seperti `filter` dan `map`; template merender hasilnya lewat `v-for` dan memilih tampilan lewat `v-if`.

## Options API vs Composition API

Options API (`data`, `methods`, `computed`) tetap valid dan nyaman untuk komponen kecil. Composition API unggul saat satu fitur punya state, computed, lifecycle, dan handler yang perlu diletakkan berdekatan atau dipindah ke composable. Jangan migrasi kode Options API hanya demi gaya jika tidak ada masalah nyata.

## Di Dunia Nyata

- **`useFetch`**: menggabungkan `data`, `loading`, `error`, dan request/abort logic.
- **`useAuth`**: state user, function login/logout, dan computed status autentikasi.
- **`useCart`**: array item, handler tambah/hapus, serta computed total dan jumlah.
- **`useWindowSize`**: listener resize dipasang saat mount dan dibersihkan saat unmount.
- **`useTodo`**: list reaktif, function toggle/filter, dan sisa tugas untuk beberapa halaman.

<div class="note">💡 `ref` untuk primitif (string, angka, boolean); `reactive` untuk object/array yang tidak perlu diganti total. Keduanya bisa berdampingan — yang penting konsisten di satu komponen.</div>
