Transaksi menjamin bahwa sekelompok perubahan diperlakukan sebagai satu unit. PostgreSQL memakai MVCC, sehingga pembaca umumnya tidak memblokir penulis.

## Alur Dasar

```sql
BEGIN;
UPDATE rekening SET saldo = saldo - 50000 WHERE id = 1;
UPDATE rekening SET saldo = saldo + 50000 WHERE id = 2;
COMMIT;
```

Gagal di tengah? `ROLLBACK;`. Perintah DDL juga bisa ikut transaksi di PostgreSQL — beda dengan MySQL.

## Savepoint

```sql
BEGIN;
INSERT INTO log VALUES ('awal');
SAVEPOINT titik;
INSERT INTO log VALUES ('opsi');
ROLLBACK TO SAVEPOINT titik;
COMMIT;
```

## Level Isolasi

```sql
SET TRANSACTION ISOLATION LEVEL REPEATABLE READ;
BEGIN ISOLATION LEVEL SERIALIZABLE;
```

| Level | Hilangkan |
| --- | --- |
| READ COMMITTED | dirty read (default) |
| REPEATABLE READ | dirty + non-repeatable read |
| SERIALIZABLE | juga phantom read/anomali serialization

## Locking Eksplisit

```sql
SELECT * FROM produk WHERE id = 1 FOR UPDATE;
SELECT * FROM produk WHERE id = 1 FOR SHARE;
SELECT * FROM produk FOR UPDATE SKIP LOCKED;
```

`SKIP LOCKED` berguna untuk antrean pekerjaan: beberapa worker mengambil baris berbeda tanpa saling menunggu.

## Deadlock

PostgreSQL mendeteksi deadlock dan membatalkan salah satu transaksi. Aplikasi harus siap retry error 40P01. Kurangi risiko dengan urutan akses tabel yang konsisten dan transaksi pendek.

<div class="note">💡 Transaction yang terbuka lama membuat autovacuum tidak bisa membersihkan baris mati yang masih terlihat oleh transaksi itu. Tutup transaksi secepatnya.</div>

## Di Dunia Nyata

- **Transfer saldo**: dua UPDATE satu transaksi.
- **Antrean job**: FOR UPDATE SKIP LOCKED.
- **Migration**: DDL + DML bisa digabung.
- **Laporan konsisten**: REPEATABLE READ memberi snapshot yang sama.
