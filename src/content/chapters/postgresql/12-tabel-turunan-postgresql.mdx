PostgreSQL memberi banyak cara menyusun query bertingkat. Memilih bentuk yang tepat membuat logika mudah dibaca dan memberi kontrol pada optimizer.

## Subquery Skalar

```sql
SELECT nama, gaji
FROM karyawan
WHERE gaji > (SELECT AVG(gaji) FROM karyawan);
```

Subquery skalar harus menghasilkan satu baris satu kolom.

## Derived Table

```sql
SELECT r.dept, r.jumlah
FROM (
  SELECT dept, COUNT(*) AS jumlah FROM karyawan GROUP BY dept
) AS r
WHERE r.jumlah >= 2;
```

Alias wajib. Ini setara dengan CTE non-rekursif, tetapi CTE biasanya lebih enak dibaca.

## LATERAL

```sql
SELECT d.nama AS dept, p.nama AS karyawan_teratas
FROM departemen d
CROSS JOIN LATERAL (
  SELECT nama FROM karyawan k
  WHERE k.dept = d.id
  ORDER BY k.gaji DESC
  LIMIT 1
) p;
```

Tanpa `LATERAL`, subquery di FROM tidak bisa melihat `d.id`. Pola ini sangat berguna untuk "top N per grup".

## CTE

```sql
WITH rata_dept AS (
  SELECT dept, AVG(gaji) AS rata FROM karyawan GROUP BY dept
)
SELECT k.nama, k.gaji, rata_dept.rata
FROM karyawan k JOIN rata_dept ON k.dept = rata_dept.dept
WHERE k.gaji > rata_dept.rata;
```

Beberapa CTE dipisah koma dan CTE berikutnya boleh merujuk yang sebelumnya.

## MATERIALIZED vs NOT MATERIALIZED

```sql
WITH cepat AS MATERIALIZED (
  SELECT * FROM tabel_besar WHERE ...
)
SELECT * FROM cepat WHERE ... UNION ALL SELECT * FROM cepat WHERE ...;
```

`MATERIALIZED` memo hasil CTE bila dipakai berkali-kali. `NOT MATERIALIZED` mengizinkan optimizer meng-inline agar filter bisa didorong ke dalam.

<div class="note">💡 Sejak PostgreSQL 12, CTE yang hanya dipakai sekali otomatis di-inline bila aman. Tidak perlu menambahkan MATERIALIZED kecuali ada ukuran atau多次 pemakaian.</div>

## Di Dunia Nyata

- **Top per kategori**: LATERAL + LIMIT 1.
- **Laporan bertahap**: CTE memberi nama setiap langkah.
- **Rekursi**: hierarki dan deret angka.
- **Query besar**: MATERIALIZED menghindari perhitungan ulang.
