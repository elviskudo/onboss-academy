Dua fitur PostgreSQL berikut menghemat banyak baris kode: **DISTINCT ON** untuk "satu yang terbaik per grup", dan **RETURNING** untuk melihat baris yang baru diubah.

## Apa Itu Keduanya?

- `DISTINCT ON (kolom)` — memilih **satu baris per nilai kolom**, sesuai kriteria ORDER BY. PostgreSQL-only.
- `RETURNING` — menampilkan baris hasil `INSERT`, `UPDATE`, atau `DELETE` dalam perintah yang sama. PostgreSQL-only (SQLite 3.35+ menyusul).

Keduanya menghapus boilerplate: tidak perlu subquery panjang untuk "yang terbaik", tidak perlu SELECT susulan untuk melihat hasil tulis.

## DISTINCT ON: Satu Baris per Kelompok

```sql
-- Postgres asli
SELECT DISTINCT ON (dept) dept, nama, gaji
FROM karyawan
ORDER BY dept, gaji DESC;
```

`DISTINCT ON (kolom)` memilih **satu baris per nilai kolom** — yang menang ditentukan ORDER BY sesudahnya. Karena diurutkan gaji DESC, yang keluar adalah karyawan dengan gaji tertinggi tiap departemen. Tanpa ORDER BY yang sesuai, hasilnya tidak menentu — DISTINCT ON selalu butuh pasangan ORDER BY.

Pemakaian ganda pun sah: `DISTINCT ON (dept, jabatan)` memilih satu baris per kombinasi keduanya.

## Padanan di Database Lain

```sql
-- padanan GROUP BY + MAX, lintas database
SELECT k.dept, k.nama, k.gaji
FROM karyawan k
JOIN (
  SELECT dept, MAX(gaji) AS gaji_max
  FROM karyawan
  GROUP BY dept
) m ON k.dept = m.dept AND k.gaji = m.gaji_max
ORDER BY k.dept;
```

Pola subquery MAX + JOIN ini menghasilkan "satu teratas per grup" di SQLite dan MySQL — karena demo editor kita berbasis SQLite, gunakan pola ini untuk mencoba hasil yang setara.

## RETURNING: Melihat Baris yang Diubah

```sql
-- Postgres asli
UPDATE karyawan
SET gaji = gaji + 500000
WHERE dept = 'Design'
RETURNING id, nama, gaji, gaji - 500000 AS gaji_lama;
```

Alih-alih UPDATE lalu SELECT terpisah, `RETURNING` menampilkan baris hasil perubahan **dalam satu perintah** — sangat praktis untuk API yang perlu mengembalikan data terbaru, atau menangkap `id` hasil INSERT tanpa langkah tambahan.

| Pemakaian | Mengembalikan | Kapan dipakai |
| --- | --- | --- |
| INSERT ... RETURNING id | id SERIAL baris baru | API POST yang langsung balik detail |
| UPDATE ... RETURNING * | baris hasil perubahan | PATCH yang merespons data terbaru |
| DELETE ... RETURNING * | baris yang dihapus | audit log, undo ringkas |

## RETURNING dengan INSERT

```sql
-- Postgres asli
INSERT INTO proyek (nama, lead_id, budget)
VALUES ('Analytics Platform', 2, 30000000)
RETURNING id, nama;
```

Mengambil `id` otomatis dari `SERIAL` langsung di perintah INSERT — tidak perlu `nextval` sequence atau SELECT terpisah.

## RETURNING dengan DELETE

```sql
-- Postgres asli
DELETE FROM proyek WHERE id = 3
RETURNING *;
```

Baris yang dihapus tampil sekaligus — audit ringkas tanpa log manual. SQLite modern (3.35+) juga mendukung RETURNING, jadi konsepnya bisa langsung dicoba di editor.

## Di Dunia Nyata

- **Endpoint POST REST** — `INSERT ... RETURNING id, created_at` membuat API cukup satu round-trip untuk menyimpan lalu membalikkan entitas baru.
- **Leaderboard tiap tim** — `DISTINCT ON (dept) ... ORDER BY dept, gaji DESC` menampilkan karyawan termahal per departemen untuk laporan HR.
- **Promosi massal** — `UPDATE ... RETURNING` menampilkan daftar karyawan yang gajinya naik — bahan email notifikasi tanpa query tambahan.
- **Keranjang belanja** — setelah DELETE item, RETURNING menampilkan sisa keranjang terbaru untuk dikirim balik ke UI.
- **Deduplikasi data** — DISTINCT ON memilih "satu yang paling baru per pelanggan" untuk daftar unik, lebih singkat daripada window function.

<div class="note">💡 DISTINCT ON = "satu yang terbaik per kelompok" dalam satu baris klausa; RETURNING = umpan balik langsung dari UPDATE/INSERT/DELETE. Keduanya menghapus boilerplate query di lapisan aplikasi.</div>
