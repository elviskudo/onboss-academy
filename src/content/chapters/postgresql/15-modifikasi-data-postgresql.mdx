PostgreSQL mengembalikan data dari perintah DML dengan RETURNING. Fitur ini memungkinkan aplikasi mendapat id generated tanpa query tambahan.

## INSERT

```sql
INSERT INTO produk (nama, harga)
VALUES ('Kopi', 25000), ('Teh', 18000)
RETURNING id, nama, harga;
```

Untuk kolom identity, jangan menyertakan nilainya kecuali memakai `OVERRIDING SYSTEM VALUE`.

## ON CONFLICT (UPSERT)

```sql
INSERT INTO produk (id, nama, harga)
VALUES (1, 'Kopi Susu', 27000)
ON CONFLICT (id) DO UPDATE
SET nama = EXCLUDED.nama, harga = EXCLUDED.harga
RETURNING id, nama;
```

`EXCLUDED` adalah baris yang diusulkan untuk disisipkan. `DO NOTHING` melewati konflik tanpa perubahan.

## UPDATE

```sql
UPDATE produk
SET harga = harga * 1.1
WHERE kategori = 'minuman'
RETURNING id, harga;
```

Tanpa WHERE, semua baris berubah. Biasakan menjalankan SELECT dengan WHERE yang sama terlebih dahulu.

## DELETE

```sql
DELETE FROM produk
WHERE aktif = false
RETURNING id, nama;
```

`TRUNCATE produk` lebih cepat untuk mengosongkan seluruh tabel, tetapi tidak bisa difilter dan tidak memicu trigger DELETE per baris.

## MERGE

```sql
MERGE INTO stok s
USING pendatang p ON s.id = p.id
WHEN MATCHED THEN UPDATE SET jumlah = p.jumlah
WHEN NOT MATCHED THEN INSERT (id, jumlah) VALUES (p.id, p.jumlah);
```

MERGE cocok untuk sinkronisasi dua tabel dalam satu pernyataan. Tersedia sejak PostgreSQL 15.

<div class="note">💡 RETURNING mengembalikan nilai **setelah** trigger BEFORE diterapkan. Ini sangat membantu saat default atau trigger mengubah kolom.</div>

## Di Dunia Nyata

- **Form input**: INSERT ... RETURNING id langsung dipakai untuk redirect.
- **Sinkronisasi**: UPSERT dari API eksternal.
- **Audit**: RETURNING pada UPDATE memberi nilai lama/baru.
- **Batch cleanup**: DELETE ... RETURNING mencatat baris yang dihapus.
