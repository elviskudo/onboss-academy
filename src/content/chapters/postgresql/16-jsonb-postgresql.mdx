JSONB menyimpan JSON dalam format biner yang bisa di-index dan di-query. Ia cocok untuk payload fleksibel, tapi bukan pengganti skema relasional untuk data yang stabil.

## Operator Utama

| Operator | Fungsi |
| --- | --- |
| `->` | ambil nilai sebagai jsonb |
| `->>` | ambil nilai sebagai text |
| `#>` | ambil jalur sebagai jsonb |
| `#>>` | ambil jalur sebagai text |
| `@>` | mengandung |
| `<@` | terkandung dalam |

```sql
SELECT data->'user' AS objek,
       data->>'user' AS teks,
       data#>>'{detail,kota}' AS kota
FROM event_log;
```

## Filter

```sql
SELECT * FROM event_log
WHERE data @> '{"aksi": "login"}';

SELECT * FROM event_log
WHERE data->>'user' = '42';
```

Bentuk pertama bisa memakai index GIN; bentuk kedua lebih cocok dengan index expression pada `(data->>'user')`.

## Index

```sql
CREATE INDEX idx_event_data ON event_log USING GIN (data jsonb_path_ops);
CREATE INDEX idx_event_user ON event_log ((data->>'user'));
```

`jsonb_path_ops` lebih kecil dan cepat untuk `@>`, tetapi tidak mendukung semua operator seperti `?` (cek kunci).

## Modifikasi

```sql
UPDATE event_log
SET data = data || '{"status": "diproses"}'::jsonb
WHERE id = 1;

SELECT jsonb_set(data, '{status}', '"selesai"') FROM event_log;
```

Operator `||` menggabungkan objek; `jsonb_set` mengubah nilai pada jalur tertentu.

## Agregasi

```sql
SELECT user_id, jsonb_agg(jsonb_build_object('id', id, 'aksi', aksi)) AS aktivitas
FROM event_log
GROUP BY user_id;
```

<div class="note">💡 JSONB mempertahankan struktur tapi **tidak** mempertahankan urutan kunci atau spasi. Kalau kamu perlu bentuk teks asli, gunakan tipe `json`.</div>

## Di Dunia Nyata

- **Event tracking**: payload berbeda-beda per jenis event.
- **Konfigurasi**: pengaturan aplikasi fleksibel per tenant.
- **API log**: response mentah disimpan untuk audit.
- **Produk**: atribut tambahan tanpa ALTER TABLE tiap kali.
