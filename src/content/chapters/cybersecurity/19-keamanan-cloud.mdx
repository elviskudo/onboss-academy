Cloud memindahkan sebagian tanggung jawab ke penyedia, tetapi **konfigurasi** tetap menjadi tanggung jawab pelanggan. Kesalahan izin adalah penyebab kebocoran yang paling sering.

## Model Tanggung Jawab Bersama

| Area | Penyedia | Pelanggan |
|---|---|---|
| Pusat data | ✓ | — |
| Hypervisor | ✓ | — |
| Sistem operasi guest | tergantung layanan | ✓ |
| Aplikasi & data | — | ✓ |
| IAM & jaringan | sebagian | ✓ |

## IAM yang Sehat

1. Gunakan **peran**, bukan kunci akses jangka panjang bila bisa.
2. Beri izin spesifik pada resource tertentu.
3. Wajib MFA untuk akun manusia.
4. Rotasi dan cabut kunci yang tidak terpakai.
5. Audit akses secara berkala.

## Contoh Izin Berlebih

```json
{ "Action": "*", "Resource": "*" }
```

Izin seperti ini memberi penyerang kendali penuh bila kunci bocor. Persempit menjadi daftar aksi dan ARN yang benar-benar dibutuhkan.

## Lindungi Penyimpanan

- Pastikan bucket tidak publik kecuali memang untuk aset statis.
- Aktifkan enkripsi at-rest dan in-transit.
- Gunakan versioning agar penghapusan tidak permanen.
- Terapkan lifecycle rule untuk mengontrol biaya dan retensi.

<div class="note">💡 Kunci API yang tertanam di aplikasi mobile atau repo git harus dianggap sudah bocor. Cabut dan terbitkan ulang, jangan hanya menghapus dari commit terakhir.</div>
