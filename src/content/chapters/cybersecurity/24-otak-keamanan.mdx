Mari rangkum semua konsep dalam satu insiden kecil. Tujuannya bukan menghafal alat, melainkan melatih urutan berpikir.

## Data yang Diterima

```text
09:21:03 login_failed user=ani ip=203.0.113.8
09:21:04 login_failed user=ani ip=203.0.113.8
09:21:06 login_failed user=ani ip=203.0.113.8
09:21:11 login_ok     user=ani ip=203.0.113.8
09:21:14 export_click  user=ani ip=203.0.113.8
```

## Triage

- Tiga kegagalan dalam 3 detik ⇒ bukan salah ketik manusia biasa.
- Login berhasil 5 detik kemudian ⇒ kata sandi kemungkinan ditemukan.
- Klik ekspor segera setelah masuk ⇒ penyerang mencari data.

## Tindakan Langsung

```text
1. Cabut semua sesi akun "ani"
2. Paksa ganti kata sandi + MFA
3. Tinjau hasil ekspor: data apa, kapan, dikirim ke mana
4. Blokir IP di edge, cari IP yang sama di log lain
5. Simpan log dan request_id sebagai bukti
```

## Akar Masalah

Ternyata tidak ada rate limit pada endpoint login, dan akun memakai kata sandi yang pernah bocor di situs lain (credential stuffing). MFA belum diaktifkan.

## Perbaikan

| Temuan | Tindakan |
|---|---|
| Tanpa rate limit | Batasi 5 percobaan / menit / IP + akun |
| Tidak ada MFA | Wajibkan untuk semua pengguna |
| Password reused | Cek against breach corpus saat ganti password |
| Deteksi terlambat | Alert pada pola gagal-berhasil dari IP sama |

<div class="note">💡 Latihan seperti ini bisa dijalankan tiap bulan dengan data simulasi. Tim yang terbiasa membaca linimasa akan jauh lebih tenang saat insiden nyata.</div>
