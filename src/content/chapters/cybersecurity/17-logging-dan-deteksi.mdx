Log adalah catatan peristiwa. Tanpa log, respons insiden berubah menjadi tebakan. Namun log yang buruk—terlalu sedikit, terlalu banyak, atau mengandung rahasia—juga tidak berguna.

## Field yang Berguna

```json
{
  "ts": "2026-01-12T09:21:03Z",
  "level": "warn",
  "event": "login_failed",
  "user": "ani",
  "src_ip": "203.0.113.8",
  "request_id": "b7f1"
}
```

`request_id` yang sama bisa dipakai untuk mengikuti satu request melintasi banyak layanan.

## Hierarki Alert

| Level | Contoh | Respons |
|---|---|---|
| Info | Login sukses | Arsipkan |
| Warn | 5 login gagal | Tinjau |
| High | Login sukses dari lokasi baru | Konfirmasi pengguna |
| Critical | Perubahan role admin | Eskalasi langsung |

## Deteksi Sederhana

```text
> 10 login gagal / 5 menit untuk satu akun     -> brute force
akses ke URL admin dari IP publik             -> penyisiran
upload file .php                              -> percobaan webshell
keluar trafik besar ke IP asing               -> kemungkinan eksfiltrasi
```

## Retensi

Tentukan berapa lama log disimpan berdasarkan kebutuhan forensik dan regulasi. Log yang lebih lama bisa dipindah ke storage murah, tetapi tetap harus terlindung dari perubahan.

<div class="note">💡 Gunakan tanda tangan atau penyimpanan append-only agar penyerang yang sudah masuk tidak bisa menghapus jejaknya dengan mudah.</div>
