Serangan web paling sering masuk lewat input yang tidak dipercaya. Dua lapisan yang sering dipakai bersama adalah WAF (di depan aplikasi) dan validasi di dalam kode.

## WAF Bukan Pengganti Kode Aman

WAF bisa memblokir pola umum, tetapi penyerang terus mencari bypass. Anggap WAF sebagai lapisan tambahan, bukan alasan untuk melewati validasi.

## Prinsip Validasi

1. **Tolak apa yang tidak dikenal** (allowlist).
2. **Validasi di server** — klien hanya untuk kenyamanan.
3. **Normalisasi dulu** — unicode, spasi, dan huruf bisa menyamar.
4. **Batasi ukuran** — panjang, jumlah field, ukuran file.
5. **Escape saat output** — menyesuaikan konteks (HTML, URL, SQL, JSON).

## Contoh Alur Aman

```text
input -> normalisasi -> allowlist -> simpan -> escape saat tampil
```

## Rate Limit

```text
5 percobaan login / menit / IP
10 request API / detik / token
```

Sertakan `Retry-After` pada respons 429 agar klien yang baik bisa menunggu. Gunakan kunci berdasarkan IP **dan** akun agar penyerang tidak bisa bergilir.

## Logging

Catat percobaan yang ditolak tanpa menyimpan kata sandi mentah. Log yang terlalu sedikit menyulitkan forensik; log yang berisi data sensitif justru menambah risiko.

<div class="note">💡 Parameterisasi query (prepared statement) adalah cara yang benar untuk mencegah SQL injection—bukan dengan membuang tanda kutip manual.</div>
