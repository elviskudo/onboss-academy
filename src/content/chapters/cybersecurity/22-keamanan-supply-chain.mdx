Aplikasi modern jarang ditulis dari nol. Sebagian besar kode berasal dari library pihak ketiga—artinya rantai pasok menjadi bagian dari permukaan serangan.

## Risiko Umum

| Risiko | Contoh | Mitigasi |
|---|---|---|
| Typosquatting | `reqeusts` mirip `requests` | Teliti nama, gunakan registry tepercaya |
| Dependency confusion | Paket internal tertarik dari publik | Scope & prioritas registry jelas |
| Versi usang | CVE pada library lama | Audit + update terjadwal |
| Paket berisiko | Script install mencurigakan | Tinjau sebelum menambah |

## Lockfile

```bash
npm ci            # deterministik dari package-lock.json
pip install -r requirements.txt --require-hashes
go mod download   # dengan go.sum
```

Simpan lockfile di repository dan jangan mengabaikan perubahan besarnya tanpa peninjauan.

## SBOM

```bash
syft . -o spdx-json > sbom.json
grype sbom:sbom.json
```

Saat CVE baru diumumkan, SBOM menjawab dengan cepat: "apakah produk kita memakai komponen itu?" Tanpa SBOM, jawabannya butuh pencarian manual.

## Tanda Tangan Artefak

```bash
cosign sign --key kms://... ghcr.io/tim/app:1.4.2
cosign verify --key kms://... ghcr.io/tim/app:1.4.2
```

Verifikasi sebaiknya terjadi di pipeline deploy, bukan hanya di dokumentasi.

<div class="note">💡 Audit otomatis sering menghasilkan temuan yang tidak relevan. Tetap prioritaskan berdasarkan apakah komponen benar-benar dipakai dan bisa dijangkau dari luar.</div>
