Insiden bukan soal "apakah akan terjadi", melainkan "kapan". Respons yang terlatih membatasi kerusakan dan menghasilkan perbaikan.

## Enam Langkah

| Langkah | Tujuan |
|---|---|
| Persiapan | Tim, kontak, alat, dan wewenang sudah jelas |
| Identifikasi | Tentukan apa terjadi dan sistem yang terdampak |
| Kontainment | Hentikan penyebaran |
| Eradikasi | Hapus akses, malware, dan akun jahat |
| Pemulihan | Kembalikan layanan dengan keamanan diperbaiki |
| Pelajaran | Tulis temuan dan tindak lanjut |

## Kotak Alat Triage

```bash
who / last            # siapa yang login
ps aux                # proses mencurigakan
ss -tunap             # koneksi aktif
find / -newermt ...   # file baru
journalctl -u ssh     # log layanan
```

## Urutan Kontainment

1. Cabut akses akun yang terdampak.
2. Putus jaringan host bila perlu, tapi **jangan** matikan dulu bila analisis memori diperlukan.
3. Simpan image disk dan log sebelum dibersihkan.
4. Ganti kredensial yang mungkin bocor.
5. Patches dan konfigurasi ulang sebelum host kembali masuk produksi.

## Komunikasi

Tentukan satu narasumber resmi dan saluran internal. Hindari menebak di depan publik; sampaikan fakta yang sudah diverifikasi dan perkiraan waktu pembaruan berikutnya.

<div class="note">💡 Latih respons insiden dengan simulasi. Tim yang baru pertama kali membaca playbook saat insiden nyata hampir selalu lebih lambat.</div>
