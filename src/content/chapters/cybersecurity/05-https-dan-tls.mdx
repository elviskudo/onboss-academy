Komunikasi tanpa enkripsi ibarat kartu pos: siapa pun di jalur bisa membacanya. **HTTPS** menutup celah ini.

## Apa yang Diberikan TLS?

- **Enkripsi** — isi pesan tidak terbaca penyadap jalur.
- **Integritas** — perubahan di tengah jalan terdeteksi.
- **Autentikasi** — server terbukti pemilik domain (lewat sertifikat).

## Cara Kerja Singkat

```
Browser -> "halo, saya mau TLS" -> Server kirim sertifikat
Browser verifikasi rantai kepercayaan ke CA
Kunci enkripsi disepakati -> koneksi terenkripsi
```

Bila verifikasi gagal, browser menampilkan peringatan — **jangan pernah mengklik "lanjutkan" pada situs peringatan sertifikat**.

## Verifikasi yang Benar (Prinsip)

```python
import ssl

# Prinsip penting: jangan pernah mematikan verifikasi
# ctx.check_hostname = False      # JANGAN
# ctx.verify_mode = ssl.CERT_NONE # JANGAN

print("Selalu biarkan check_hostname dan verifikasi sertifikat aktif")
print("Self-signed hanya untuk lingkungan uji internal tertutup")
```

Mematikan verifikasi membuat enkripsi berguna bagi penyadap yang menyamar sebagai server.

## HTTP vs HTTPS pada Praktik

```
http://contoh.com          -> terbaca di WiFi publik
https://contoh.com         -> terenkripsi
```

Aktifkan redirect 301 dari HTTP ke HTTPS untuk semua halaman.

## HSTS dan Header Pendukung

```
Strict-Transport-Security: max-age=31536000; includeSubDomains
```

HSTS mengunci domain ke HTTPS setahun ke depan. Dampingi dengan `Secure` pada cookie dan pertimbangkan preload HSTS.

## Empat Bagian Kepercayaan TLS

Ada **4 bagian** yang bekerja bersama pada koneksi HTTPS.

| Bagian | Fungsi | Contoh | Kegagalan umum |
|---|---|---|---|
| Sertifikat | Mengikat domain ke public key | Sertifikat `example.com` | Kedaluwarsa |
| CA chain | Menghubungkan ke root tepercaya | Intermediate CA | Chain tidak lengkap |
| Handshake | Menegosiasikan versi dan kunci | TLS 1.3 | Versi lama diizinkan |
| Record encryption | Melindungi data aplikasi | AEAD | Cipher usang |

TLS modern menggunakan kriptografi asimetris untuk autentikasi dan pertukaran kunci, lalu kriptografi simetris yang lebih cepat untuk data sesi. Forward secrecy membatasi dampak jika private key server bocor kemudian. Operasikan TLS 1.2 atau 1.3 sesuai kompatibilitas; nonaktifkan protokol usang.

```bash
curl --fail --show-error --location https://example.com/
openssl s_client -connect example.com:443 -servername example.com
```

`curl` gagal bila sertifikat atau status HTTP bermasalah. `openssl s_client` membantu memeriksa chain dan nama server; jangan menambahkan opsi yang mematikan verifikasi pada client produksi. Otomatiskan penerbitan serta renewal sertifikat dan alert sebelum kedaluwarsa.

HSTS baru aman setelah seluruh subdomain mendukung HTTPS. `includeSubDomains` dan preload sulit dibatalkan, jadi uji bertahap dengan `max-age` pendek. HTTPS juga harus digunakan untuk koneksi internal yang melintasi jaringan tidak tepercaya.

## Di Dunia Nyata

1. Toko online mengalihkan seluruh HTTP ke HTTPS dan menandai cookie sesi `Secure`, `HttpOnly`, serta `SameSite`.
2. API mobile melakukan verifikasi hostname normal dan tidak menerima semua sertifikat saat debugging selesai.
3. Load balancer menghentikan TLS, lalu mengenkripsi ulang koneksi ke service sensitif di jaringan internal.
4. Monitoring memberi peringatan 30 hari sebelum sertifikat habis agar renewal gagal tidak menjadi downtime.
5. Organisasi menguji konfigurasi TLS setelah perubahan cipher atau proxy, termasuk chain untuk client lama yang masih didukung.

TLS melindungi data saat transit, bukan endpoint yang sudah terinfeksi, database tanpa kontrol akses, atau situs phishing dengan sertifikat valid. Tetap perlukan autentikasi, otorisasi, patch, dan edukasi pengguna.
