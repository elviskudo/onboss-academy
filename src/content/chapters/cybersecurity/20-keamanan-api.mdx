API sering menjadi pintu depan aplikasi modern. Karena sifatnya terprogram, satu celah otorisasi bisa dieksploitasi secara massal dalam hitungan detik.

## Autentikasi vs Otorisasi

```text
token -> siapa pemilik request (autentikasi)
aturan -> apakah ia boleh mengakses objek ini (otorisasi)
```

Keduanya harus dijalankan di server untuk setiap permintaan yang sensitif.

## IDOR

```text
GET /api/invoice/1042   -> milik saya
GET /api/invoice/1043   -> milik orang lain?
```

Selalu bandingkan kepemilikan objek dengan identitas pengguna. Jangan mengandalkan kerahasiaan ID acak sebagai satu-satunya perlindungan.

## CORS

```http
Access-Control-Allow-Origin: https://app.example.com
Access-Control-Allow-Credentials: true
```

Jangan menggunakan `*` bersama kredensial. Daftar asal yang diizinkan sebaiknya eksplisit dan tervalidasi.

## Batas dan Kuota

- Batasi ukuran body request.
- Batasi jumlah field dan kedalaman JSON.
- Gunakan paginasi dengan batas maksimal.
- Terapkan kuota per token dan rate limit.

<div class="note">💡 Endpoint yang "internal" tetap harus diamankan. Jaringan bisa berubah, dan layanan lain bisa saja terekspos tidak sengaja.</div>
