Aplikasi mobile berjalan di perangkat yang bisa hilang, di-root, atau dipasangi aplikasi jahat. Karena itu, data sensitif tidak boleh dibiarkan di penyimpanan biasa.

## Penyimpanan

| Kebutuhan | Tempat yang tepat |
|---|---|
| Token akses | Keychain / Keystore |
| Preferensi biasa | Pengaturan aplikasi |
| File besar sensitif | Terenkripsi, kunci di keystore |
| Sementara | Cache dengan masa hidup pendek |

## Transport

```text
HTTPS wajib -> sertifikat terverifikasi -> pinning (opsional)
```

Pinning memberi perlindungan tambahan, tetapi jika sertifikat berubah dan aplikasi lama tidak diperbarui, pengguna bisa terblokir. Siapkan beberapa pin cadangan dan mekanisme update.

## Izin

```text
kamera -> hanya saat memindai QR
lokasi -> hanya saat fitur peta dipakai
kontak -> hapus bila tidak ada fitur yang memakainya
```

Minta izin **saat dibutuhkan**, bukan semua sekaligus saat instalasi.

## Ancaman Khusus

- **Repackaging** — aplikasi dimodifikasi lalu disebarkan.
- **Overlay attack** — lapisan palsu menipu pengguna memasukkan PIN.
- **Clipboard sniffing** — malware membaca salinan kode OTP.
- **Logcat** — log yang terlalu verbose membocorkan token.

<div class="note">💡 Jangan menaruh rahasia permanen di biner aplikasi. Kunci yang dikirim ke perangkat bisa diekstrak; anggap sebagai data publik.</div>
