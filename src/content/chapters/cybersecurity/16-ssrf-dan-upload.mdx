Dua celah yang sering muncul pada aplikasi modern: fitur "ambil URL" (SSRF) dan fitur unggah berkas. Keduanya memberi penyerang kendali atas sumber data.

## SSRF

```text
POST /preview
{ "url": "http://169.254.169.254/latest/meta-data/" }
```

Endpoint metadata cloud sering menjadi target. Jika server mengambil URL itu, kredensial sementara bisa bocor.

## Pertahanan SSRF

1. Allowlist hostname yang diizinkan.
2. Resolve DNS lalu blokir IP privat, loopback, link-local, dan IPv6 lokal.
3. **Matikan redirect** atau validasi ulang setiap tujuan.
4. Batasi protokol hanya `http`/`https`.
5. Terapkan proxy keluar khusus dengan aturan ketat.

## Upload Aman

```text
terima file -> cek ukuran -> cek magic bytes -> ubah nama
          -> simpan di luar web root -> sajikan lewat endpoint kontrol
```

## Tipe vs Ekstensi

```text
file bernama  foto.jpg
isi sebenarnya: <?php system($_GET['cmd']); ?>
```

Cek beberapa byte awal (magic bytes), bukan hanya nama. Untuk gambar, bisa juga diproses ulang (re-encode) agar metadata berbahaya hilang.

<div class="note">💡 Jangan mengandalkan `Content-Type` dari request—nilainya dikirim klien dan mudah dipalsukan.</div>
