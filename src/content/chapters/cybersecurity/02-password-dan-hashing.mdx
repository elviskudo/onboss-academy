Kata sandi adalah lapisan pertama autentikasi — dan **cara menyimpannya** menentukan nasib jutaan akun bila basis data dicuri.

## Aturan Emas Penyimpanan

- **Jangan pernah simpan password sebagai teks biasa.**
- Simpan **hash + salt**, idealnya dengan algoritma lambat khusus password.
- **Verifikasi** dengan meng-hash input pengguna memakai salt yang tersimpan, lalu membandingkan.

## Konsep Hash + Salt

```python
import hashlib
import os

salt = os.urandom(8).hex()
teks = "kata-sandi-rahasia" + salt
hasil = hashlib.pbkdf2_hmac("sha256", teks.encode(), salt.encode(), 100000)

print("salt :", salt)
print("hash :", hasil.hex()[:32], "...")
```

Contoh ini memakai `pbkdf2_hmac` dari standard library untuk memahami konsep. Di produksi, utamakan **bcrypt, scrypt, atau Argon2** yang memang dirancang untuk password.

## Mengapa Hash Cepat Berbahaya?

```python
# Hash cepat cocok untuk integritas file, bukan password:
# penyerang bisa menguji miliaran tebakan per detik
print("Untuk password, pilih algoritma yang sengaja LAMBAT")
```

MD5 dan SHA-256 mentah dirancang cepat — tepat untuk checksum, salah untuk password.

## MFA: Faktor Kedua

```python
# Verifikasi dua langkah (konsep TOTP)
kunci_rahasia = "JBSWY3DPEHPK3PXP"   # dibagikan saat aktivasi
interval = 30   # detik

# code = TOTP(kunci_rahasia, sekarang // interval)
print(f"Kode berlaku tiap {interval} detik -- butuh aplikasi auth di perangkat")
```

Dengan MFA, mencuri password saja tidak cukup untuk membajak akun.

## Kebiasaan Baik untuk Pengguna

- Frasa sandi panjang + password manager untuk mengingat.
- Aktifkan MFA pada email, bank, dan akun kerja.
- Waspadai phishing — situs tiruan mencuri password asli Anda.

## Empat Komponen Penyimpanan Password

Ada **4 komponen inti**: algoritma, salt, cost, dan format hasil.

| Komponen | Fungsi | Contoh | Kapan diperbarui |
|---|---|---|---|
| Algoritma | Memperlambat tebakan | Argon2id, scrypt, bcrypt, PBKDF2 | Saat rekomendasi berubah |
| Salt | Membuat hasil unik per password | Acak minimal 16 byte | Setiap password baru |
| Cost | Mengatur biaya komputasi/memori | Parameter waktu dan memori | Saat hardware makin cepat |
| Format | Menyimpan algoritma dan parameter | String hash terstruktur | Bersama record akun |

Salt tidak perlu dirahasiakan dan disimpan bersama hash. **Pepper** berbeda: nilai rahasia global yang disimpan di secret manager, bukan database. Pepper opsional dan harus dapat dirotasi; ia tidak menggantikan salt atau algoritma yang benar.

Saat login, ambil hash tersimpan, baca parameter, hitung hash input, lalu bandingkan secara constant-time melalui library. Jika cost lama terlalu rendah, lakukan rehash setelah login berhasil. Jangan membuat algoritma sendiri dan jangan memotong hasil hash.

## Kebijakan Praktis

Izinkan password panjang, dukung password manager, blok password yang diketahui bocor, dan hindari aturan pergantian berkala tanpa indikasi kompromi. Rate limit login berdasarkan beberapa sinyal agar penyerang tidak dapat mencoba tanpa batas sekaligus tidak mudah mengunci semua pengguna. Reset password memakai token acak, sekali pakai, berumur pendek, dan disimpan sebagai hash.

## Di Dunia Nyata

1. Marketplace memigrasikan bcrypt cost lama secara bertahap ketika pengguna berhasil login.
2. Portal perusahaan memeriksa password baru terhadap daftar password bocor tanpa mencatat password tersebut.
3. Reset akun mengirim tautan berumur 15 menit dan mencabut seluruh sesi setelah password diganti.
4. Admin memakai security key, sedangkan pengguna umum diberi TOTP dan recovery code sekali pakai.
5. Tim insiden memaksa reset hanya untuk akun terdampak setelah kebocoran hash, lalu memantau credential stuffing.

Password tidak pernah dikirim kembali kepada pengguna. Jika layanan dapat mengirim password lama, berarti layanan dapat membacanya dan desain penyimpanannya salah.
