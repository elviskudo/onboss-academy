OOP mengelompokkan data + perilaku jadi `class`. Python mendukung **4 pilar OOP** (dengan catatan jujur soal encapsulation) lewat sintaks yang ringkas.

## Class & Object

```python
class Siswa:
    def __init__(self, nama, nilai):
        self.nama = nama
        self.nilai = nilai

    def lulus(self):
        return self.nilai >= 70

    def __str__(self):
        return f"{self.nama} ({self.nilai}) → {'LULUS' if self.lulus() else 'REMED'}"

s = Siswa("Sari", 90)
print(s)
```

`class` = cetak biru, object = hasil cetak (`Siswa("Sari", 90)`). `__init__` = constructor, `__str__` = tampilan saat di-print, `__repr__` = representasi untuk developer.

## 4 Pilar OOP di Python

| Pilar | Makna | Status & cara di Python |
|---|---|---|
| Encapsulation | sembunyikan detail internal | **Konvensi**: `_nama` (jangan di luar class), `__nama` (name mangling) — tidak ada private ketat |
| Inheritance | class anak memakai induk | `class Kucing(Hewan):` — ada multi-level & MRO |
| Polymorphism | metode sama, perilaku beda | method override + duck typing ("kalau jalan seperti bebek…") |
| Abstraction | sembunyikan kompleksitas | `abc.ABC` + `@abstractmethod` untuk interface wajib |

```python
class Hewan:
    def bersuara(self):
        return "..."

class Kucing(Hewan):
    def bersuara(self):
        return "Meong!"
```

## Method & Properti

```python
class Lingkaran:
    def __init__(self, r):
        self.r = r

    @property
    def luas(self):
        return 3.14 * self.r ** 2

print(Lingkaran(7).luas)
```

Ada **3 jenis method**: instance (`self`), `@classmethod` (butuh `cls`, untuk factory), dan `@staticmethod` (tanpa self/cls, utilitas murni). `@property` membuat atribut terbaca seperti field tapi dihitung otomatis.

## Constructor & Destructor

`__init__` dipanggil saat object dibuat; `__del__` (destructor) dipanggil saat dihapus GC — **jarang dipakai**. Untuk resource (file, koneksi), Python lebih suka context manager: `__enter__`/`__exit__`, dipakai lewat `with`.

## Kapan OOP vs Prosedural

- **OOP**: banyak state berubah + perilaku terkait (akun bank, keranjang belanja, karakter game, model data).
- **Prosedural/fungsional**: skrip sekali jalan, transformasi data, logika matematis murni.
- Python fleksibel: kelas bisa dipakai tanpa pewarisan, dan fungsi bebas di dalam class — pakai sesuai kebutuhan, bukan ritual.

Gabungkan class, list, method, dan string formatting jadi aplikasi konsol nyata. Fitur wajib yang sudah ada: tambah tugas, tandai selesai, tampilkan daftar, hitung progres. Latihan lanjutan: hapus tugas, simpan/ muat dari JSON (chapter 8), dan cari tugas dengan `for` + `if` (chapter 4).

## Di Dunia Nyata

- Class `Karyawan` menyimpan gaji + method `hitungTHR()` — data dan aturannya tidak tercecer.
- Model `Produk` dengan `@property harga_setelah_diskon` dipakai ulang di keranjang & halaman checkout.
- Game: class `Pemain` pewarisan `Karakter` — statistik beda, cara serang sama.
- Aplikasi tiket: class `Pesanan` dengan status (`dibayar` → `selesai`) memakai method, bukan variabel global yang bisa lupa di-set.

<div class="note">💡 Python percaya pada duck typing: yang penting object punya method yang dibutuhkan, bukan keturunannya. Tulis class saat ada **state + aturan yang hidup bersama** — kalau hanya satu fungsi murni, cukup `def` biasa.</div>
