Sebelum membagikan proyek, kamu perlu memastikan dependensinya tercatat dan tidak bentrok dengan proyek lain. Di sinilah `pip` dan virtual environment berperan.

## pip

```bash
pip install requests
pip install "flask>=3.0,<4"
pip uninstall requests
pip list
pip show requests
pip install -r requirements.txt
```

Selalu pin versi di `requirements.txt` untuk reproducibility:

```
requests==2.32.3
Flask==3.0.3
pytest==8.3.4
```

## Virtual Environment

```bash
python -m venv .venv

# macOS / Linux
source .venv/bin/activate

# Windows (PowerShell)
.venv\Scripts\Activate.ps1
```

Setelah aktif, prompt berubah dan `pip install` hanya memengaruhi environment itu. Matikan dengan `deactivate`.

## Kenapa Perlu Isolasi?

Proyek A butuh `Django 4`, proyek B masih `Django 3`. Tanpa venv, instalasi terakhir akan menimpa yang pertama. Dengan venv, masing-masing punya folder `site-packages` sendiri.

## Struktur Proyek Sehat

```
proyek/
├── .venv/                 # jangan di-commit
├── requirements.txt
├── src/
│   └── app.py
├── tests/
└── README.md
```

Tambahkan `.venv/` ke `.gitignore`.

## Alternatif Modern

| Tool | Keunggulan |
|---|---|
| `venv` | bawaan Python, tanpa instalasi |
| `pipenv` | lockfile otomatis |
| `poetry` | manajemen dependensi + packaging |
| `uv` | sangat cepat, replacement pip/venv |

<div class="note">💡 Jangan pernah install paket ke Python sistem (global) untuk proyek nyata. Selalu aktifkan venv dulu — cek dengan <code>which python</code> (atau <code>where python</code> di Windows) yang harus menunjuk ke folder <code>.venv</code>.</div>
