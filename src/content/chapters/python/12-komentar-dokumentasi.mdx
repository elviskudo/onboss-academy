Komentar adalah catatan untuk pembaca kode, bukan untuk mesin. Python mengabaikannya saat mengeksekusi program.

## Komentar Baris

```python
# ini komentar
x = 10  # komentar di akhir baris
```

Gunakan spasi dua kali sebelum `#` inline agar mudah dibaca. Hindari komentar yang hanya mengulang kode: `x = 10  # set x ke 10` tidak menambah informasi.

## Docstring

Docstring adalah string literal pada baris pertama modul, class, atau fungsi. Ia menjadi dokumentasi resmi yang bisa dibaca `help()`.

```python
def rata_rata(nilai):
    """Kembalikan rata-rata dari list angka.

   .List angka kosong mengembalikan 0 agar pemanggil tidak perlu cek dulu.
    """
    return sum(nilai) / len(nilai) if nilai else 0
```

| Objek | Letak docstring | Diakses lewat |
|---|---|---|
| Modul | baris paling atas file | `help(modul)` |
| Fungsi | baris pertama setelah `def` | `help(f)` / `f.__doc__` |
| Class | baris pertama setelah `class` | `help(Kelas)` |

## Type Hint

Sejak Python 3.5, kamu bisa menulis tipe parameter dan hasil. Ini bukan paksaan runtime, tapi petunjuk untuk editor, `mypy`, dan rekan tim.

```python
def sapa(nama: str, umur: int = 0) -> str:
    return f"Halo {nama}, umur {umur}"

def total(items: list[float]) -> float:
    return sum(items)
```

<div class="note">💡 Tulis komentar untuk menjelaskan <b>alasan</b>, bukan <b>apa</b> yang terjadi. `x = x * 0.9` sudah jelas menghitung diskon 10%; komentar yang berguna adalah "diskon diberikan sebelum pajak sesuai aturan SO-2024".</div>

## Kapan Berkomentar

- Konstanta ajaib: jelaskan mengapa batasnya 30, bukan 31.
- Workaround: sebutkan issue/library versi yang bermasalah.
- Algoritma kompleks: ringkas strategi di atas blok sebelum kode.
- API publik: selalu pakai docstring agar `help()` berguna.
