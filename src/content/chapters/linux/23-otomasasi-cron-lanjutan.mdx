Tugas berulang bisa dijalankan dengan cron klasik atau systemd timer modern. Memilih yang tepat menghindari jadwal yang diam-diam tidak jalan.

## Cron

```text
* * * * *  perintah
│ │ │ │ │
│ │ │ │ └── hari dalam minggu (0-7)
│ │ │ └──── bulan (1-12)
│ │ └────── hari dalam bulan (1-31)
│ └──────── jam (0-23)
└────────── menit (0-59)
```

```bash
0 2 * * * /usr/local/bin/backup.sh >> /var/log/backup.log 2>&1
*/15 * * * * /usr/local/bin/cek-kesehatan.sh
0 9 * * 1-5 /usr/local/bin/laporan-harian.sh
```

| Pola | Arti |
|---|---|
| `*/5` | tiap 5 unit |
| `1,15` | pada 1 dan 15 |
| `1-5` | rentang |
| `0` | tepat pada 0 |

## systemd Timer

```ini
# backup.timer
[Unit]
Description=Backup harian

[Timer]
OnCalendar=daily
Persistent=true

[Install]
WantedBy=timers.target
```

```bash
systemctl daemon-reload
systemctl enable --now backup.timer
systemctl list-timers
```

`Persistent=true` membuat tugas yang terlewat saat mesin mati dijalankan saat boot.

## Perbandingan

| Aspek | cron | systemd timer |
|---|---|---|
| Sintaks | ringkas | butuh unit file |
| Log | sendiri | journald |
| Job terlewat | tidak dijalankan | bisa ditunda |
| Dependencies | tidak ada | ada |
| Monitoring | perlu extra | `systemctl status` |

<div class="note">💡 Selalu alihkan output cron ke log. Job yang gagal tanpa jejak adalah sumber masalah yang sulit dilacak.</div>

## Praktik Baik

- Simpan skrip di `/usr/local/bin`, bukan di home pengguna.
- Gunakan path absolut di crontab — `PATH` di cron sangat terbatas.
- Tambahkan locking (`flock`) agar job tidak tumpang tindih.
