Sebelum memakai Docker, penting tahu bahwa container bukan teknologi sihir — ia adalah **fitur kernel Linux yang dirangkai rapi**.

## Namespace

Namespace membuat proses melihat “dunia” yang berbeda:

| Namespace | Isolasi |
|---|---|
| PID | daftar proses |
| NET | interface dan routing |
| MNT | mount point |
| UTS | hostname |
| USER | UID/GID |
| IPC | shared memory |

```bash
ls -l /proc/self/ns
```

## cgroup

```bash
cat /proc/self/cgroup
```

cgroup mengontrol berapa CPU dan memori yang boleh dipakai sebuah grup proses. Tanpa batas, satu container bisa menguras seluruh host.

## Image vs Container

```text
Image  = cetakan read-only (layer)
Container = image + lapisan writable + proses berjalan
```

## Perbandingan

| Aspek | VM | Container |
|---|---|---|
| Kernel | tamu masing-masing | berbagi host |
| Ukuran | GB | MB |
| Startup | menit | detik |
| Isolasi | kuat | sedang |
| Use case | OS berbeda | aplikasi mikroservis |

<div class="note">💡 Container bukan pengganti VM untuk semua kasus. Isolasi kernel shared berarti kernel rentan tetap berdampak ke semua container di host yang sama.</div>

## Kapan Dipakai

- Menstandarkan lingkungan development dan produksi.
- Mengemas mikroservis beserta dependensinya.
- Menjalankan banyak aplikasi pada satu host secara efisien.
- Membangun pipeline CI yang reproducible.
