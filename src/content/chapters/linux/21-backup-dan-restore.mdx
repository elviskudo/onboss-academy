Backup yang baik diukur dari **kemampuan restore**, bukan dari ukuran file hasil backup.

## Aturan 3-2-1

```text
3 salinan data
2 jenis media berbeda
1 salinan di lokasi terpisah
```

## Jenis Backup

| Jenis | Kelebihan | Kekurangan |
|---|---|---|
| Full | restore paling cepat | ruang besar |
| Inkremental | hemat ruang | restore bertahap |
| Differensial | tengah-tengah | makin lama makin besar |
| Snapshot | sangat cepat | bukan offsite |

## rsync

```bash
rsync -avz /srv/app/ /backup/app/
rsync -avz --delete /srv/app/ /backup/app/
rsync -avz -e ssh /srv/app/ user@backup:/backup/
```

Opsi `--delete` menyamakan tujuan dengan sumber — hati-hati salah arah bisa menghapus data.

## Backup Database

```bash
mysqldump -u user -p namadb | gzip > db.sql.gz
pg_dump namadb | gzip > db.sql.gz
```

```bash
gunzip < db.sql.gz | mysql -u user -p namadb
```

## Otomatisasi

```bash
# /etc/cron.d/backup
0 2 * * * root /usr/local/bin/backup.sh >> /var/log/backup.log 2>&1
```

```bash
#!/bin/bash
set -euo pipefail
TANGGAL=$(date +%F)
tar -czf "/backup/app-$TANGGAL.tar.gz" /srv/app
find /backup -name "app-*.tar.gz" -mtime +30 -delete
```

<div class="note">💡 Simpan checksum backup. Jika file berubah tanpa sengaja, perbandingan hash membantu mendeteksi korupsi sebelum restore diperlukan.</div>

## Checklist Restore

1. Pilih backup yang tepat.
2. Restore ke lokasi sementara.
3. Verifikasi file dan izin.
4. Uji aplikasi bila memungkinkan.
5. Dokumentasikan waktu dan hasilnya.
