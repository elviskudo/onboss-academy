## Strict Mode

```bash
#!/usr/bin/env bash
set -euo pipefail

TMP=$(mktemp)
trap 'rm -f "$TMP"' EXIT
trap 'echo "Dibatalkan"; exit 130' INT TERM

echo "data" > "$TMP"
echo "Bekerja dengan $TMP"

# pipefail membuat pipeline gagal bila salah satu bagian gagal
grep "data" "$TMP" | wc -l
```

```bash
set -e   # keluar saat perintah gagal
set -u   # error pada variabel belum didefinisikan
set -o pipefail  # pipeline gagal bila salah satu tahap gagal
```

Kombinasi `set -euo pipefail` adalah standar skrip produksi.

## Trap

```bash
trap 'rm -f "$TMP"' EXIT
trap 'echo "Sinyal INT diterima" >&2' INT
```

Penangan EXIT berjalan terakhir, baik karena akhir skrip, `exit`, maupun error dengan `set -e`.

## Berkas Sementara

```bash
TMPDIR_KU=$(mktemp -d)
trap 'rm -rf "$TMPDIR_KU"' EXIT
```

`mktemp` membuat nama acak yang sulit ditebak — jauh lebih aman daripada `/tmp/fileku.txt` yang bisa ditimpa proses lain.

## Membersihkan dengan Aman

```bash
bersih() {
  local kode=$?
  [ -n "${TMP:-}" ] && rm -f "$TMP"
  exit "$kode"
}
trap bersih EXIT
```

Pertahankan kode keluar asli agar scheduler mengetahui apakah skrip berhasil.

<div class="note">💡 Jangan memakai `trap ... EXIT` dengan variabel yang belum di-set saat `set -u` aktif. Gunakan `${VAR:-}` supaya handler tidak ikut error.</div>
