## Melihat Proses

```bash
#!/usr/bin/env bash
ps aux | grep nginx
pgrep -f "nginx" | head -5

# kirim sinyal berdasarkan PID
kill 1234           # SIGTERM
kill -9 1234        # SIGKILL (terakhir)

# berdasarkan nama
pkill -f "script-lama.sh"

# jalankan di latar belakang
sleep 60 &
pid=$!
echo "PID: $pid"
jobs
wait "$pid"
```

| Perintah | Fungsi |
|---|---|
| `ps aux` | daftar lengkap semua proses |
| `ps -ef` | format UNIX standar |
| `top` / `htop` | tampilan interaktif |
| `pgrep nama` | cari PID berdasarkan nama |
| `pstree` | pohon hubungan proses |

## Sinyal

```bash
kill -l              # daftar sinyal
kill 1234            # kirim SIGTERM
kill -HUP 1234       # minta proses memuat ulang konfigurasi
kill -9 1234         # paksa mati
```

Prinsipnya: coba SIGTERM dulu, tunggu beberapa detik, baru SIGKILL bila perlu.

## Job Control

```bash
perintah &      # latar belakang
Ctrl+Z          # jeda proses depan
bg              # lanjutkan di latar belakang
fg %1           # bawa ke depan
jobs            # lihat daftar job
```

`$!` berisi PID dari perintah latar belakang terakhir, sementara `$$` adalah PID skrip saat ini.

## Wait

```bash
Unduh & Unduh2 &
wait
echo "Semua selesai"
```

`wait` tanpa argumen menunggu semua child process selesai — sangat berguna dalam skrip paralel.

<div class="note">💡 `pkill -f` mencocokkan seluruh baris perintah, bukan hanya nama proses. Periksa hasil `pgrep -f` dulu agar tidak menghentikan proses yang salah.</div>
