## Perbandingan

```bash
#!/usr/bin/env bash
umur=20
nama="Budi"

if [ "$umur" -ge 18 ]; then
  echo "Dewasa"
fi

if [[ "$nama" == Bu* ]]; then
  echo "Nama diawali Bu"
fi

file="data.txt"
[ -f "$file" ] && echo "Berkas ada"
[ -d "/tmp" ] && echo "/tmp adalah folder"
[ -z "$nama" ] || echo "Nama tidak kosong"
```

| Kategori | Operator | Arti |
|---|---|---|
| Angka | `-eq`, `-ne` | sama, tidak sama |
| Angka | `-lt`, `-le` | kurang, kurang atau sama |
| Angka | `-gt`, `-ge` | lebih, lebih atau sama |
| String | `=`, `!=` | sama, tidak sama |
| String | `-z`, `-n` | kosong, tidak kosong |

Kesalahan umum: memakai `>` untuk angka. Operator `>` membandingkan string secara leksikografis.

## Cek Berkas

| Operator | Benar bila |
|---|---|
| `-e` | path ada |
| `-f` | file biasa |
| `-d` | direktori |
| `-r`, `-w`, `-x` | bisa dibaca / ditulis / dijalankan |
| `-s` | file ada dan tidak kosong |

## `[` versus `[[`

```bash
[ "$a" = "x" ]            # POSIX, lebih portabel
[[ "$a" == x* ]]          # Bash, mendukung pola
[[ $a =~ ^[0-9]+$ ]]      # regex, hanya di [[ ]]
```

Di dalam `[[ ]]`, variabel tidak perlu dikutip untuk menghindari word splitting, tapi mengutip tetap aman.

## Kombinasi Catatanika

```bash
if [ -f "$file" ] && [ -r "$file" ]; then
  echo "Bisa dibaca"
fi
```

<div class="note">💡 Selalu kutip variabel di dalam <code>[ ]</code>. bila variabel kosong, <code>[ $x = y ]</code> berubah menjadi <code>[ = y ]</code> dan menyebabkan error.</div>
