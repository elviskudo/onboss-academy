| Konsep | Contoh | Fungsi |
|---|---|---|
| Error enum | `enum FormError: Error` | mendefinisikan kasus gagal |
| `throws` | `func validasi() throws` | menandai fungsi bisa gagal |
| `do-catch` | `catch FormError.kosong` | menangani error spesifik |
| `defer` | `defer { tutup() }` | membersihkan resource |

## Mendefinisikan Error

```swift
enum SaldoError: Error {
    case tidakCukup
    case akunTidakAda
}

func tarik(_ jumlah: Int, dari saldo: Int) throws -> Int {
    guard saldo > 0 else { throw SaldoError.akunTidakAda }
    guard saldo >= jumlah else { throw SaldoError.tidakCukup }
    return saldo - jumlah
}

do {
    let sisa = try tarik(150, dari: 100)
    print(sisa)
} catch SaldoError.tidakCukup {
    print("Saldo tidak cukup")
} catch {
    print("Error lain: \(error)")
}
```

```swift
enum FormError: Error {
    case kosong
    case terlaluPendek(minimum: Int)
}
```

Enum bisa membawa nilai terkait, misalnya jumlah minimum karakter.

## Melempar dan Menangkap

```swift
func validasi(_ s: String) throws {
    guard !s.isEmpty else { throw FormError.kosong }
}

do {
    try validasi(nama)
} catch {
    print(error.localizedDescription)
}
```

`try` wajib ditulis pada pemanggilan fungsi `throws`.

## defer

```swift
func bacaFile() throws {
    let handle = buka()
    defer { tutup(handle) }
    try bacaIsi(handle)
}
```

`defer` dijamin berjalan saat scope selesai, baik sukses maupun gagal.

## Result

```swift
let hasil: Result<Int, Error> = Result {
    try hitungRisiko()
}

switch hasil {
case .success(let nilai): print(nilai)
case .failure(let error): print(error)
}
```

`Result` cocok bila error perlu disimpan atau diteruskan lewat callback asynchronous.

<div class="note">💡 Jangan memakai exception untuk alur bisnis normal. Error handling paling tepat untuk keadaan luar biasa seperti file hilang atau jaringan putus.</div>
