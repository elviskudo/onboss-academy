## 1. Pertanyaan Bisnis

> Pelanggan mana yang kemungkinan besar berhenti langganan bulan depan sehingga bisa diberi penawaran retensi?

Target: `churn` = 1 bila berhenti, 0 bila tetap.

## 2. Data dan Fitur

```python
data = [
    {"lama_bulan": 2, "tagihan": 50000, "churn": 1},
    {"lama_bulan": 18, "tagihan": 75000, "churn": 0},
    {"lama_bulan": 4, "tagihan": 60000, "churn": 1},
    {"lama_bulan": 24, "tagihan": 90000, "churn": 0},
]

fitur = [[d["lama_bulan"], d["tagihan"]] for d in data]
label = [d["churn"] for d in data]
print(fitur, label)
```

## 3. Hindari Kebocoran

Jangan memasukkan `tanggal_pembatalan`, `alasan_keluar`, atau kolom apa pun yang hanya diketahui **setelah** churn terjadi.

## 4. Split dan Model

```python
latih = data[:3]
uji = data[3:]
print("Jumlah latih:", len(latih), "uji:", len(uji))
```

Dengan data sebanyak ini, hasil tidak bisa dijadikan kesimpulan final — di dunia nyata dibutuhkan ribuan baris dan cross-validation.

## 5. Evaluasi

Gunakan confusion matrix, recall, dan AUC. Pertimbangkan biaya: menawarkan diskon ke pelanggan yang sebenarnya tidak churn lebih murah daripada kehilangan pelanggan.

## 6. Deploy dan Pantau

- Simpan versi model dan preprocessor bersamaan.
- Pantau distribusi fitur baru (data drift).
- Latih ulang secara berkala.
- Simpan feedback apakah penawaran berhasil.

<div class="note">💡 Model hanyalah bagian kecil dari sistem. Pengetahuan bisnis, kualitas data, dan desain intervensi sering menentukan keberhasilan jauh lebih besar daripada pilihan algoritma.</div>
