## Contoh Rentan

```sql
-- JANGAN seperti ini
DECLARE @sql NVARCHAR(MAX) =
  N'SELECT * FROM dbo.siswa WHERE nama = ' + @input + N'';
EXEC(@sql);
```

Jika `@input` berisi `Ana' OR 1=1 --`, query berubah menjadi pengambilan seluruh tabel. Varian yang lebih berbahaya bisa menambah `DROP TABLE`.

## Parameterisasi

```sql
EXEC sp_executesql
  N'SELECT nama, nilai FROM dbo.siswa WHERE nama = @nama',
  N'@nama NVARCHAR(100)',
  @nama = @input;
```

Nilai `@input` tidak pernah dianggap sebagai perintah. Ironisnya, query berparameter juga sering lebih cepat karena rencana eksekusinya bisa dipakai ulang.

## Di Stored Procedure

```sql
CREATE PROCEDURE dbo.cari_siswa @nama NVARCHAR(100) AS
BEGIN
  SET NOCOUNT ON;
  SELECT nama, nilai FROM dbo.siswa WHERE nama = @nama;
END;
```

Aman selama prosedur tidak membangun string SQL sendiri. Kalau nama tabel harus dinamis, validasi terhadap daftar putih (whitelist) nilai yang diizinkan.

## Pertahanan Berlapis

| Lapisan | Tindakan |
| --- | --- |
| Aplikasi | prepared statement / parameterized query |
| Database | hak minimal, hindari `db_owner` |
| Input | validasi tipe, panjang, pola |
| Monitoring | audit query anomali |

<div class="note">💡 Mengganti tanda kutip dengan dua tanda kutip ("escaping") bukan strategi yang bisa diandalkan. Parameterisasi menangani semua tipe data dan karakter khusus dengan benar.</div>
