## Jenis JOIN

| Join | Hasil |
| --- | --- |
| `INNER JOIN` | hanya yang cocok |
| `LEFT JOIN` | semua kiri + yang cocok kanan |
| `RIGHT JOIN` | semua kanan + yang cocok kiri |
| `FULL OUTER JOIN` | semua dari kedua sisi |
| `CROSS JOIN` | setiap kiri × setiap kanan |

```sql
SELECT k.nama, d.nama AS divisi
FROM dbo.karyawan AS k
INNER JOIN dbo.divisi AS d ON k.divisi_id = d.id;
```

## ON versus WHERE

```sql
-- aman: filter tambahan di ON tetap mempertahankan baris kiri
SELECT k.nama, p.tanggal
FROM dbo.karyawan k
LEFT JOIN dbo.pesanan p ON k.id = p.id_karyawan AND p.status = N'Lunas';

-- hati-hati: WHERE p.status = 'Lunas' mengubah hasil jadi mirip INNER JOIN
```

Aturan praktis: syarat yang menentukan **bagaimana tabel digabung** ditaruh di `ON`; syarat yang menyaring **hasil akhir** ditaruh di `WHERE`.

## Beberapa JOIN

```sql
SELECT k.nama, d.nama AS divisi, j.nama AS jabatan
FROM dbo.karyawan k
JOIN dbo.divisi d ON k.divisi_id = d.id
JOIN dbo.jabatan j ON k.jabatan_id = j.id;
```

Urutan join dapat memengaruhi rencana eksekusi. SQL Server biasanya menyusun ulang secara otomatis, tetapi statistik yang usang bisa membuat pilihannya buruk.

## Self Join

```sql
SELECT atasan.nama AS atasan, bawahan.nama AS bawahan
FROM dbo.karyawan AS bawahan
JOIN dbo.karyawan AS atasan ON bawahan.atasan_id = atasan.id;
```

Satu tabel dipakai dua kali dengan alias berbeda.

<div class="note">💡 `CROSS JOIN` sangat mudah membuat hasil meledak: 1.000 × 1.000 = 1.000.000 baris. Gunakan hanya untuk tabel kecil seperti tanggal atau daftar kombinasi.</div>
