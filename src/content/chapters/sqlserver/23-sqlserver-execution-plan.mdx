## Membaca Rencana

Rencana eksekusi dibaca **kanan ke kiri, bawah ke atas**. Operator di kanan menghasilkan data, operator di kiri mengonsumsinya.

| Operator | Arti |
| --- | --- |
| Clustered Index Seek | indeks dipakai, langsung ke baris |
| Clustered Index Scan | seluruh indeks dibaca |
| Table Scan | tidak ada indeks yang cocok |
| Key Lookup | mengambil field tambahan dari tabel |
| Hash Match | join/agregasi berbasis hash |

## Estimated versus Actual

- **Estimated**: perkiraan optimizer sebelum query jalan.
- **Actual**: jumlah baris dan waktu nyata setelah query jalan.

Selisih besar antara estimasi dan aktual hampir selalu berarti statistik usang atau predikat yang sulit diperkirakan (misalnya fungsi pada kolom).

## Statistik

```sql
UPDATE STATISTICS dbo.siswa;
EXEC sp_refreshview dbo.vKaryawanAktif;
```

Auto Update Statistics biasanya aktif, tetapi tabel dengan perubahan sangat cepat kadang perlu pembaruan manual.

## Parameter Sniffing

```sql
CREATE PROCEDURE dbo.cari @kota NVARCHAR(50) AS
SELECT * FROM dbo.pelanggan WHERE kota = @kota;
GO
EXEC dbo.cari @kota = N'Jakarta';
```

Saat pertama dijalankan dengan `Jakarta` (jutaan baris), optimizer memilih scan. Eksekusi berikutnya dengan kota kecil tetap memakai plan itu. Solusinya: `OPTION (RECOMPILE)`, `OPTIMIZE FOR UNKNOWN`, atau memisahkan prosedur untuk pola data yang sangat berbeda.

## Hints: Terakhir, Bukan Pertama

```sql
SELECT * FROM dbo.siswa WITH (INDEX(ix_kelas)) WHERE kelas = 'A';
```

Query hint memaksa pilihan optimizer. Pakai hanya setelah analisis matang — sering kali perbaikan yang lebih baik adalah indeks baru atau rewrite query.

<div class="note">💡 Hindari `SELECT *`. Selain memakan bandwidth, ia mencegah covering index karena optimizer harus mengambil hampir semua kolom dari tabel.</div>
