## Clustered versus Nonclustered

| Jenis | Karakter |
| --- | --- |
| Clustered | mengurutkan baris data fisik; satu per tabel |
| Nonclustered | struktur terpisah berisi kunci + penunjuk baris; banyak per tabel |

Biasanya `PRIMARY KEY` otomatis menjadi clustered index. Pilih kunci yang sempit, stabil, dan sering dipakai untuk rentang.

## INCLUDE untuk Covering Index

```sql
CREATE NONCLUSTERED INDEX ix_siswa_kelas_nilai
ON dbo.siswa(kelas, nilai)
INCLUDE (nama);
```

Query `SELECT nama FROM siswa WHERE kelas = 'A' ORDER BY nilai` kini bisa dijawab langsung dari indeks tanpa membaca tabel — disebut **covering index**.

## Filtered Index

```sql
CREATE NONCLUSTERED INDEX ix_pesanan_belum
ON dbo.pesanan(tanggal)
WHERE status = N'Belum Dibayar';
```

Indeks menjadi jauh lebih kecil bila sebagian besar baris sudah lunas. Predikat di query harus cocok dengan predikat indeks agar indeks terpakai.

## Columnstore

```sql
CREATE NONCLUSTERED COLUMNSTORE INDEX cci_penjualan
ON dbo.penjualan(tanggal, produk_id, jumlah, total);
```

Sangat efektif untuk `SUM`, `AVG`, dan scan jutaan baris. Tidak cocok untuk tabel yang terus menerus di-update baris per baris.

## Memantau

```sql
SELECT i.name, s.user_seeks, s.user_scans, s.user_updates
FROM sys.dm_db_index_usage_stats s
JOIN sys.indexes i ON s.object_id = i.object_id AND s.index_id = i.index_id
WHERE s.database_id = DB_ID();
```

Indeks dengan `user_updates` besar tetapi `user_seeks` nol adalah kandidat untuk dihapus. Tetap pertimbangkan siklus aplikasi sebelum memutuskan.

<div class="note">💡 Indeks berlebih memperlambat INSERT/UPDATE/DELETE karena setiap indeks harus ikut diperbarui. Ukuran dan manfaatnya harus dievaluasi secara berkala.</div>
