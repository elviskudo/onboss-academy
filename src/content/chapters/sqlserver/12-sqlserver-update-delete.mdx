## UPDATE

```sql
UPDATE dbo.karyawan
SET gaji = gaji * 1.05, diubah = SYSDATETIME()
WHERE aktif = 1;
```

Tanpa `WHERE`, semua baris berubah. Kebiasaan baik: tulis `SELECT COUNT(*)` dengan filter yang sama terlebih dahulu.

## UPDATE dari Join

```sql
UPDATE k
SET k.gaji = k.gaji * 1.05
FROM dbo.karyawan AS k
JOIN dbo.divisi AS d ON k.divisi_id = d.id
WHERE d.nama = N'Teknik';
```

Alih-alih subquery berulang, join memberi cara yang jelas untuk menentukan baris target.

## DELETE

```sql
DELETE FROM dbo.pesanan
WHERE tanggal < DATEADD(year, -2, SYSDATETIME());
```

`TRUNCATE TABLE` menghapus semua baris lebih cepat, tetapi tidak bisa memakai `WHERE`, tidak mengaktifkan trigger DELETE, dan mengreset IDENTITY.

## OUTPUT untuk Audit

```sql
DELETE FROM dbo.siswa
OUTPUT deleted.id, deleted.nama, deleted.nilai
WHERE id = 5;
```

Baris lama bisa langsung disimpan ke tabel audit dengan `OUTPUT ... INTO dbo.audit_siswa`.

## MERGE

```sql
MERGE dbo.stok AS t
USING @data AS s ON t.kode = s.kode
WHEN MATCHED THEN UPDATE SET t.jumlah = s.jumlah
WHEN NOT MATCHED THEN INSERT (kode, jumlah) VALUES (s.kode, s.jumlah);
```

`MERGE` ringkas untuk sinkronisasi, tetapi harus diuji dengan saksama: konkurensi dan aturan join yang salah bisa mengubah baris yang tidak diinginkan.

<div class="note">💡 Sebelum UPDATE/DELETE massal, jalankan `BEGIN TRAN;`, perintah tersebut, lalu `SELECT` verifikasi. Kalau hasilnya salah, `ROLLBACK TRAN;` langsung memulihkan keadaan.</div>
