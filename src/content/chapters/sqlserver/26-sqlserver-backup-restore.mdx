## Recovery Model

| Model | Log backup | Cocok untuk |
| --- | --- | --- |
| SIMPLE | tidak ada | development, data bisa diulang |
| FULL | ya | produksi yang butuh point-in-time recovery |
| BULK_LOGGED | ya | operasi bulk besar dengan log minimal |

```sql
ALTER DATABASE AcademyDB SET RECOVERY FULL;
```

## Strategi Umum

```sql
-- mingguan
BACKUP DATABASE AcademyDB
TO DISK = 'D:\Backup\AcademyDB_full.bak'
WITH COMPRESSION, INIT;

-- harian
BACKUP DATABASE AcademyDB
TO DISK = 'D:\Backup\AcademyDB_diff.bak'
WITH DIFFERENTIAL, COMPRESSION;

-- tiap 15 menit
BACKUP LOG AcademyDB
TO DISK = 'D:\Backup\AcademyDB_log.trn'
WITH COMPRESSION;
```

`INIT` menimpa file backup lama. Simpan salinan di lokasi berbeda agar kehilangan satu disk tidak menghilangkan semua backup.

## Restore

```sql
RESTORE DATABASE AcademyDB
FROM DISK = 'D:\Backup\AcademyDB_full.bak'
WITH RECOVERY;
```

Untuk point-in-time:

```sql
RESTORE DATABASE AcademyDB
FROM DISK = 'D:\Backup\full.bak' WITH NORECOVERY;
RESTORE DATABASE AcademyDB
FROM DISK = 'D:\Backup\diff.bak' WITH NORECOVERY;
RESTORE LOG AcademyDB
FROM DISK = 'D:\Backup\log.trn'
WITH RECOVERY, STOPAT = '2026-11-20 09:00:00';
```

`NORECOVERY` menjaga database dalam keadaan "restoring" agar backup berikutnya bisa diterapkan.

<div class="note">💡 Backup yang tidak pernah diuji bukan backup. Lakukan restore rutin ke server uji dan verifikasi jumlah baris serta beberapa query kunci.</div>
