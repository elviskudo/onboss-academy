## TRY...CATCH

```sql
BEGIN TRY
  SELECT 1 / 0;
END TRY
BEGIN CATCH
  SELECT ERROR_NUMBER() AS kode, ERROR_MESSAGE() AS pesan;
END CATCH;
```

Kesalahan runtime seperti pembagian dengan nol atau constraint violation ditangkap di `CATCH`. Kesalahan kompilasi (misalnya nama kolom salah) tidak selalu tertangkap di level yang sama.

## Informasi Error

| Fungsi | Isi |
| --- | --- |
| `ERROR_NUMBER()` | kode error |
| `ERROR_MESSAGE()` | teks pesan |
| `ERROR_SEVERITY()` | tingkat keparahan |
| `ERROR_STATE()` | state |
| `ERROR_LINE()` | nomor baris |
| `ERROR_PROCEDURE()` | nama prosedur |

## THROW

```sql
THROW 50000, N'Saldo tidak mencukupi.', 1;
```

Nomor di atas 50000 dipakai untuk error buatan aplikasi. `THROW;` tanpa argumen di dalam `CATCH` melempar kembali error aslinya — cara terbaik untuk tetap menyimpan detail asli sambil menambah logging.

## Transaksi yang Aman

```sql
BEGIN TRY
  BEGIN TRAN;
  -- beberapa perintah UPDATE/INSERT
  COMMIT TRAN;
END TRY
BEGIN CATCH
  IF XACT_STATE() <> 0 ROLLBACK TRAN;
  INSERT INTO dbo.log_error (waktu, pesan)
  VALUES (SYSDATETIME(), ERROR_MESSAGE());
  THROW;
END CATCH;
```

`XACT_STATE()` menghindari `ROLLBACK` ketika tidak ada transaksi aktif, yang sendiri akan memicu error baru.

<div class="note">💡 Jangan menelan error dengan CATCH kosong. Minimal catat ke tabel log lalu lempar kembali — kalau tidak, aplikasi mengira perintah berhasil padahal data tidak berubah.</div>
