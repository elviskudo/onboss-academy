Proyek C nyata terdiri dari banyak file. Memahami pemisahan deklarasi (`*.h`) dan implementasi (`*.c`) adalah kunci konkurensi tim dan build yang rapi.

## Translation Unit

Setiap file `.c` dikompilasi menjadi object file sendiri. Compiler hanya melihat file itu plus header yang di-include. Linker kemudian menggabungkan semua object dan menyambung referensi antarfile.

## Header

```c
#ifndef MATEMATIKA_H
#define MATEMATIKA_H

int tambah(int, int);
extern int counter_global;   /* deklarasi, bukan definisi */

#endif
```

Jangan taruh definisi fungsi di header tanpa `static inline` — akan menyebabkan "multiple definition" saat di-link.

## extern & static

```c
/* di config.c */
int counter_global = 0;       /* definisi */
static int rahasia = 7;       /* hanya terlihat di config.c */

/* di file lain */
extern int counter_global;    /* boleh dipakai */
```

## Contoh Build

```bash
gcc -c mathutil.c -o mathutil.o
gcc -c main.c     -o main.o
gcc main.o mathutil.o -o app
```

Atau sekali jalan: `gcc main.c mathutil.c -o app`.

## Praktik Baik

1. Setiap `.c` punya `.h` dengan nama sama.
2. Header hanya deklarasi + typedef + makro.
3. Pakai header guard di semua header.
4. Simpan state global seminimal mungkin.
5. Prefix nama fungsi publik dengan nama modul (`util_hitung`).

<div class="note">💡 Kalau kamu butuh "private" di C, tandai fungsi dengan `static` di file .c. Ini lebih sederhana dan lebih aman daripada berharap orang tidak memanggil fungsi yang tidak ada di header.</div>
