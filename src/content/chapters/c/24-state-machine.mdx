State machine (atau finite-state machine/FSM) memodelkan sistem yang berada dalam salah satu dari sekumpulan keadaan yang terbatas. Perubahan keadaan terjadi karena event.

## Komponen

- **State**: kondisi sistem saat ini (`IDLE`, `JALAN`).
- **Event**: pemicu perubahan (`START`, `STOP`).
- **Transition**: aturan state + event → state baru.
- **Action**: efek yang dilakukan saat masuk/keluar state.

## Implementasi Enum + Switch

```c
typedef enum { IDLE, CONNECTING, CONNECTED, ERROR } State;

State next(State s, Event e) {
    switch (s) {
        case IDLE:       return e == EV_CONNECT ? CONNECTING : IDLE;
        case CONNECTING: return e == EV_OK ? CONNECTED : ERROR;
        case CONNECTED:  return e == EV_CLOSE ? IDLE : CONNECTED;
        case ERROR:      return e == EV_RESET ? IDLE : ERROR;
    }
    return ERROR;
}
```

## Tabel Transisi

Untuk state machine besar, tabel 2D lebih rapi daripada switch panjang:

```c
static State tabel[4][4] = {
    /*          START  STOP  OK  RESET */
    /* IDLE */ {JALAN, IDLE, IDLE, IDLE},
    /* JALAN*/ {JALAN, SELESAI, JALAN, IDLE},
    /* ...  */
};
s = tabel[s][event];
```

## State Machine vs Flag Boolean

Banyak `bool sedangJalan, sedangJeda, sudahSelesai` yang saling bertentangan sebaiknya diganti satu enum. Ini menghilangkan kombinasi mustahil seperti "jalan dan jeda bersamaan".
