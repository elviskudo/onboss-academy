C memberi kontrol penuh atas memori — dan juga tanggung jawab penuh. Memahami cara kode bisa salah adalah bagian dari keahlian C.

## Undefined Behavior (UB)

Contoh UB:

```c
int i = 5;
i = i++ + ++i;      /* urutan evaluasi tidak ditentukan */
int a[3]; a[5] = 1; /* out of bounds */
int *p = NULL; *p = 1;
int x; printf("%d", x);  /* belum diinisialisasi */
```

Compiler boleh mengoptimalkan dengan asumsi UB tidak terjadi — akibatnya bug bisa hilang di debug dan muncul di release.

## Buffer Overflow

```c
char nama[16];
strcpy(nama, input_panjang);   /* BAHAYA */
gets(nama);                    /* JANGAN PERNAH */
```

Ganti dengan:

```c
fgets(nama, sizeof nama, stdin);
snprintf(nama, sizeof nama, "%s", input);
```

## Overflow Integer

```c
unsigned char x = 255;
x++;   /* 0 (wrap-around, terdefinisi) */

int y = 2147483647;
y++;   /* UB pada signed int */
```

Cek batas sebelum operasi bila nilai berasal dari input eksternal.

## Defensive Coding

1. Selalu cek pointer sebelum dereference.
2. Selalu cek hasil `malloc`.
3. Gunakan ukuran `sizeof *ptr`.
4. Inisialisasi variabel lokal.
5. Batasi semua operasi string.
6. Aktifkan warning: `gcc -Wall -Wextra -Werror`.

## Sanitizer

```bash
gcc -fsanitize=address,undefined -g program.c -o program
```

Jalankan test suite dengan sanitizer secara rutin — ini menangkap bug yang mustahil dilihat hanya dengan membaca kode.

<div class="note">💡 Anggap semua input dari luar (user, file, jaringan) sebagai berbahaya. Validasi panjang, rentang, dan format sebelum memprosesnya.</div>
