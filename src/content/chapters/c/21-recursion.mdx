Rekursi terjadi saat sebuah fungsi memanggil dirinya sendiri. Ia adalah alternatif loop untuk masalah yang bisa dipecah jadi submasalah yang lebih kecil.

## Dua Bagian Wajib

```c
int jumlah(int n) {
    if (n == 0) return 0;        /* base case */
    return n + jumlah(n - 1);    /* recursive case */
}
```

Setiap pemanggilan menyimpan variabel lokal di **call stack**. Setelah base case tercapai, frame-frame di-"unwrap" satu per satu.

## Contoh: Binary Search Rekursif

```c
int cari(int a[], int l, int r, int x) {
    if (l > r) return -1;
    int mid = l + (r - l) / 2;
    if (a[mid] == x) return mid;
    if (a[mid] > x) return cari(a, l, mid - 1, x);
    return cari(a, mid + 1, r, x);
}
```

## Rekursi vs Iterasi

| Aspek | Rekursi | Iterasi |
|---|---|---|
| Kode | ringkas untuk tree/graph | eksplisit |
| Memori | O(n) stack | O(1) |
| Risiko | stack overflow | tidak |
| Performa | ada overhead panggilan | biasanya lebih cepat |

## Rekursi Ekor (Tail Recursion)

```c
int jumlah_ekor(int n, int akum) {
    if (n == 0) return akum;
    return jumlah_ekor(n - 1, akum + n);
}
```

Kalau compiler melakukan tail-call optimization, frame lama bisa dipakai ulang. Tidak semua compiler menjamin ini.

<div class="note">💡 Selalu tanya: "Apakah base case pasti tercapai?" Rekursi tanpa jaminan itu resep stack overflow. Untuk input besar, iterasi hampir selalu lebih aman.</div>
