Menguasai algoritma adalah satu hal; **menjelaskannya** adalah hal lain. Wawancara dirancang untuk melihat keduanya.

## Enam Langkah

```text
1. Klarifikasi   - input, output, batasan
2. Contoh        - satu kasus sederhana
3. Ide solusi    - jelaskan sebelum mengetik
4. Implementasi  - kode bersih dan naming jelas
5. Pengujian     - kasus normal dan edge case
6. Kompleksitas  - waktu dan ruang
```

## Contoh Response

```text
"Inputnya array integer terurut, outputnya indeks atau -1.
Saya akan pakai binary search karena datanya terurut.
Tiap iterasi saya buang setengah ruang pencarian.

Kalau array kosong, langsung return -1.
Waktunya O(log n), ruangnya O(1)."
```

Jauh lebih baik daripada langsung menulis `for` tanpa konteks.

## Kategori Soal yang Sering Muncul

| Pola | Contoh |
|---|---|
| Array/string | two pointers, sliding window |
| Hash map | frekuensi, dua jumlah |
| Tree | traversal, height, BST |
| Graf | BFS/DFS, shortest path |
| DP | knapsack, subsequence |
| Heap | top-K, median streaming |
| Sorting | custom comparator |

## Kesalahan Umum

- Tidak bertanya apakah input bisa kosong atau duplikat.
- Terlalu cepat mengoptimasi sebelum solusi benar.
- Lupa menyebut kompleksitas.
- Diam terlalu lama tanpa memberi progres.

<div class="note">💡 Interviewer ingin melihat Anda sebagai rekan kerja yang bisa diajak berpikir. Solusi yang salah arah tapi dijelaskan dengan jelas sering lebih bernilai daripada kode benar yang tidak bisa dijelaskan.</div>

## Latihan Efektif

Kerjakan satu soal dengan dua pendekatan, lalu bandingkan. Tulis penjelasan 3 paragraf: masalah, ide, kompleksitas. Kebiasaan itu membangun kejelasan yang sama persis dengan yang dicari di wawancara.
