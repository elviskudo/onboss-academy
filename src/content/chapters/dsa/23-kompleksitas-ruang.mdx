Diskusi efisiensi sering berhenti di waktu. Padahal **memori** juga sumber daya yang bisa menjadi bottleneck.

## Apa yang Dihitung?

- Variabel lokal dan frame call stack.
- Struktur data bantuan (array, hash, heap).
- Salinan input yang dibuat algoritma.

```python
def total(a):
    return sum(a)                 # O(1) ekstra

def duplikat(a):
    return [x for x in a]         # O(n) ekstra
```

## Contoh Perbandingan

| Algoritma | Waktu | Ruang ekstra |
|---|---|---|
| Bubble sort | O(n²) | O(1) |
| Merge sort | O(n log n) | O(n) |
| Quick sort (rata-rata) | O(n log n) | O(log n) |
| Heap sort | O(n log n) | O(1) |
| DP knapsack | O(n·k) | O(n·k) atau O(k) |

## Mengurangi Ruang

```python
# DP 2D -> 1D dengan menyimpan hanya baris sebelumnya
def fib_tabel(n):
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b
    return a
```

Banyak tabel DP bisa direduksi bila transisi hanya melihat baris atau kolom sebelumnya.

## Trade-off Nyata

- **Memoization** mempercepat tapi menambah memori.
- **Compression** menghemat penyimpanan tapi menambah waktu CPU.
- **Streaming** memproses data sedikit demi sedikit agar tidak memuat seluruh file.

<div class="note">💡 Di perangkat dengan RAM terbatas (embedded, mobile lawas), algoritma O(1) ruang bisa lebih berguna daripada algoritma paling cepat di kertas.</div>
