Hash table adalah struktur data dengan **lookup rata-rata tercepat**: O(1). Di Python ia hadir sebagai `dict` — tipe yang paling sering kamu pakai tanpa sadar.

## Operasi Dasar dict

```python
harga = {"apel": 5000, "mangga": 8000, "jeruk": 6000}

print(harga["mangga"])        # ambil         O(1)
harga["pepaya"] = 4000        # sisip/update  O(1)
del harga["apel"]             # hapus         O(1)
print("jeruk" in harga)       # cek keberadaan O(1)
print(harga.get("durian", 0)) # ambil aman, default 0
```

## Bagaimana Di Balik Layar

```
kunci --hash()--> indeks bucket --> entri (kunci, nilai)
```

1. `hash(kunci)` menghasilkan bilangan integer.
2. Modulo ukuran tabel menentukan **bucket** (slot) tujuan.
3. Kunci dan nilai disimpan sebagai pasangan di bucket itu.

```python
for kata in ["apel", "mangga", "jeruk"]:
    print(kata, "->", hash(kata) % 8, "(bucket)")
```

Setiap pemanggilan `hash` untuk kunci yang sama selalu menghasilkan angka yang sama — itulah syarat utama fungsi hash.

## Menghitung Frekuensi

Kasus klasik hash table: menghitung kemunculan tanpa nested loop.

```python
teks = "onboss academy onboss git onboss"
frek = {}
for kata in teks.split():
    frek[kata] = frek.get(kata, 0) + 1

print(frek)   # {'onboss': 3, 'academy': 1, 'git': 1}
```

Tanpa dict, cara ini butuh O(n^2). Dengan dict: O(n).

## Set: Hash Table Tanpa Nilai

```python
unik = {"python", "go", "rust", "python"}
print(len(unik))          # 3 — duplikat hilang
print("go" in unik)       # O(1)
```

## Kunci Harus Hashable

```python
d = {}
d[(1, 2)] = "tuple boleh"      # tuple immutable -> boleh
# d[[1, 2]] = "list tidak"     # list mutable -> TypeError
```

| Kunci | Boleh? |
|-------|--------|
| str, int, float, bool | ya |
| tuple (berisi hashable) | ya |
| frozenset | ya |
| list, dict, set | tidak |

## Collision dan Kapasitas

Ada **2 strategi collision umum**: separate chaining menyimpan beberapa entri per bucket, sedangkan open addressing mencari slot lain dalam tabel. CPython `dict` memakai open addressing, bukan chaining. Ketika tabel terlalu padat, dict memperbesar kapasitas dan menyusun ulang slot; biaya resize O(n), tetapi operasi sepanjang waktu tetap O(1) amortized.

| Operasi dict/set | Rata-rata | Terburuk | Kapan dipakai |
|---|---:|---:|---|
| get / membership | O(1) | O(n) | lookup key |
| insert / update | O(1) amortized | O(n) | indeks dan cache |
| delete | O(1) amortized | O(n) | mencabut entri |
| iterasi | O(n) | O(n) | memproses semua entri |

Kesamaan key mengikuti kontrak `a == b` dan hash yang sama untuk objek setara. Karena hash string diacak antarproses, jangan menyimpan nilai `hash()` sebagai ID permanen. `dict` mempertahankan insertion order, tetapi urutan itu bukan urutan berdasarkan key.
