Beberapa operasi sesekali mahal, tetapi **rata-rata** tetap murah. Analisis amortized memberi caraformal untuk mengatakan itu.

## Intuisi Dynamic Array

```python
kapasitas = 1
data = []
for i in range(8):
    if len(data) == kapasitas:
        kapasitas *= 2
        print("resize ke", kapasitas)
    data.append(i)
```

Resize menyalin n elemen, tetapi terjadi setelah makin banyak append. Total salinan: 1 + 2 + 4 + ... + n/2 &lt; n.

```text
total biaya n append < 2n  ->  amortized O(1)
```

## Dua Metode

| Metode | Ide |
|---|---|
| Aggregasi | hitung total T(n), bagi n |
| Potensial | simpan “kredit” pada struktur |

```text
biaya amortized = biaya aktual + ΔΦ
```

Saat kapasitas bertambah, Φ naik. Saat resize, Φ turun untuk membayar biaya salin.

## Contoh Lain

- **Stack dengan pop multipel** — bisa mahal sekali, murah secara amortized.
- **Disjoint Set Union** — path compression mencapai hampir O(1).
- **Hash table resize** — rehash jarang terjadi.

<div class="note">💡 Amortized berbeda dengan average case. Average case bergantung pada distribusi input; amortized menjamin rata-rata atas **urutan operasi apa pun**.</div>

## Kapan Penting

Saat merancang struktur data kustom, catat operasi yang mahal lalu tanyakan: seberapa sering ia terjadi, dan apakah biayanya bisa dibayar oleh operasi sebelumnya?
