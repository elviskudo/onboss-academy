## Kapan Dibutuhkan

Satu operasi pada **satu dokumen** sudah atomik. Transaksi diperlukan kalau satu proses bisnis menyentuh **beberapa dokumen** dan semua harus berhasil atau semua gagal.

Contoh klasik: memindahkan saldo dari rekening A ke B. Tanpa transaksi, aplikasi bisa saja sudah mengurangi A tetapi gagal menambah B.

## Session

```javascript
const session = client.startSession();

try {
  session.startTransaction();
  await db.collection("akun").updateOne(
    { _id: 1 }, { $inc: { saldo: -100 } }, { session }
  );
  await db.collection("akun").updateOne(
    { _id: 2 }, { $inc: { saldo: 100 } }, { session }
  );
  await session.commitTransaction();
} catch (err) {
  await session.abortTransaction();
  throw err;
} finally {
  session.endSession();
}
```

Opsi `{ session }` wajib disertakan pada setiap operasi agar menjadi bagian dari transaksi.

## Batasan

| Aspek | Keterangan |
| --- | --- |
| Durasi | sebaiknya singkat; transaksi lama menahan resource |
| Ukuran | ada batas total data yang ditulis |
| Lingkungan | replica set / sharded cluster |
| DDL | tidak semua perubahan struktur bisa masuk transaksi |

## Alternatif: Desain Atomik

Sering kali transaksi bisa dihindari dengan **embed**: simpan saldo dan riwayat dalam satu dokumen, lalu gunakan update atomik `$inc` dengan syarat filter. Satu dokumen = satu operasi atomik, lebih cepat dan lebih sederhana.

<div class="note">💡 Transaksi menambah overhead. Pakai hanya untuk operasi yang benar-benar harus konsisten lintas dokumen, bukan sebagai kebiasaan default.</div>
