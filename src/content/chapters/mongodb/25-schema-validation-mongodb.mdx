## Kenapa Perlu Aturan

Fleksibilitas MongoDB adalah kekuatan sekaligus risiko. Tanpa aturan, koleksi `produk` bisa berisi dokumen tanpa nama, harga berupa string, atau field yang salah eja. Schema validation menolak dokumen yang tidak mematuhi aturan.

## $jsonSchema

```javascript
db.createCollection("produk_valid", {
  validator: {
    $jsonSchema: {
      bsonType: "object",
      required: ["nama", "harga"],
      properties: {
        nama: { bsonType: "string", description: "wajib teks" },
        harga: { bsonType: "int", minimum: 0 },
        kategori: { enum: ["Elektronik", "Furniture", "Makanan"] }
      }
    }
  },
  validationAction: "error",
  validationLevel: "strict"
})
```

Deklarasi di atas mewajibkan `nama` dan `harga`, melarang harga negatif, serta membatasi nilai kategori.

## Level dan Action

| Opsi | Nilai | Efek |
| --- | --- | --- |
| `validationLevel` | `strict` | semua insert/update dicek |
| | `moderate` | dokumen lama yang invalid tidak dicek saat diubah |
| `validationAction` | `error` | tolak tulisan |
| | `warn` | terima tapi tulis peringatan di log |

## Menambah ke Koleksi Lama

```javascript
db.runCommand({
  collMod: "produk",
  validator: { $jsonSchema: { required: ["nama"] } },
  validationLevel: "moderate"
})
```

Mulai dengan `warn` dan `moderate` saat data lama masih kotor. Setelah dibersihkan, baru naikkan ke `error` dan `strict`.

<div class="note">💡 Schema validation bukan pengganti validasi aplikasi. Tetap validasi input di lapisan API agar pesan error ramah pengguna dan tidak bergantung pada detail database.</div>
