Go Modules adalah sistem manajemen dependensi resmi sejak Go 1.11. Modul adalah kumpulan package yang versinya tercatat bersama.

## Membuat Modul

```bash
mkdir belajar-go && cd belajar-go
go mod init example.com/belajar-go
```

Hasil `go.mod`:

```go
module example.com/belajar-go

go 1.22
```

Path modul sebaiknya unik (biasanya memakai domain), meski tidak harus benar-benar online.

## Menambah Dependensi

```bash
go get github.com/username/paket@v1.2.3
```

Atau cukup import di kode lalu jalankan `go mod tidy`.

## Isi go.mod

| Bagian | Fungsi |
|---|---|
| `module` | Nama modul |
| `go` | Versi bahasa minimum |
| `require` | Dependensi langsung |
| `replace` | Alihkan path/versi (lokal atau fork) |
| `exclude` | Tolak versi tertentu |

```go
require (
    golang.org/x/text v0.14.0
    github.com/stretchr/testify v1.8.4 // indirect
)
```

## go.sum

Setiap modul yang diunduh dicatat dengan hash SHA-256. Jangan diedit manual. Jika hash berubah, `go` akan menolak — ini melindungi dari dependensi yang dimodifikasi.

## Perintah Sehari-hari

| Perintah | Fungsi |
|---|---|
| `go mod tidy` | Selaraskan dependency dengan kode |
| `go mod download` | Unduh ke cache |
| `go mod verify` | Cek integritas |
| `go list -m all` | Tampilkan semua modul |
| `go get -u` | Perbarui versi |

## Vendor (Opsional)

```bash
go mod vendor
```

Menyalin dependensi ke folder `vendor/` agar build bisa offline.

<div class="note">💡 Commit Both <code>go.mod</code> dan <code>go.sum</code> ke repository. Tanpa keduanya, rekan tim bisa mendapat versi berbeda.</div>
