Saat dua aturan CSS menargetkan elemen yang sama dengan properti yang sama, browser perlu aturan wasit. Wasitnya bernama **cascade**, dan kekuatan masing-masing aturan disebut **spesifisitas**.

## Komponen Spesifisitas

Spesifisitas ditulis sebagai tiga angka `(id, class, tag)`:

| Selector | Hitungan | Nilai |
|----------|----------|-------|
| `p` | 0 id, 0 class, 1 tag | `0-0-1` |
| `.judul` | 0, 1, 0 | `0-1-0` |
| `#main` | 1, 0, 0 | `1-0-0` |
| `.card p` | 0, 1, 1 | `0-1-1` |
| `#main .card:hover` | 1, 2, 0 | `1-2-0` |

Pseudo-class seperti `:hover` dihitung seperti class. Pseudo-element seperti `::before` dihitung seperti tag. Combinator (spasi, `>`, `+`) **tidak menambah nilai**.

## Urutan Cascade Lengkap

Dari yang paling kuat ke paling lemah:

1. Deklarasi `!important` (dari stylesheet pengguna/browser juga ikut berpengaruh)
2. Inline style (`style="…"`)
3. Selector dengan id
4. Selector class, atribut, pseudo-class
5. Selector tag dan pseudo-element
6. Aturan yang ditulis terakhir saat spesifisitas sama

## Contoh Konflik

```css
p          { color: black; }   /* 0-0-1 */
.intro     { color: blue;  }   /* 0-1-0 → menang */
#utama p   { color: green; }   /* 1-0-1 → menang lagi */
#utama .intro { color: red; }  /* 1-1-0 → paling kuat */
```

Karena `.intro` lebih spesifik dari `p`, warna biru menang walau aturan `p` ditulis belakangan.

<div class="note">💡 Hindari `!important` kecuali benar-benar terpaksa (misalnya menimpa style library pihak ketiga). Lebih baik naikkan spesifisitas dengan class yang tepat atau susun ulang urutan stylesheet.</div>

## Strategi Sehat

- Pakai class sebagai "satuan gaya" utama, bukan id.
- Jaga spesifisitas serendah mungkin agar mudah ditimpa.
- Susun CSS dari umum (reset, tipografi) ke khusus (komponen, state).
- Kalau kamu perlu menimpa, tambahkan class state seperti `.is-active`, bukan `!important`.

## Di Dunia Nyata

- Tombol `.btn` berubah tampilan saat `.btn.is-loading` ditambahkan.
- Tema gelap menimpa warna terang karena aturannya dimuat setelahnya.
- Library UI sering memakai `!important` pada utilitas seperti `.hidden` — tahu cara mengatasinya menyelamatkan debugging.
